## 教训

- **`UID` 是 bash 只读变量**：脚本里 `UID=xxx` 赋值**静默失败**（`readonly variable`），
  值沿用系统 uid（本机 197108）⇒ HTTP 路径第一次跑出的 uid 不是预期的 `RECFIX01`。改 `RUID` 后正常。
- **用户给的路径要先 dry-run 证伪**：`git push --dry-run <path>` 是零副作用的事实核验手段，
  比猜意图可靠（本次一跑就看出是源仓自身）。
- **改 env 相关代码后要连带查测试脚本**：产品改用 env 覆盖后，测试里任何硬编码同名路径都会
  从「能跑」变成「静默失效」（`force:true` 掩盖了删不到文件）。

**审批面板在真机上永远是空的**。
`viewerbackend.cpp` 自己那 5 处 `/api/*`（fetchEvents/requestClasses/fetchRecordings/…）**都**做了派生，
唯独新写的 InteractBridge 漏了。⇒ 上一轮「HTTP 端到端全绿」是假象：我用 curl 直连 http，
**绕过了这段派生** —— 这正是"不跑真桥就看不到"的一类问题。

**修法**：收成单一真源 `ViewerBackend::httpBaseUrl()`（非虚、不改类布局 ⇒ **只重编 2 个 obj**），
`InteractBridge` 两处改用它。commit `078277b` + push ✅（顺带补齐并行会话那笔已提交未推的 `52505ef`）。
