### 新知识（会再踩的）

1. **QML 内联组件必须加 `pragma ComponentBehavior: Bound`**。`component X: ...` 在 Qt 6.5+
   默认 Unbound → **不捕获本文件上下文**，组件里引用外层 id（如 `dlg.theme`）解析不到。
   qmllint 原话："Set pragma ComponentBehavior: Bound in order to use IDs from outer components
   in nested components"。加之前 12 条提示，加之后 0 条。
2. **勾选行不能用 `Row` 包 `MouseArea`+`anchors.fill`** —— Row 把每个子项横向排队，
   MouseArea 会变成第三个格子而不是铺满整行。要 `Item` 里放 `Row` + 铺满的 MouseArea。
3. 勾选框属性名用 `checked` 不用 `on`（`on: ...` 易被当成信号处理器语法）。
4. **`runAction()` 是按文案分支的 if-else 链**：`d.a` 为 `""` 的项（音量/探活/软件/定时/文件/通知）
   **必须各自有分支**，否则掉到最后的 `else if (d.a !== "")` 什么都不做，点上去毫无反应且不报错。

## 6. 性能 / 内存 / 占用优化（用户点名，2026-10-06 下午）

先量后改。量出来的结论：**唯一无上界增长的磁盘项是无轮转的 events.log；唯一无上界
增长的内存项是 results 回执表；viewer-qt 侧是建收流页时 new 出来不回收的 timer。**

### 6.1 events.log 体积轮转（cloud-ws，提交 31539e3）

- 现状：events.log 14MB、只 append 从不轮转、~1.9MB/天（教室机一学期几百兆，
  盘吃满后云端连写文件都失败）。
- 改法：config.js 加 `CLOUD_EVENTS_MAX_BYTES`(10MB)/`CLOUD_EVENTS_KEEP_FILES`(3)；
  registry.js 到顶 rename 归档 + 重建空文件，归档保留最近 N 个、更老删掉。
- **两个真踩过的坑（写进代码注释了）**：
  1. 轮转判断**不能用 `statSync` 现读大小** —— appendFile 异步，同步循环里读到的
     永远是旧值（钉 4096B 上限推 301 条实测一次没转、文件长到 38KB）。必须自己
     累加 eventsBytes。
  2. 并行 append 在轮转 rename 那一瞬把在飞写落进**归档**，主日志只剩 31 行（近事
     全跑到归档里、看着像断流）。→ 落盘改成 eventsChain Promise 串行链，
     轮转永远发生在两次写之间，顺带压掉广播风暴的并发 append。
- 归档名用 ISO 时间戳（字典序 == 时间序，截断即可淘汰最老）且**全 ASCII** ——
  这台机器上非 ASCII 文件名曾把云端整个打挂过（ERR_INVALID_CHAR），别重蹈。
- 验证：探针（限 4096B/留 2 份推 301 条）8 项全过；真云端启动冒烟 /api/devices 401。
