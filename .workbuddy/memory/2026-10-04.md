### 我写错的 API（自查抓出并已改，记账免得重犯）
- `QWebEngineView` **不是 QObject**是 QWidget → 没有 `(QObject*)` 构造，且不能 `setParent(backend)`（QObject 不是 QWidget）。解法：不设 parent，生命周期靠析构 `deleteLater()`。
- `QWebChannel(QWebChannelPrivate&,QObject*)` 是私有的 → 正确是 `new QWebChannel(this)`，transport 由 `page->setWebChannel()` 接管。
- `QString::toJsonEscapedString()` **不存在**；`QJsonDocument(QJsonValue)` **也没有** → 改用「塞进 QJsonObject 再 toJson，取最后一个冒号后的字面量」。
- `page->loadFinished.connect(...)` 在 Qt6 不可用（signal 关键字已移除）→ 用 `QObject::connect`。
- QWebChannel 的 JS 名 **必须和 Q_INVOKABLE 方法名逐字一致**（按名字映射，对不上是静默失效）—— 已把 HTML 里的 `window.__qt.answer/ice/frame/track` 全改成 `rtcGotAnswer/rtcGotIce/setRtcFrame/rtcGotTrack`。
- 页面必须用 **file:// origin** 加载（临时目录 `stelarith-viewer-rtc.html`）：`data:` URL 的 origin 是 null，页面里的 `<script src="qrc:///qtwebchannel/qwebchannel.js">` 会被同源策略拦掉，QWebChannel 建不起来。

## J 段（23:46–00:15）功能跟进 + UI 优化：画面源收敛、链路徽标、空态分级

### 一、功能：两路帧互相覆盖（真 bug，用户可见）
