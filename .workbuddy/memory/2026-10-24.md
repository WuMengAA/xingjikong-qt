## VNC 重构 · 轴 A（地基）：换带 zlib 的 libvnc，编码默认 ZRLE（viewer `41d4bd0`）

- **三轴判断**（用户点「所以需要重构」后定）：A=编码层（真地基，必做）；B=传输层（vnc-data 挤主 WS，消队头阻塞）；C=触控层（RFB 只有单指针，多点无解只能近似）。**顺序 A 先**——A 不动就做 B/C = 屎上叠叠乐。
- **换库**：自编 libvncserver(master `98aaee0` 2026-10-07) + zlib 1.3.1(/MD)，用 `lib.exe /OUT:` 把 zlibstatic **静态合并**进两端 .lib → 使用方零改动（不用改 CMakeLists 加 zlib）。装进 `third_party/{libvncserver,libvncclient}`（**该目录 untracked**，换库零版本库污染；原件备份在 `%TEMP%\stelarith-libvnc-build\backup-orig`）。
- **不选 Tight**：libvnc CMake 里 `if(JPEG_FOUND)` 才编 `tight.c` ⇒ Tight 强依赖 libjpeg；且其 JPEG 层有损压花文字。**ZRLE 只需 zlib 且无损**，桌面 UI/PPT 场景更优。
- **改动面**：viewer 仅 `src/vnc_client.cpp`（+9−5，注释 + `encodingsString` 改 `"zrle copyrect hextile raw"`）；control-qt **代码零改动**（只换 untracked 库）。两端均重编通过并链接。
- **验证（探针 `probe/{probe_server,probe_client}.c`，720p 模拟 UI + 每 200ms 动 60×60，各 5s）**：
  | 编码 | bytesSent | bytesIfRaw | 压缩比 |
  |---|---|---|---|
  | ZRLE | 1,670 | 4,017,846 | 2405× |
  | HEXTILE(旧默认) | 5,862 | 4,018,134 | 685× |
  | RAW | 4,018,134 | 4,018,134 | 1× |
  `preferredEncoding` 精确命中：zrle→**16** / hextile→**5** / raw→**0** ⇒ 协商真生效。**ZRLE 比旧 hextile 再省 3.5×**。
- **⚠️ 坑（血泪，必记）**：
  1. **旧库不是 release tag**：`rfbconfig.h` 写 0.9.15，但含 `rfbSecurityTag`/`rebindListenSockets`/`rfbClientConnect`/`x509ExpectedFingerprint` 等 **master 才有的符号** ⇒ 0.9.14 和 0.9.15 tag 都 ABI 不兼容（结构体字段缺失，混用必崩）。**正解：clone master 编库 + 换 master 头，整体自洽**。判据：拿旧库已有符号去 grep 目标版本头，全命中才可用。
  2. 新 `rfbproto.h` 在 LIBZ 分支 `#include <zlib.h>` ⇒ **zlib.h/zconf.h 必须一并放进 third_party/include**，否则 fatal C1083。
  3. **CRT 必须对齐**：libvnc 是 `/MD`（CMake `CMAKE_C_FLAGS_RELEASE=/MD`）。探针用 `/MT` 会报一堆 `__imp_fopen` 未解析；`/MT` 下 LNK4286 提示 libucrt 冲突。正解 `/MD` + 显式链 `ucrt.lib vcruntime.lib`。
  4. **带宽统计不在 `client->bytesSent`**：那字段常年 0。真值在 **`client->statEncList` 链表**（按 encoding 分类，`type/sentCount/bytesSent/bytesSentIfRaw`），要遍历累加。`rfbClientRec::rawBytesEquivalent` 是另一回事。
  5. **`rfbInitClient` 的 host 格式是单冒号 `host:port`**（`parse_host_and_port`），写 `host::port` 会被当 IPv6 → “Couldn't convert to host address”；且端口 **<5900 会自动 +5900**。
  6. client 侧编解码器不是独立 obj：`rfbclient.c` 用 `#include "zrle.c"` 单编译单元内联 ⇒ `vncclient.dir` 里看不到 zrle.c.obj 是正常的，别误判“没编进去”。
- **未做**：① 未换生产包（仅工作区构建）；② 未在真实 agent↔cloud↔viewer 全链路实测（只用回环探针）；③ 轴 B（拆独立通道）/ 轴 C（手势近似多点）未动。**判断：A 之后 B 的紧迫性大降**（带宽已降 3.5×），C 仍无解只能近似。

### ⚠️ 事故/教训：commit 把 index 里别人的 staged 改动一起带走了

- 我给 viewer 只 `git add CMakeLists.txt src/main.cpp`，但 commit 出来 **20 files / −772 行** —— 因为 index 里**早有**"旧界面迁移"第四刀的部分改动（第三刀 `ded1f1c` 已提交，之后的改动留在 staged）。

- **根因**：`git commit` 提交的是**整个 index**，不是"我刚 add 的文件"。`git add A B` 只把 A B 加进 index，**不会清掉 index 里已有的东西**。
