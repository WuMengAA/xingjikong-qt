## 00:0x-00:4x 用户 #111：Android 语音「取值失败」——按 Qt/Android 权限资料逐条核，修两处真 bug（viewer-qt）

**背景**：用户贴 Qt for Android 权限资料（① Manifest 声明 → ② 运行时动态请求 → ③ 永久拒绝引导 → ④ 音频格式兼容）＋编号「#111」，指向**手机端（管理端）**的权限/取值问题。上一轮我查的是桌面端日志（正常），方向偏了。

**逐条核对结论**：
- ① 声明 ✓ `android/AndroidManifest.xml` 已有 RECORD_AUDIO / CAMERA / POST_NOTIFICATIONS。
- ② 运行时请求 ✓ 但**做法错**（见修 1）。
- ③ 永久拒绝引导 ✓ `openAudioSettings()` + QML 红条（`5bcb57d`）。
- ④ **格式兼容 ✗ 完全没做** ⇒ 两处真 bug（见修 2）。
- 手机端**有意不做语音**：`qml/mobile/OverviewPage.qml:78` 明写「远控 / 语音 / 广播 / 课表请用桌面管理端」；但 `audio_capture_android.cpp` 却实现了完整 AAudio 采集 ⇒ **已就绪未接线**。
- 手机端**无摄像头功能**（CAMERA 仅声明、无运行时请求也无采集代码）。

**修 1 —— 权限模型（`src/viewerbackend.cpp`）**
- 旧写法 `QtAndroidPrivate::requestPermission` **每次都硬请求**；而 Android 在用户拒过一次后**不再弹框** ⇒ 变成「请求 → 立刻 Denied → 报失败」死循环，永远停在"没权限"。（＝dsh 10-11 记的"Android 13+ 弹框只出现一次"，那是**症状**不是根因。）
- 改为 Qt 官方 `QPermission` 三态：`qApp->checkPermission(QMicrophonePermission())` → **Granted** 直接开麦 / **Denied** 不浪费请求、直接引导去系统设置 / **Undetermined** 才弹系统框（唯一该弹的一次），回调 `qApp->requestPermission(mic, this, lambda)`。
- `audioPermGranted()`：手写 JNI `checkSelfPermission` → `qApp->checkPermission(...) == Granted`。
- `requestAudioPerm()`：委托 `startSpeaking()`（QML 未调用它，保留 Q_INVOKABLE 仅不破接口）。
- **未动**：`openAudioSettings()`（跳应用详情页）、`QtAndroidPrivate::startActivity`（两处文件选择器）。
- 新增 `#include <QPermissions>`（在 `Q_OS_ANDROID` 分支内）——**QtCore 自带、无需 Multimedia**；原注释「QMicrophonePermission 是 minimal 无 status」是误解。

**修 2 —— 音频格式归一化（`src/audio_capture_android.cpp`）**
- AAudio 的 `setSampleRate` / `setFormat` / `setChannelCount` **都只是"建议"**，设备可不照办且不报错。旧码无条件按"16kHz/单声道/I16"解释回调数据、按固定 640B 切帧 ⇒ ① 设备回 **FLOAT** 时 float 字节被当 int16 发 → 对端听到**噪声**；② 设备回 **48kHz** 时每帧实际只有 6.7ms，对端按 20ms 播 → **快放/变调**。
- 现在回调内归一化：任意格式/声道 → 单声道 float → **线性重采样到 16kHz** → I16；16k 直通走快路径。对外契约（640B/20ms）不变 ⇒ **对端零改动**。open 后回读设备实际 rate/ch/fmt 并打日志（真机排查一眼可见）。

**验证（实证）**
- **Android（arm64-v8a · NDK 27 · Qt 6.12 android kit）**：`ninja -C build-android` 编 `audio_capture_android.cpp.o` ✓ EXIT=0、`viewerbackend.cpp.o` ✓ EXIT=0（含 cmake 重配成功）。

## 12:2x 「换网站登录态失败站点返回 HTTP 0」——根因机制 + 修复（被控端 `c73daa1`，版本升 0.6.27）

**用户报**：「远端提示：换网站登录态失败站点返回 http 0」。出处 `control-qt/src/oauthbind.cpp:265` —— 是**被控端**「用星璃账号绑定」的换令牌步骤，**不是管理端**。

**根因（呈现层，实测确证）**：`QNetworkReply::attribute(HttpStatusCodeAttribute)` 在**传输层失败**时是**无效 QVariant**，`toInt()` 得到 **0** —— 这个 0 **不是站点返回的状态码**，而是「一个字节的 HTTP 响应都没收到」。旧代码把 0 当状态码直接报出，而真因（DNS 解析不了 / 连接被拒 / TLS 握手失败 / 被代理或杀软拦）只在 `error()` / `errorString()` 里，**被整段丢掉**。

① `onTokenFinished`/`onBindFinished` 取出 `error()`/`errorString()`，区分「没拿到任何响应（status==0）」与「站点确实回了非 200」；

## 16:0x · 🔴 TLS 后端生产事故 + 三端登记项（WorkBuddy）

### 事故（用户贴学生机 DESKTOP-I15OM55 的 agent-qt.log 定位）

```
[oauthbind] 自检：TLS 可用=否 运行时=(未加载) 后端=cert-only 应用代理类型=2
QSslSocket::connectToHostEncrypted: TLS initialization failed   （networkError=99）
```

⇒ **"被控端连不上地址" 与 "换网站登录态 HTTP 0" 是同一根因**：Qt 的活跃 TLS 后端退化成 `cert-only`（**只能解析证书、不能建 TLS 连接**）。同一次启动里 `连接 wss://…` 之后**永远没有** `已连上云端`。

### 根因链

| 层 | 事实 |
|---|---|
| 1 | `HTTP 0` 不是状态码，是"一个字节响应都没收到"（`HttpStatusCodeAttribute` 无效 → `toInt()`=0） |
| 2 | 真因是 TLS 层初始化失败（`networkError=99`） |
| 3 | 活跃后端是 `cert-only` —— Qt 的**退化后端** |
| 4 | **Qt 6.12 的 TLS 后端是插件**（`{app}\tls\`：qcertonly / qopenssl / qschannel） |
| 5 | **windeployqt 默认只部署 certonly + schannel、不拷 openssl 后端**（`--list relative` 实测只列这 2 个） |
| 6 | schannel 在部分机器（杀软 / 系统策略 / LTSC 精简）加载失败 ⇒ 退化成 cert-only |
| 7 | **CMake 与全部脚本里都没有 windeployqt 调用** —— `build/tls/` 是 10-12 10:10 手工跑一次留下的 |

**佐证**：本机 `C:\Program Files\Stelarith\tls\` 有 3 个（含 qopensslbackend，10-11 17:40）—— 那是**手工救场补的，从未固化**。这正是事故之根。
