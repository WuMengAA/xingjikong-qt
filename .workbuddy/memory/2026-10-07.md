## 管理端 0.6.11：输入框主题 + 通知契约 + 收流页换目录

触发：真机反馈「暗色模式下的通知无法输入内容 / 通知收到待完善」+ 0.6.10 运行日志。

### 1. 「无法输入内容」= 白底白字，不是不能输入

界面上 7 处输入框**都只写 `color: th.fg`、没人设 `background`** ⇒ 沿用 Qt 系统调色板（Windows 白底）。
暗色外观 `th.fg` 是 `#FAFAFA` ⇒ **白底白字，字打出去了但一个都看不见**。

⚠️ 教训：**控件级样式在每个调用点各写一遍 = 写一遍漏一遍**，漏的那遍就是 bug。样式类的东西要有唯一组件。

### 2. 通知弹窗此前拼的是**错参数**（界面自己拼了一份，跟被控端对不上）

`qml/NotifyParams.js` 那份契约一直存在（还有 `scripts/test-notify-params.mjs` 16 条断言，本次跑 PASS=16），
**但界面根本没用它**，内联拼的是 `{title, content, seconds:8, tts:true, flags:{severity}}`：

| 界面发的 | 被控端 `notifyFromParams()` 实际读 | 后果 |
|---|---|---|
| 顶层 `tts` | **只读 `flags.speech`** | 朗读从来没生效过 |
| `flags.severity`（任何形态都带） | 只在 `fullscreen` 下读 | "重要/紧急"点了等于没点 |
| 无 `kind` | `params["kind"]`，缺省→popup | 形态永远只能是弹窗 |

现在全走 `buildNotifyParams()`：形态三选一、朗读、秒数、紧急确认；严重度非全屏时**置灰并写明原因**；
字数超 24/64 提前提示；支持发给多选设备（`batchStart` + 逐台 sendAction）。

### 3. 收流页临时文件：带 PID 也照样「拒绝访问」→ 根因是**目录**不是名字

`QDir::tempPath()` 是公共目录，系统清理/实时防护扫描都在那儿落文件，文件名再唯一撞上一次就完蛋。
改法：① 挪到应用私有缓存目录 `QStandardPaths::CacheLocation`；② 用 `QTemporaryFile` 发名（原子创建、撞了自动换名）；
③ `setAutoRemove(false)`（要留给 WebEngine 加载），路径存新成员 `m_rtcHtmlPath`，析构里删。
自检实证：已在 `AppData\LocalLow\Stelarith Viewer\cache\` 生成 `stelarith-viewer-rtc-WBYQfl.html`（6728 B）——
**Temp 那条路一直失败的这一步现在成功了**。

## 管理端 0.6.12：灵动岛贴左上角 + 输入框绑定循环 + 批量收口

用户直接甩了一张截图：灵动岛展开面板**贴在左上角盖住左栏**，写着「通知 0/1」不动，顶部「0 台在线」。

### 1. 锚点锚在了 Window 上（截图那个现象）

```qml
anchors.horizontalCenter: root.horizontalCenter   // root = ApplicationWindow
```
**ApplicationWindow 继承 QWindow，不是 Item** ⇒ 没有 anchors 体系、没有 horizontalCenter，
赋个 undefined **静默失效**（不报错、不打日志），Item 退回 x=0 ⇒ 从窗口最左边长，正压左栏。
改锚 `parent`（子项进 `contentItem`，它是 Item）。Toast 同样。
**实测探针：`island x=590 parentW=1180`（正中）；修前 x=0。**

⚠️ 好教训：**QML 里"不报错的错"最贵** —— 锚 Window 只是安静地不生效。

### 2. 我 0.6.11 引入的回归：`th: th` 绑成自己

调用点写 `th: th`，QML 右值先在**组件自身作用域**找 `th` ⇒ 自引用 ⇒
真机刷 7 条 `QML InputField: Binding loop detected for property "th"`，
`th` 恒 null ⇒ 用兜底色 ⇒ **亮色下输入框文字仍近白，0.6.11 那件事其实没修完**。
改 `th: root.th`（`CommandPalette` 那处本来就是 `pal.theme`，无事）。
⚠️ 抽组件时，**调用点的属性名不能和目标组件自己的属性同名**，否则绑定自噬。

### 3. 「通知 0/1」不动 = sendAction 不管在线

`sendAction()` 只检查 `currentUid` 非空、**不检查在线**。设备离线时指令发出去没人回执，
`batchStep` 永不推进 ⇒ 灵动岛永远亮着。补两处：① 下发前 `isDevOnline()` 过一遍，离线直接结账不发；
② 窗口层 `batchTimeout` 按台数 10s~60s 收口，到点把剩下的算失败并如实报。

### 事故（如实记）
摘临时探针时脚本用 `find('        Timer {')` 找起点，**匹配到文件里第一个 Timer**（不是探针那个），
一路删掉 1000+ 行（2565 → 1557）。处置：坏文件存 `.workbuddy/Main.qml.broken` →
`git checkout --` 回 0.6.11 → 用**锚点+行号双重定位**的补丁重做全部改动。
⚠️ **删区间前先确认起点唯一**，别拿"第一个匹配"当锚。

### 验证
qmllint 无 Error → 编译 `[exit] 0` → **离屏自检报错行 0**（Binding loop 已消）→
出包 131,451,007 B / 18/18 / sha `ec3a8ba7…` → ota 0.6.12 → viewer `c9aa60c→3d0615b`。

## 管理端 0.6.13：画面区放大 + UI 收口 + 自检开关

用户：「留给画面的区域太少了」「UI 值得统一标准，找好 UI 库」。

### 1. 画面太小 —— 先量再改

临时探针（只改 `build/` 里的 QML，运行时加载，不必重编译）实测三栏：
`left=160 mid=671 right=293 win=1180 rightImpl=293`。

**修前**（按截图换算，原图 1756×1173 → 逻辑 1180）：左 168 / **画面 ~299** / 右 ~657。

根因：**`Layout.preferredWidth` 不是硬约束**。右栏内容自然宽 293，却被某项顶到 657，
多出来的宽度是从靠 `fillWidth` 吃剩余的**画面区**身上抢的 ⇒ 画面被压成竖缝。

改法（不依赖"猜是谁顶的"）：左右栏各加 **`Layout.maximumWidth` 硬上限**（184 / 300），
画面 `fillWidth` + 显式 `preferredWidth: 640`。实测画面 **299 → 671（2.24 倍）**。

### 2. UI 收口

盘点（实测计数）：裸 `Button` **5 → 0**、`Btn` 10 → **15**、`Card`/`EmptyState` **0 引用**、手写 `MouseArea` 22。
**裸 Button 走系统调色板 = 黑白界面里唯一会"自己变白"的控件**（与 0.6.11 输入框白底白字同源）。
5 处（发送/设定/广播/考试起停）全部并到 `Btn`，并补显式 width（Btn 是 Rectangle，没有 implicitWidth）。

新建 `docs/UI规范-2026-10-07.md`：令牌表 / 圆角 3 档 / 字号 4 档 / 组件白名单 / **6 条禁止写法**；
调研结论：**不引第三方 UI 库**（Kirigami/Cutie/停更的 qml-material 都不划算；Qt 官方 FluentWinUI3
能用但会整套推翻黑白稿）——**缺的不是库，是唯一真源**。

### 3. STE_ALLOW_MULTI：让自检不再被单实例挡住

`singleinstance.cpp` 加开发开关（默认不设⇒行为逐字不变；`.h/.cpp` 已按规矩原样同步到被控端，
两端 md5 一致）。**为什么值得**：0.6.9/0.6.10/0.6.11 连续三轮因用户开着管理端而没法自检，
0.6.11 那个 `InputField Binding loop` 就是这么漏到用户眼前的。现在跑着正式版也能起离屏实例。
