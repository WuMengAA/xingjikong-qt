## 教训（可复用）

1. **动通用闸门前，先问"谁在依赖它"**。这次差点直接把内容指纹加进所有 kind 的限流键 ——
   那会打穿 #496 缩略图防刷屏（缩略图每帧内容都不同 ⇒ 限流失效 ⇒ 60×40 直接灌爆）。
   正确做法是**默认不变 + 按需开启（opts）**，并跑压测实证结论未变。
2. **新写的守卫型用例必须做变异验证**：临时撤掉修复跑一遍，确认它会变红。
   否则很可能写出"永远通过"的假守卫（本环境吃过多次假阴性/假阳性的亏）。
   `git stash push -- <file>` 是最干净的撤法（不动别人文件、pop 即恢复）。
3. **测试里不要留 `MIN_MS=0` 这类绕过**：绕过会让被测路径失真，修复后来必须拆掉，
   让测试跑在真实默认参数上（这轮拆掉后立刻暴露了 3 个用例的真假）。

- **四形态实证表**（`scripts/_var_probe.cpp`，QML 侧读同一 property）：
  | C++ 写入 | QML 读成 | `!== null` | `=== null` |
  |---|---|---|---|
  | 初始未写 | `null` | false | true |
  | `setProperty(k, QVariant())` | **`undefined`** | **true（穿透）** | false |
  | 活 QObject | 对象 | true | false |
  | `setProperty(k, fromValue<QObject*>(nullptr))` | `null` | false | true |
- `undefined !== null` 按 JS 严格比较为真 ⇒ QML 写 `x !== null` 守卫被穿透，绑定重算读 `.active`/`.nextTitle` 抛 TypeError。**真值判断（`x` / `!x`）对 null/undefined/活对象三态全兼容**。
- **修复（两处配合）**：① island.cpp `setQmlObjectProperty` 的 destroyed 回调清空改用 `QVariant::fromValue<QObject*>(nullptr)`（读成 null）；② IslandRoot.qml 四处守卫 `!== null`/`=== null` → 真值判断（参考行 45 `bridgeRef` 早有 `typeof x !== "undefined" && x !== null` 双保险）。收起态 `_expanded=false` 会短路不抛——解释现场恰 3 条而非 4 条。
- **探针前后对比闭合**：island 探针 `--vhclear` 模式（注入假 QObject→delete 触发销毁回调→400ms 后数 TypeError）：**修复前 3 条/退出码 1 → 修复后 0 条/0**；`--expand`/`--face` 回归 0 错；状态面截图确认「VoiceHub：模块未注入」渲染正确。

### 根因 2：OAuth 403 = SvelteKit `csrf.checkOrigin`（生产站点 curl 对照实证）

- SvelteKit 对**form 类 Content-Type**（`x-www-form-urlencoded`/`multipart`/`text-plain`）的 POST 校验 Origin 头；QNAM 默认不发 Origin ⇒ 403「Cross-site POST form submissions are forbidden」。`application/json` 不触发（is_form_content_type 判定失败）。
- **Live 实锤**：同一站点 `/oauth/token`，form 编码 → 403 与现场日志逐字一致；JSON → 400 `invalid_grant`（穿透 CSRF 直达业务逻辑，假 code 按设计拒绝）。
- **修复**：oauthbind.cpp token 交换 form → JSON（站点 `toParams` 本就有双形态支持，无需站点改动）。
- 隐患（只报未动）：VoiceHub 等其它调 `/oauth/token` 的 form 客户端会有同款 403。
