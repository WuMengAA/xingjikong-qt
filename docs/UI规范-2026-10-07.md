# 星集控管理端 · UI 规范与组件标准（2026-10-07 立）

> 这份是**干活时照着做**的东西，不是宣传稿。数据都是当场量出来的（探针 / 计数），不是印象。

---

## 一、先回答"要不要找个 UI 库"

**结论：不引入第三方 UI 库；把自家这套立成标准，并用 Qt 自带样式兜底。**

### 备选与代价

| 方案 | 是什么 | 为什么不选 |
|---|---|---|
| **Qt 官方样式**（Basic / Fusion / Material / Universal / **FluentWinUI3**） | Qt Quick Controls 2 换皮肤，一行 `QQuickStyle::setStyle("FluentWinUI3")`。本机 Qt 6.8.1 已带 FluentWinUI3 实现（`Qt6QuickControls2FluentWinUI3StyleImpl.dll` 在 build 里） | **不是不能用**，而是它会**整套推翻既有黑白设计稿**（变成 Windows 11 原生观感：彩色、Mica、圆角阴影）。设计稿是"黑白、无彩色、唯一强调＝反白"，两套语言不能混。真要换，是全站换、不是局部换 |
| **Kirigami（KDE）** | QML 组件库，功能完整 | 依赖 KF6 框架，Windows 上要拖一整套 KDE 运行时。为一个单平台桌面端背这个，不划算 |
| **Cutie / Lomiri（Ubuntu）** | QML 组件库 | 面向 Linux 触摸端，Windows 桌面不适用 |
| **qml-material** | 老牌 Material QML 实现 | Qt5 时代停更，Qt6 上跑不起来 |
| **Fluent 2 / Material 3 / Ant Design / Apple HIG** | **设计规范**（不是代码） | ✅ **这些才是该看的** —— 我们抄它们的"标准维度"（间距阶、字号阶、状态色、控件状态机），不抄它们的皮 |

**我们缺的不是"库"，是"唯一真源"。** 证据见下（都是真实发生过的）：

- 输入框 7 处各自只写 `color: th.fg`、没人设 `background` ⇒ 沿用系统白底 ⇒ **暗色下白底白字，输入的字看不见**；
- 裸 `Button` 5 处（Qt 自带，走系统调色板）⇒ 黑白界面里**唯一会自己变白的控件**；
- 组件传参 `theme: th` 导致 `InputField` 的 `th` **绑定成自己**（Binding loop，属性恒 null，悄悄用兜底色）；
- `Card.qml` / `EmptyState.qml` **建好了 0 引用** —— 页面里全在手写 Rectangle。

这四条是同一个病：**没有单一真源**。引一个第三方库不解决它，只会多一套语言。

### 字（对比度按 WCAG 算，不凭感觉调）

| 令牌 | 暗色 | 亮色 | 用途 | 暗色实测（对底 `win` `#0A0A0A`） |
|---|---|---|---|---|
| `fg` | `#FAFAFA` | `#161616` | 主文字 | 18.97:1 |
| `op` | `#C8C8C8` | `#3C3C3C` | 次文字 | 11.83:1 |
| `fg3` | `#8A8A8A` | `#6E6E6E` | 辅助文字（按钮字、说明） | **5.73:1** ← 曾 `#5A5A5A` **2.87:1** ❌ |
| `fg4` | `#707070` | `#808080` | 最弱（离线设备名、禁用态） | **4.00:1** ← 曾 `#3A3A3A` **1.74:1** ❌ |
| `ph` | `#6E6E6E` | `#8A8A8A` | 占位符（`InputField` 在用） | **3.88:1** ← 曾 `#4E4E4E` **2.38:1** ❌ |
| `inv` | `#F0F0F0` | `#1A1A1A` | **反白**：唯一的强调手段（选中态、主操作、实时链路） | — |

**为什么拿 WCAG 数字说话**：2026-10-07 用户报"字体、对比度太小"，量出来旧值
`fg3` 只有 **2.87:1**、`fg4` **1.74:1** —— 前者低于 AA 正文线（4.5:1），
后者连大字号线（3:1）都不到，**而这两档合计用了 65 处**（暗色下最常读的就是它们）。
现在：正文类 ≥ 4.5:1（`fg3` 已达标），最弱档（`fg4`）定 **≥ 4:1** ——
它是"次要"，不是"看不清"。

> ⚠️ **铁律：`inv` 当底色的地方，字必须用 `win`。**
> `#F0F0F0` 浅底 + 近黑字 = 稿子说的"反白"。写 `fg3` 只有 2.95:1；
> 写死 `"#111"` 在**亮色下直接消失**（亮色 `inv` 是近黑的 `#1A1A1A`）。
> 0.6.14 之前 `Btn` 的 `strong` 态、集控页 5 处选中 chip 都踩在这里。

### 圆角

`rWin 16` / `rCard 12` / `rCtrl 8` —— 三档，别再出现第四个数字。

**字号只有四档**：`12 注 / 13 正 / 14 徽标 / 16 标题`（另有 `20`，只给"在线设备数"那种大数字）。

> **2026-10-07 调整（用户报"字体太小"）**：原定 `11 / 12 / 13 / 15`，而 `11` 恰恰是
> **用量最大的一档（65 处）** —— 等于"最小档当了主档"。整体抬一档后：
> `11→12`、`12→13`、`13→14`、`15→16`，并顺手**消灭 `10px`**（`11` 都不是最小了，`10` 更没理由）。
> 共改 **123 处**。根窗口设 `font.pixelSize: 13` 兜底：漏写 `pixelSize` 的文字
> 不会再掉回系统默认的小字。
> ⚠️ 抬字号会同时顶大容器需求量（实测右栏内容高 543 → **624**，可用 660，**还没溢出但余量只剩 36**）
> ⇒ 再往右栏加按钮，**先改成 Flickable**，别继续抬 `minimumHeight`。

## 三、组件标准（白名单）

页面里**只允许**用 `qml/components/` 下的这些东西；需要的控件没有，就**加一个组件**，不许在页面里手写样式。

| 组件 | 行数 | 用法 | 引用数（2026-10-07 实测） |
|---|---|---|---|
| `Btn.qml` | 63 | 所有按钮。`theme` + `text` + `width`（**必须显式给宽**，它不写死宽）+ `strong`（主操作反白）/ `disabled` / `tip` | **15**（本轮把最后 5 处裸 Button 也换进来） |
| `InputField.qml` | 42 | 所有单行输入。自带底色/描边/占位色/聚焦态 | 7 |
| `ToggleRow.qml` | 68 | 设置页的开关行 | 2 |
| `CommandPalette.qml` | 201 | Ctrl+K 命令面板（命令表由主界面装配） | 1 |
| `DynamicIsland.qml` | 204 | 灵动岛（状态聚合层） | 1 |
| `AccountMenu.qml` | 275 | 顶栏账户菜单 | 1 |
| `Card.qml` | 57 | 卡片壳 ⚠️ **0 引用** | 0 |
| `EmptyState.qml` | 43 | 空态 ⚠️ **0 引用** | 0 |

### 禁止写法（每条都对应一个真实事故）

1. **`Button { }` / `TextField { }`** —— Qt 自带控件走系统调色板，黑白界面里它们会自己变白（或白底白字）。用 `Btn` / `InputField`。
2. **在页面里写 `color: "#......"`** —— 页面只认 `th.*`。例外要写在注释里说清为什么。
3. **`TextField { color: th.fg }` 但不给 background** —— 就是 0.6.11 那个"输入的字看不见"。
4. **组件调用点把属性写成与组件自身属性同名**（`InputField { th: th }`）—— 会自引用成 Binding loop。一律 `th: root.th`。
5. **给 `Btn` 不写宽度** —— 它是 Rectangle，没有 implicitWidth，会变成 0 宽。
6. **把锚点锚在 `root`（ApplicationWindow）上** —— Window 不是 Item，锚点**静默失效**（灵动岛因此贴过左上角）。锚 `parent`。
7. **在 `inv`（反白）底上写 `fg3` / `fg4` / 裸 `"#111"`** —— 浅底必须配 `win`（近黑）。
   这条是"提了对比度反而更糊"的唯一来源：`fg3` 从 `#5A5A5A` 提到 `#8A8A8A` 后，
   落在 `inv` `#F0F0F0` 上只有 **2.95:1**（原来 6.05:1）。
8. **只在暗色下验对比度就收工** —— 亮色是同一批令牌的另一半，`inv` 在两边是**反转**的。
   暗色下的"浅底深字"，亮色下变成"深底浅字"，**同一处写死色值必然在另一边翻车**
   （集控页那 5 处 `"#111"` 就是这样：暗色能用，亮色直接看不见）。
9. **改色值后不量就交** —— 对比度是算出来的数，不是看出来的。改令牌前后各跑一次：

```python
def _l(h):
    h = h.lstrip('#'); c = [int(h[i:i+2], 16) / 255 for i in (0, 2, 4)]
    c = [(x / 12.92 if x <= 0.03928 else ((x + 0.055) / 1.055) ** 2.4) for x in c]
    return 0.2126 * c[0] + 0.7152 * c[1] + 0.0722 * c[2]

def contrast(a, b):                      # 返回 a 与 b 的对比度（≥4.5 才够正文）
    la, lb = _l(a), _l(b)
    return (max(la, lb) + 0.05) / (min(la, lb) + 0.05)
```

## 五、下一步（按性价比排序）

1. **把主题抽成 QML 单例 `Theme.qml`**（`pragma Singleton` + `qmldir`）。
   收益：组件直接读 `Theme.fg`，**彻底取消 `theme: th` 传参** ⇒ 从根上不可能再出现"绑定成自己"那类事故；页面也不用处处传 `th`。
   代价：牵动全部 8 个组件 + 所有调用点，必须独立一轮做完整验证（不能顺手改）。
2. **`Card` / `EmptyState` 用起来**：把页面里手写的卡片壳和空态换成组件，消灭 0 引用。
3. **抽 `SectionLabel`**（组标题）与 `NumericField`（秒数/时长类输入）。
4. **字号与间距令牌化**：现在 `11/12/13/15` 和 `10/12/14/16` 散在页面里，改成 `th.fsNote` / `th.sp2` 这类名字，改一处就能全局调。

> 换不换 Qt 官方外观（FluentWinUI3）是**另一个决定**：一行代码的事，但等于换掉整套黑白语言。
> 要试可以先用命令面板/环境变量做开关，看两版再定，别直接改主分支默认值。
