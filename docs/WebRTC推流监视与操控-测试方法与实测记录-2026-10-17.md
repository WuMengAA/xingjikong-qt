## 0. 判定基线（先看懂这些，测的时候对上号）

| 层 | 工具/判据 | 说明 |
|---|---|---|
| WebRTC 链路 | 两端日志出现 `DTLS handshake finished` + `SRTP profile is: ...` + `PeerConnection 状态 → Connected` | 媒体加密通道建立，这是 H264 能走的前提 |
| STUN 打洞 | 两端 Debug 日志出现 `srflx`（服务器反射候选） | 表示 NAT 后能拿到公网可路由地址（本机 miwifi STUN 实测可达） |
| SDP 正常 | answer 里 `m=video 9 ... AVPF`（**port 9 而非 0**） | port 0 = 该媒体被拒（= 0 帧的直接原因） |
| SDP 必带 | offer 里 screen media 有 `a=ssrc:42` | **缺它=接收端无法路由 RTP=0 帧**（本轮唯一最终根因） |
| H264 出帧 | answer 工具打印 `H264 帧 #N: xxx B` | 帧级证据 |

## 2. 摄像头监视（WebRTC 第二轨 · 2026-10-17 已 H264 化并沙箱实测通过）

### 2.1 现状（已改造）
- 摄像机走独立 `camera` track（mid="camera"，payload 97，SSRC=43），与屏幕轨同一 PeerConnection；
- **2026-10-17 摄像头轨 H264 化**（agent `20c5767` + viewer `d87c902`）：ffmpeg dshow 采集 → libx264 → H264(Annex B) → H264RtpPacketizer 打包（不再是手动 JPEG-over-RTP）；接收端 camera 本端轨挂 H264RtpDepacketizer + 独立解码子进程（scale 统一 320x240）；
- 隐私红线保留：**只有管理端发 `camera_stream_start` 才采集**（不看不采）。

### 2.2 测试方法（已实测）
1. agent 侧：`camera_stream_start`（带 device；`STE_CAM_TEST_SRC=lavfi` 时用 ffmpeg lavfi testsrc2 模拟源——沙箱验证用，真机不设该变量走真实 dshow）；
2. agent 日志验证：`摄像头采集已开（device=…）` + 回执 `result=done`；
3. answer/viewer 侧：camera 轨 H264 帧出现（`CAM 帧 #N: xxx B`）；
4. 关格 → `camera_stream_stop` → agent 停采（隐私「不看不采」验证）。

### 2.3 实测结果（2026-10-17）
> ✅ **摄像头 H264 端到端通过**（沙箱 8899 + lavfi 模拟源，无真实摄像头用模拟源替代）：
> `[result] 屏幕 H264 帧 116 ✓ | 摄像头 H264 帧 709（1,226,714 B）✓`
> CAM 帧 #1 4687B 起持续；agent 实锤 `收到指令 camera_stream_start（D5 真执行）→ 采集已开 → 回执 done`。
> **未验证**：真实 dshow 摄像头源（本机两虚拟设备 BindToObject 失败，属环境限制）；真机 viewer 摄像头格显画。

## 3. 键鼠映射直通与触控支持（操控）

### 3.1 现状（两端均已实现，代码级已核）
- **下发链路**：viewer `sendPointer(kind, nx, ny, button)` / `sendKey(vk, action)` → 云端 `instruction/input` → agent `SendInput` 注入；
- **坐标**：viewer 把画面区坐标归一化 0~1 → agent 按**虚拟桌面**（SM_VIRTUALSCREEN，非主屏）换算绝对坐标（修过投影仪副屏偏移 bug）；
- **三键**：left/right/middle 分别映射 DOWN/UP；滚轮 `wheel` + delta；
- **键盘**：`key` 携带 Windows 虚拟键码（vk 1-255），down/up 分离，方向键带 EXTENDEDKEY；组合键（Ctrl+C / Ctrl+Alt+Del）由管理端按序发多个 down 再逐个 up；
- **触控**：教室大屏为触摸屏场景——抓屏侧已含触控容差（island.cpp），画面区 MouseArea 按「按住才移动」设计（悬停绝不灌指令）。

### 3.2 测试方法（真机/双实例）
| 项 | 操作 | 期望 |
|---|---|---|
| 左键点击 | 画面区点一下 | 对象被点开（开始菜单/应用图标） |
| 右键菜单 | 画面区右键 | 弹出右键菜单 |
| 拖拽 | 按住拖动 | 窗口/文件被移动 |
| 滚轮 | 画面区滚轮 | 页面滚动 |
| 键盘打字 | 点画面区 → 键盘输入 | 输入框出现字符 |
| 方向键/F1-F12 | 点画面区 → 按键 | 编辑器/游戏响应 |
| 组合键 | Ctrl+C | 复制生效 |
| 坐标准确性 | 点屏幕角落 | 落点不偏移（验证虚拟桌面换算） |
| 悬停安全 | 鼠标停在画面区不动几秒 | 日志无 `操控→ move` 刷屏 |
| 触控（真机） | 触摸屏上滑动/点按 | 与鼠标同效 |

### 3.3 实测结果（2026-10-17 沙箱指令链路）
> ✅ **键鼠指令链路沙箱端到端实测（viewer→云端→agent→SendInput）**——用 ws_answer_h264 按真实 viewer 的 v1 `instruction` 信封下发，agent 三条全回执：
> - `input move(0.5,0.5)` → **result=done**（SendInput 移光标真执行，屏幕中央）；
> - `input key vk=300`（越界值）→ **result=failed，error="vk 无效:300"**（校验分支正确拦截）；
> - `input wheel(delta=120)` → **result=done**（SendInput 滚轮成功）。
>
> ⚠️ **未验证**：真实按键/点击落点效果需真机（沙箱为避免干扰桌面，只测了无破坏性路径 move/wheel/非法值；SendInput 键盘与三键 down/up 代码路径相同，逻辑已覆盖但真机按 §3.2 表闭环）。
