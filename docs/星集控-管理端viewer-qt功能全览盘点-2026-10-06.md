## 3. 动作覆盖：被控端 32 → 管理端能发 31

**口径**：动作名单取自被控端 `Stelarith-control-qt/src/main.cpp` 里
`action == QStringLiteral("xxx")` 的全部命中（32 个），与管理端源码里实际下发的名字做集合差。

| 项 | 结论 |
|---|---|
| 被控端动作总数 | 32 |
| 管理端已覆盖 | **31** |
| 缺口 | **`self_update`（仅此一个）** |
| 假缺口 1：`open_app` | 被控端 `main.cpp:1856` 就是 `launch_app \|\| open_app` **同一分支**，端到端行为一样，属于别名单，不必单独接 |
| 假缺口 2：`input` | 不走 sendAction，而是 `sendPointer()` / `sendType()` 直接构造 `action:"input"`（`viewerbackend.cpp:1121,1295`）——即远控打字那一路，**已覆盖** |

已覆盖（按用途分组，共 31）：
- **基础状态**：ping、lock、shutdown、reboot、screenshot、set_volume
- **应用进程**：launch_app、list_shortcut_candidates、process_list、process_stop
- **通知**：notify（6 处调用，popup/island/fullscreen 三态齐全）
- **日志**：log_tail
- **计划任务**：schedule_shutdown、schedule_reboot、list_schedules、cancel_schedule
- **摄像头**：camera_list、camera_snapshot、camera_record_start、camera_record_stop
- **媒体文件**：media_list、media_delete、media_session_start、media_session_stop
- **文件推送**：file_push、file_chunk、file_done
- **远控**：remote_control_start、remote_control_stop、input
- **自更新**：❌ self_update

## 6. 顺带查实的一件事（对接一户通用）

桌面管理端接入站点票据**比想象中小改**：

- 云端 WS **早就接受票据**：`cloud-ws/src/index.js:584-585` 的 `authorizeViewer()` 里
  `if (ticket) return verifyViewerTicket(ticket);` —— 桌面端只要握手时发 `ticket` 字段即可，
  无需云端任何修改。
- 管理端当前握手固定发 `{"type":"auth","payload":{"token":…}}`（`viewerbackend.cpp:718`），
  令牌来源是 `qEnvironmentVariable("STE_VIEWER_TOKEN")`（`viewerbackend.cpp:182`），
  回落的默认地址是 `ws://127.0.0.1:8788/ws/viewer`（`:180`）。
- 站点已有一张能签票的端点：`POST`-`GET /admin/console/mobile/ticket`
  （`website/.../mobile/ticket/+server.ts`：cookie + `userCan(viewConsole)` → `mintViewerTicket`，TTL 2 分钟）。
- ⚠️ **但 2 分钟窗口对桌面端不够**：桌面端是常驻程序，不是页面。需要的是「登录一次 → 拿一张
  长一点的票（或服务器签发 refresher）→ 重连自动续」。这块要新设计，不能照抄 mobile 页的 2 分钟 TTL。
