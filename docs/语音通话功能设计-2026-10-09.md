# 语音通话功能设计（2026-10-09 · 增量：语音对讲 → 双向通话）

> 现状：语音对讲 = 老师**单向**讲（管理端 waveIn 采集 → 云端 fan-out → 学生 waveOut 播放）。
> 目标：升级为**双向通话**——学生可应答回传，老师能听到学生那头。
> 依据：三端 grep blob 实测（audio 路径全链路）。

---

## 1. 现状全链路（已核实）

```
管理端 viewerbackend：audio_capture.h（winmm waveIn 采集）
  → 二进制帧 mime=audio/pcm → 云端
云端 index.js：audio.start/stop → setAudioBroadcasting(bool)
  → broadcastAudioToAgents(buf, 'audio/pcm', seq)  [fan-out 全部在线设备]
被控端 control-qt：AudioPlayer（winmm waveOut 懒打开）播 audio/pcm
```

**缺口（双向所需）**：
| 端 | 缺什么 |
|----|--------|
| 被控端 | **麦克风采集**（现「只收不采」3.3.6 安全约束；有 noise_monitor 的 WASAPI 骨架可复用）|
| 云端 | **反向通道**：学生音频 → 单播回「发起对讲的老师」（不是再广播全教室）|
| 管理端 | **播放能力**：学生回传的 audio/pcm 播放（现只有采集无播放）|

## 2. 双向通话架构

```
老师（管理端）                   云端                          学生（被控端）
┌─────────────┐   audio/pcm ↑   ┌──────────┐   audio/pcm ↑   ┌─────────────┐
│ waveIn 采集  │ ───────────────→ │ 广播(全班)│ ───────────────→ │ waveOut 播放 │
│ waveOut 播放 │ ←── audio回传 ───│ 单播(老师)│ ←── audio回传 ───│ waveIn/mic  │
└─────────────┘      单播        └──────────┘      上行        └─────────────┘
```

- **下行（老师→学生）**：沿用现有 fan-out（全班听）
- **上行（学生→老师）**：新增，**单播到发起者**（隐私边界：学生只对讲给老师，不广播全教室）

## 3. 安全边界（关键设计决策）

**现 3.3.6「学生端只收不采」是有意设计**（防教室机被当窃听器）。双向必须放开麦克风——**用「会话内采集」压住风险**：

| 边界 | 规则 |
|------|------|
| 触发 | 仅当**老师发起 `audio.start` 且带 `duplex:true`** 参数时，学生才开采集（默认单向不变）|
| 时长 | 对学生端采集设**硬上限**（如 120s），与老师讲话上限（现有 m_speakMaxMs）同档 |
| 目标 | 学生音频**只单播给发起老师**的 WS，不落盘、不广播、不转第三方 |
| 停止 | 老师 `audio.stop` 或超时 → 学生端立刻关 mic、丢缓冲 |
| 可视化 | 学生机保持「正在进行语音通话」提示（现有对讲提示沿用）|
| 考试模式 | **NotificationGate 拦截**：考试激活期间 mic 采集一律拒绝（§6.2 已定）|

## 4. 改造点

### 4.1 被控端（control-qt）
| 项 | 内容 |
|----|------|
| 麦克风采集 | 新 `microphone.h/cpp`（waveIn 或 WASAPI；复用 noise_monitor 骨架），会话内开关 |
| 指令 | 收 `audio.start{duplex:true}` → 开 mic；`audio.stop` → 关 |
| 上行帧 | 与下行同协议（[1B 版本][2B headerLen][header JSON][payload], mime=audio/pcm），发回云端带 `to=teacher-uid` |
| 考试 | NotificationGate 前置拦截 |

### 4.2 云端（cloud-ws）
| 项 | 内容 |
|----|------|
| 会话态 | `audio.start{duplex:true}` 记录发起者 teacherUid + duplex 标志 |
| 上行收 | 学生二进制帧 → **单播**回 teacherUid 的 WS（新增 `sendAudioToViewer(uid, buf)`）|
| 广播不变 | 下行仍 fan-out 全班（非 duplex 时行为完全不变）|
| 边界 | 无 duplex 会话时拒收学生上行帧；teacherUid 离线即弃 |

### 4.3 管理端（viewer-qt）
| 项 | 内容 |
|----|------|
| 播放 | 新增 `audio_playback.h/cpp`（winmm waveOut 播 audio/pcm，与被控端 AudioPlayer 同族）|
| 会话 | `audio.start` 带 `duplex:true`（UI 上「对讲」→「通话」开关）|
| 收听 | 收上行 audio/pcm → waveOut 播放 |

## 5. UI（管理端）

- 「语音对讲」区按钮升级：**「对讲」= 现有单向**；**「通话」= 双向**（带 duplex）
- 通话中显示「学生正在说话」指示（收到上行帧时亮，用彩色规范 `ok` 绿点）
- 收尾可选：通话时长、挂断按钮（现有停止已有）

## 6. 实现顺序与验证

1. **管理端播放组件** `audio_playback`（独立文件可先造可测）
2. **被控端 mic 组件** `microphone`（独立文件可先造可测）
3. 云端 `duplex` 会话态 + 单播回传（index.js/registry.js——与 WorkBuddy 共区，靠窗口）
4. 三端接线 + 隔离联调（云端 8095 + 假双端）
5. 真机：教室机对讲回传实测

## 7. 不做（第一版）

- ❌ 不做全双工混音（半双工通话：说话互斥，分离学两不可同时出声）
- ❌ 不做音质增强/降噪（PCM 原样，后续接 opus 再谈）
- ❌ 不做多点通话（1 老师 ↔ N 学生提问式，非多方会议）
