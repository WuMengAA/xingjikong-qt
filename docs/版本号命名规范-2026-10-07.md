# 版本号命名规范（DeepSeek Harness 同款）

> 生效：2026-10-07（2026-10-07 晚间补 `-alpha.N` 内测阶段）· 适用：星集控三端（被控端 / 管理端 / 云端 OTA 清单）
> 同款参照：DeepSeek Harness（`@deepseek-ai/dsh`）的版本列表——
> 三位数核心版本 + **两个并存的阶段后缀** `-alpha.N`（内测）/ `-rc.N`（候选），号从 1 起、允许跳号，
> **成熟度标记（内测/公测/强制升级）不塞进版本号里**。
>
> dsh 真实例（`npm view @deepseek-ai/dsh versions` 摘录）：
> `0.0.1-rc.1 / rc.2 / rc.5`、`0.1.0-rc.2 … rc.8`、`0.1.2-alpha.2 ~ alpha.5`、`0.1.2-rc.1`、
> `0.1.7-alpha.1 / alpha.2`、`0.1.7-rc.1 / rc.2`、`0.2.0-rc.1 / rc.2`、`0.2.1-alpha.1`。
> 注意这里的关键事实：**`-alpha` 与 `-rc` 是两条并存的链，不是同一条链改叫法**
> ——`0.1.2-alpha.5` 之后是 `0.1.2-rc.1`（不是 `0.1.2-alpha.6`），中间还插着别的 alpha。

---

## 0. 为什么要改

改之前是「心里有个 0.6.x，各处手写」：CMakeLists 一份、源码里一份、installer.nsi 又抄一份，
而 OTA 的比较函数把后缀一律当空气（注释里还留着历史证据：`0.4.0-v1`、`0.5.0` vs `0.5.1`）。

结果是三类事故，都真实发生过：

| 事故 | 表象 | 根因 |
| --- | --- | --- |
| 双源漂移 | exe 报 0.6.2、日志和「关于」写 0.6.3 | CMake 与 main.cpp 各写一份，靠人记着同步 |
| 三源漂移 | 装出来的是 0.5.1、云端按 0.5.0 判 OTA | installer.nsi 抄了第三份 |
| 后缀不可比 | 带后缀的版本和正式版判成"相等" | 比较函数逐段取数字、忽略后缀 |

所以这次改的不只是"叫法"，顺带把**真源收敛**和**比较语义**一起定死。

## 1. 格式（三种形态）

```
X.Y.Z            正式版（stable）
X.Y.Z-rc.N       候选版 / 公测（N 从 1 起）
X.Y.Z-alpha.N    内测版（N 从 1 起，比 rc 更早的一档）
```

例：`0.6.22`（已发布）→ `0.6.23-alpha.1`（内测，先给校内几台）→ `0.6.23-alpha.2`
→ `0.6.23-rc.1`（候选，公测）→ `0.6.23-rc.2` → `0.6.23`（转正）

⚠️ **alpha 和 rc 不共用一条号链**：内测号用完转候选时号**归 1**
（`0.6.23-alpha.5` 的下一个是 `0.6.23-rc.1`，不是 `0.6.23-alpha.6`），跟 dsh 的 `0.1.2-alpha.5 → 0.1.2-rc.1` 一致。

**X / Y / Z 位次语义**

| 位 | 触发动作 | 例 |
| --- | --- | --- |
| X 主版本 | 不兼容的改动、要重装/迁移的动作 | `1.0.0` |
| Y 次版本 | 新功能、新能力（**含新端、新面板**） | `0.7.0` |
| Z 修订号 | 修复、打磨、内部重构（**用户感知不变**） | `0.6.23` |

`0.x` 阶段 Y 位同样算"新功能"，别因为前面是 0 就不敢加。

## 2. 阶段号规则（三条，**alpha 与 rc 各适用一套**）

1. **同核心递增**：`0.6.23-rc.1` → `0.6.23-rc.2` → …、`0.6.23-alpha.1` → `0.6.23-alpha.2` → …
   （同一个 GIT 动作反复出包就 +1）
2. **换核心归零**：核心版本一变（Z 或 Y 变了），阶段号从 `1` 重新起
3. **转正即剥离**：从预发布变正式时，版本号**不带后缀**（`0.6.23-rc.3` → `0.6.23`，号作废，不保留）

**alpha → rc 的跳变**：不做"号连号"，直接换前缀归 1（`0.6.23-alpha.5` → `0.6.23-rc.1`）。
这条不是我们发明的，是照抄 dsh 的真版本序列。

反例（一律不算合规）：`0.6.23-rc`、`0.6.23-rc.0`、`0.6.23-alpha`、`0.6.23-Beta.1`、
`0.6.23.1`（第四段不是阶段后缀）、`0.6.23-alpha.1-rc.1`（两个阶段后缀）。

## 3. 阶段 ≠ 成熟度标记（**别混为一谈**）

版本串里的 `-alpha.N` / `-rc.N` 是**阶段坐标**（谁在哪个位置、跟谁比大小），
它不是"成熟度开关"。以下几件事各有各的承载位置，**不许**再往版本号里塞：

- 云端是否**强制升级** → `ota.json` 的 `mandatory`（只有 `true` 才算强制，`null` 是未知不是强制）
- 发版说明、渠道备注 → `ota.json` 的 `notes`
- 管理端界面的"内测/公测"字样 → 由 `viewer.env` / 构建期宏给，不写进版本串

照 dsh 的 dist-tag（`latest` / `next` / `alpha`）思路：阶段是**坐标**，成熟度是**标记**，
混在一起就没法比较了（比较函数一旦要认"公测"这种字眼，升级判定立刻失真）。

一个具体反例：不要因为"这是内测版"就在版本号里写 `0.6.23-alpha.1-internal`，
也不要写 `0.6.23-internal.1`——都是不合规。

## 4. 唯一真源

| 端 | 唯一真源 | 其它位置 |
| --- | --- | --- |
| 管理端 | `Stelarith-viewer-qt/CMakeLists.txt` 的 `set(VIEWER_VERSION ...)` | `src/main.cpp` 的 `kViewerVersion`（回落值 + 构建期比对，**不手改**） |
| 被控端 | `Stelarith-control-qt/CMakeLists.txt` 的 `set(AGENT_VERSION ...)` | `src/main.cpp` 的 `kAppVersion`（回落值 + 构建期比对）、`installer.nsi`（由 CMake 生成） |
| 发布 | `Stelarith-cloud` 的 `ota.json` | `scripts/publish-release.mjs` 只负责校验与写入 |

**改版本只动 CMakeLists 那一行**，其余三处由构建期卡死：

- CMake 用正则读源码里的版本字面量，不一致 ⇒ `FATAL_ERROR`（这就是 0.6.3 那次之后补的守卫）
- `installer.nsi` 不再手写 `!define VER`，改为 `!include "build\version.nsh"`，
  那份文件由 `CMakeLists.txt` 用 `configure_file` 生成 ⇒ 源头上不可能漂移
- 源码里的 `kViewerVersion` / `kAppVersion` 是**回落值**：CMake 万一没跑起来，程序也能编；
  正常构建时构建期守卫保证它与真源一致

## 5. 显示版本 vs 二进制版本（容易踩）

版本号字符串可以带 `-rc.N`，但**烧进 exe 的版本资源分两块**：

| 用途 | 字段 | 取值 | 例 |
| --- | --- | --- | --- |
| 显示 | `FileVersion` / `ProductVersion`（StringFileInfo 里的字符串） | **完整串，可带后缀** | `"0.6.23-rc.1"` |
| 二进制 | `FILEVERSION` / `PRODUCTVERSION` | **必须四段纯数字** | `0,6,23,0` |

⚠️ Windows 的版本资源二进制字段不接受 `-rc.1` / `-alpha.1`。推导规则固定：**核心三段 + 第 4 段永远是 `0`**。
（改之前的实现是 `string(REPLACE "." ";")` 直接拆整体版本串——`0.6.23-rc.1` 会拆出 `"22-rc"` 这种段。）

## 6. 比较语义（semver 子集）

```
① 先比核心三段 X.Y.Z 的数字（缺段补 0）；
② 核心打平后先比阶段排名：alpha(0) < rc(1) < 正式(2)；
③ 同阶段才比号（rc.2 > rc.1、alpha.3 > alpha.1）；
④ 跨阶段只比阶段 —— 数字不参与（alpha.5 < rc.1）；
⑤ 非本标准的老后缀（-v1、-beta）当空气，跟同核心的正式版判相等。
```

| 例子 | 判定 |
| --- | --- |
| `0.6.23-rc.1` < `0.6.23` | ✓ 候选排在正式版前面 |
| `0.6.23-alpha.1` < `0.6.23-rc.1` | ✓ 内测早于候选（**跨阶段不比号**） |
| `0.6.23-alpha.5` < `0.6.23-rc.1` | ✓ 同上——alpha.5 里的 5 不参与比较 |
| `0.6.23-alpha.9` < `0.6.23` | ✓ 内测永远排在同核心正式版前面 |
| `0.6.23-rc.2` > `0.6.23-rc.1` | ✓ 同核心同阶段按号递增 |
| `0.6.23-rc.10` > `0.6.23-rc.9` | ✓ 按数字比，不是字符串（`0.10.0 > 0.9.9` 同理） |
| `0.6.23-rc.1` > `0.6.22` | ✓ 核心大的就是大，哪怕它是候选 |
| `0.6.23` < `0.6.24-alpha.1` | ✓ 同理，不因为内测就降权 |
| `0.6.24-alpha.1` > `0.6.23-rc.9` | ✓ 核心优先，阶段只在核心打平后比 |
| `0.4.0-v1` vs `0.4.0` | ✓ 老后缀当空气 ⇒ 相等（历史兼容行为，保持） |

两处实现，语义必须**逐条对齐**：

- 参考实现：`scripts/version-compare.mjs` 的 `cmpVersion()`（`STAGE_RANK = { '': 2, rc: 1, alpha: 0 }`）
- 被控端 OTA：`Stelarith-control-qt/src/main.cpp` 的 `compareVersion()`

⚠️ **这两份是各写一遍实现，靠断言对齐，不是共用代码。** 断言在 `scripts/test-version-naming.mjs`
（改比较逻辑前先跑它）；C++ 侧还能用 `_probe_cpp.py` 把 `compareVersion()` 原样抽出来编译跑同一组断言。
**只跑 JS 那条断言是验不出 C++ 的 bug 的**（2026-10-07 晚间就栽过一次，见 §9 末尾那条记录）。

### 这轮踩到的坑（写代码前先看）

1. **CMake 的正则引擎不吃非捕获组 `(?:...)`** —— 写进 `if(... MATCHES "...")` 直接
   `RegularExpression::compile(): ?+* follows nothing` 把配置期炸了。
   解法：抽取时写宽松的 `([^"]+)`，**格式校验另起一行**用 `string MATCHES` 做（`(...)`, `?`, `\\.` 这些普通语法都支持）。
2. **`Stelarith-control-qt/CMakeLists.txt` 的行尾是 `\r\r\n`（CR CR LF）**，不是普通 CRLF。
   Edit 工具按文本匹配会命中 0 次。改这种文件必须用脚本按 `"\r\r\n"` split → 只换行内容 → 拼回去。
3. **CMake 字符串里的字面 `\n` 会被展开成真换行**：把两条 `string(REGEX REPLACE)` 用 `...\n...`
   拼在同一行 ⇒ `Parse error. Expected a command name, got unquoted argument with text "\n"`。必须拆成两条物理行。
4. **`STAGE_RE` 只匹配阶段名本体，不含前导 `-`**：调用处已经把 `-` 剥掉了，正则里再写 `-(alpha|rc)`
   会解析不出阶段 ⇒ 比较断言全线飘（症状很像"跨阶段比较错了"，其实是解析错了）。
5. **本机 Qt 6.8.1 编不过 MSVC 14.51（VS18）**：`qbytearray.h` / `qlatin1stringview.h` 报 C2666 / C2139，
   且 Qt 还要求 `/permissive-` + `/Zc:__cplusplus`（不开就把 `__cplusplus` 报成 199711L 直接 `#error`）。
   这是**工具集版本漂移**，与版本号逻辑无关 ⇒ C++ 侧验试用最小 shim 顶掉 Qt 头文件，见 `_probe_cpp.py` / `_shim_qt/`。
6. **`stddef.h` 不在 VC 的 include 里**：MSVC 14.51 的 CRT 头文件转发到 Windows SDK 的 `Include\<ver>\ucrt`，
   INCLUDE 里少这一路就是 `fatal error C1083: 无法打开包括文件: "stddef.h"`。
7. **msvc 当链接器会往 TMP 写临时 il 文件**（本机 TMP 满 ⇒ `D8037`）⇒ 链接直接调 `link.exe`。

### 附：一条断言抓出来的真 bug（2026-10-07 晚间）

补 `-alpha` 时顺手把 C++ 的 `compareVersion()` 抽出来编了断言，**B1 / B2 / B17 三条挂了**：

```
X B1  候选 < 同核心正式版 : 期望 -1 实际 1（0.6.23-rc.1 vs 0.6.23）
X B2  正式版 > 候选       : 期望  1 实际 -1（0.6.23 vs 0.6.23-rc.1）
X B17 内测 < 同核心正式版 : 期望 -1 实际 1（0.6.23-alpha.9 vs 0.6.23）
```

根因：C++ 里"没有阶段后缀"的 rank 初值被写成了 `0`，而 `parse()` 内部又是 `-1`——两套哨兵并存。
`0` 恰好等于 `RANK_ALPHA`，于是核心打平后「正式版 < 候选版」：

```
compareVersion("0.6.23", "0.6.23-rc.1") → -1   // 本该是 +1
```

**实际后果**：rc 转正、云端发正式版时，被控端 `compareVersion(云端 latest, 本机)` 判成 `-1`
⇒ 走进"已是最新"分支 ⇒ **托盘不提示升级、自动升级不触发**。修法是把无阶段的哨兵统一成 `RANK_RELEASE(2)`。

这也说明一件事：`scripts/test-version-naming.mjs` 只验 JS，**验不出 C++ 的错**。
两处实现必须各自有断言，C++ 侧就是 `_probe_cpp.py` 那条抽离编译的路子。

### 没验到的

- **被控端整链**（`.rc` 真的烧进 exe + 安装器真编）：被 `src/oauthbind.cpp/h` 缺失卡住，只验到 configure 阶段。
- **C++ 侧 `compareVersion` 的真机行为**：抽离编译 19 条断言全过，但没在教室机上跑过一次真实升级。
- **真机装机 3 枚快捷方式 / 卸载**（沙箱 COM 限制，沿用上一轮结论）。
- **`_shim_qt/` 打桩 ≠ 真 Qt**：`QString` API 只实现了 `compareVersion` 用到的那几个方法
  （`trimmed / indexOf / mid / left / toInt / split / at / 可遍历`），接口行为与真 Qt 完全一致但实现是简化的；
  它能证明**逻辑**对，不能替代真机编译。

## 12. 发版预演抓出的第二个同类 bug（2026-10-07 16:0x）

### 又是「同一条规则抄三处，只抄了两处」

第 10 节那条 bug 的教训是"同一条语义写了两份，总有一份是错的"。
这次**又犯了一次，而且是同一类**：同一个正则抄到四处，漏了第三处。

漏的是 `Stelarith-cloud/scripts/publish-release.mjs` 的 `--version` 守门（阶段号还写着 `\d+`）：

| 实现位置 | 阶段号写法 | 认不认 `0.6.23-alpha.0` |
|---|---|---|
| `scripts/version-compare.mjs` 的 `isCandidate()` | `(alpha\|rc)\.[1-9]\d*` | ✗ 拒绝 |
| 两端 `CMakeLists.txt` 守门 | `-(alpha\|rc)\.[1-9][0-9]*` | ✗ 拒绝 |
| `control-qt/src/main.cpp` 的 `compareVersion()` | 解析阶段号要求 `n>=1` | ✗ 降级当"无阶段" |
| `publish-release.mjs` 的 `--version` 守门（**漏**） | `(alpha\|rc)\.\d+` | ✅ **放行** |

**后果链（每一环都实测过，不是推理）**：

1. 手滑发 `--version 0.6.23-alpha.0` ⇒ 脚本放行，`0.6.23-alpha.0` 被写进 `ota.json`；
2. 被控端解析阶段号要求 `n>=1` ⇒ 判成"无阶段"⇒ 当**正式版**处理；
3. 教室机：云端 `0.6.23-alpha.0` 与本机 `0.6.23` 比较结果 `0` ⇒ **判"已是最新"，不升级**；
4. 最难查的是第 4 环：等真要发正式版 `0.6.23` 时，比较结果**还是 0** ⇒ **这个版本此后永远推不下去**，
   而现场现象只是"升级点了没反应"。

`test-version-naming.mjs` 的 **F1b** 断言就是钉死这一处的（断言源码里不再含 `-(?:alpha|rc)\.\d+`）。
**教训**：改命名规则时，四处（JS 唯一实现 / 两端 CMake / C++ / 发布脚本）必须同时改，
改完跑 `scripts/preview-ota-publish.py` —— 光靠 `test-version-naming.mjs` 只查文本，不查行为。
