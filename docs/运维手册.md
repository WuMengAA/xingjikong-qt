# 星集控 · 运维手册

> 版本 v0.6.x（2026-10-07 更新）。覆盖：日常巡检、日志位置、看门狗、备份、故障排查、升级回滚、
> 批量功能（考试模式/语音/屏幕广播/班级监控/通知确认）的运维要点与错误码体系。

## 1. 系统组成与关键进程

| 进程/任务 | 位置 | 作用 |
|---|---|---|
| `StelarithCloud`（计划任务） | 云端主机 | 开机启动云端 |
| `StelarithCloudWatchdog`（计划任务） | 云端主机 | 每 5 分钟自愈 |
| `node.exe`（云端进程） | 云端主机 | :8788 |
| `StelarithAgentQt`（计划任务） | 教室机 | 登录时启动被控端 |
| `stelarith-agent-qt.exe` | 教室机 | 托盘常驻 |
| `viewer-qt.exe` | 老师机 | 管理端 |

## 2. 日志位置

| 组件 | 路径 | 内容 |
|---|---|---|
| 云端主日志 | `Stelarith-cloud\cloud-service.log` | 启动、鉴权失败、错误 |
| 云端事件流水 | `Stelarith-cloud\events.log` | 设备上下线、指令、回执（**排障首选**） |
| 看门狗 | `Stelarith-cloud\cloud-watchdog.log` | 每次拉起记录 |
| 被控端 | `%LOCALAPPDATA%\xingjikong\agent-qt.log` | 连接、指令、回执、RTC、内存回收 |
| 管理端 | 工作目录 `viewer-run.log` | 连接、鉴权、设备表、RTC 信令 |

> ⚠️ `cloud-service.log` / `events.log` **正被云端进程占用**，可读可追加，但**不要删除或移动**（会导致新日志写丢失）。

### 2.1 云端日志轮转（必要）

云端日志无内置轮转，长期运行会增大。建议任务计划每日归档：

```bat
rem 每日 03:00：把超过 50MB 的日志改名归档，空出当前文件
for %%F in (cloud-service.log events.log cloud-watchdog.log) do (
  if exist "%%F" (
    for %%A in ("%%F") do if %%~zA GTR 52428800 move /y "%%F" "%%~nF-%date:~0,4%%date:~5,2%%date:~8,2%.log" >nul
  )
)
```
> 改名后需重启云端进程才会写新文件；或在计划任务里先 `taskkill` 再改名再拉起。

## 3. 日常巡检（建议每日一次）

1. `netstat -ano | findstr :8788` → 有 LISTENING。
2. `curl -H "Authorization: Bearer <CLOUD_VIEWER_TOKEN>" https://<域名>/api/devices` → `count` 与应在线教室机数一致。
3. 查 `events.log` 末尾 50 行，是否有异常 `error`（如大量「HTTP 管理面鉴权失败」= 有人扫端口）。
4. 抽查一台教室机：托盘图标在、`agent-qt.log` 有近期心跳。
5. 磁盘剩余：云端 ≥ 3GB。
6. `recordings/` 目录大小（班级监控上传的 mp4）：`du -sh recordings`（Windows 用
   PowerShell `Get-ChildItem recordings -Recurse | Measure-Object Length -Sum`）。
   录制无自动清理（第一版），增长过快时手动归档/清理旧片段。

## 4. 看门狗机制

- 触发：`StelarithCloudWatchdog` 每 5 分钟跑 `cloud-watchdog.cmd`。
- 逻辑：`netstat` 查 8788 是否 LISTENING；不在则写 `cloud-watchdog.log` 并 `start` 拉起云端。
- 日志样貌：`[2026-10-05 04:02:43] watchdog: 8788 not listening, restarting cloud`。
- 验证：`taskkill /f /im node.exe`（**确认那台就是云端进程**）后 5 分钟内应自愈。

> 注意：若云端以「计划任务 + 指定 PID」方式运行，`taskkill /im node.exe` 会杀掉**所有** node 进程，请确认主机上没有别的 node 业务。

## 5. 备份

| 对象 | 频率 | 方法 |
|---|---|---|
| 云端 `.env` | 改动即备份 | 复制到离线位置（含密钥，注意保密） |
| 云端数据（db + 事件流水） | 每日 | **用 `scripts/backup.mjs`**（2026-10-07 起） |
| `ota.json` | 每次发布 | 随发布记录归档 |
| 安装包 `dist\stelarith-agent-setup.exe` | 每版本 | 连同 sha256 一起归档 |
| 被控端 `agent.env` | 装机时 | 记录本（含令牌，保密） |

### 5.1 云端数据备份脚本（推荐）

```bash
# 在 cloud-ws 目录：
node scripts/backup.mjs              # 备份 instruction-queue.db + events.log* 到 backups/<UTC时间戳>/
node scripts/backup.mjs --keep 14    # 保留最近 14 份，更旧的自动清理（默认 30）
node scripts/backup.mjs --list       # 只列出已有备份
```

- 备份内容：`instruction-queue.db`（已下发未回执的指令队列）+ `events.log` 及轮转归档。
- **恢复**（手工）：停云端 → 把 `backups/<时间>/instruction-queue.db` 覆盖回 cloud-ws 根目录
  → `events.log*` 同理 → 重启云端。
- 第一版边界：本机目录备份（未加密/未推对象存储）。异地备份建议把 `backups/` 目录
  同步到离线位置。

> ⚠️ 新增：云端多了 `recordings/` 目录（班级监控上传的录制 mp4）。如需保留录制，
> 备份时一并复制；磁盘占用监控要算上它（见 §3 巡检第 6 条）。

## 5.5 错误码体系（2026-10-07 起）

所有错误响应统一带 `ecode`（数字码）+ `code`（语义码）+ `message`（人话）。
格式 `[模块2位][类型1位][编号3位]`：模块 AU认证/DV设备/CM指令/NT网络/PV权限/SY系统；
类型 1客户端/2服务端/3网络/4业务。

| 码 | 含义 | 排查 |
|---|---|---|
| AU1001 | 账号或密码错误 | 站点侧登录问题 |
| AU1002 | Token 过期 | 重新登录 |
| AU1003 | Token 无效 | 令牌被改/票据过期；查 `.env` 令牌一致性 |
| DV3001 | 设备离线/不存在 | 设备未连或 uid 打错（§6.2） |
| DV3002 | 心跳超时/无响应 | 设备假死，杀进程重启 agent |
| CM1001/1002 | 指令类型/参数错误 | 管理端版本过旧或参数缺 |
| CM2001/2002 | 执行失败/超时 | 查被控端日志对应动作 |
| CM4001/PV400x | 无权限 | 角色/授权班级问题 |
| NT300x | 网络错误 | 连接层（§6.2） |

> 语义码兼容：未编号的旧码（BAD_TOKEN 等）保留原样，老客户端不受影响。

## 5.6 批量功能运维要点（考试模式 / 语音 / 屏幕广播 / 班级监控 / 通知确认）

| 功能 | 动作（被控端执行） | 运维要点 |
|---|---|---|
| 通知 + 确认快捷回复 | `notify`（`flags.confirm` + `flags.replies`） | 学生点击后回执 `result=confirmed` + `data.reply`；管理端回执流水可见。若回执一直 `failed`，查被控端是否旧版本（无确认功能） |
| 定时任务 | `schedule_shutdown` / `schedule_reboot` | `at` 需 ISO 8601 字符串；查 `list_schedules` 对账 |
| 考试模式 | `exam_mode` / `exam_mode_stop` | 参数 `minutes`（0=不自动结束）+ `whitelist`（进程名逗号分隔）。**只拦输入+白名单进程**，防君子不防小人。教室机被"锁死"时管理端点「结束考试」恢复 |
| 语音对讲 | 会话 `audio.start/stop` + PCM 二进制帧 | 老师→全班单向；默认静音；停止后帧被云端拒绝（安全边界） |
| 屏幕广播 | `broadcast.start/stop` + JPEG 帧 | 3fps；停止后帧被拒。带宽：60 台 × ~300kbps ≈ 18Mbps 可承受 |
| 班级监控 | `camera_record_start/stop` → 自动上传 | 录制走 ffmpeg DirectShow（教室机需摄像头）；上传到 `/api/recordings/upload`（设备令牌）；管理端 `/api/recordings` 列表 |

**管理端二进制帧路由**：云端按当前活跃会话转发——语音播着→转语音帧，广播播着→
转广播帧，都无→丢弃并记 warn。若管理端推帧无效果，先查 `events.log` 是否有
「无活跃语音/广播会话」warn。

## 6. 故障排查（症状 → 定位 → 处理）

### 6.1 云端起不来
- 看 `cloud-service.log`：
  - `FAIL 端口占用或启动失败` → 端口被占；`netstat -ano | findstr :8788` 找占用者。
  - `ExperimentalWarning: SQLite` → 正常提示，非错误。
  - `Cannot find module 'node:sqlite'` → **Node 版本过低**，需 ≥ 24。
- 检查 `.env` 是否被 `node --env-file` 读到（路径、编码）。

### 6.2 教室机连不上云端
按此顺序查（**先看转发层，再怀疑端点**）：
1. 教室机 `agent-qt.log` 是否有 `已发送 register v1`；有则说明发出了。
2. 云端 `events.log` 是否有对应 uid 的注册记录；无则**报文没到云端**（网络/反代/令牌）。
3. 若云端回了 `错误 error code=AUTH_REQUIRED` → 令牌不一致。
4. `wss://` 场景：反代是否透传了 `Upgrade` 头（缺了会握手失败）。

### 6.3 有设备在线但看不到画面
1. 管理端 `viewer-run.log` 搜 `RTC offer 带的 uid` —— 若出现「与本地当前 uid 不一致，以 offer 为准修正」，属**已知自愈路径**，正常。
2. 被控端日志应有 `state:streaming`；若无，检查教室机是否装了**无 WebEngine 的旧包**（旧包无法 RTC）。
3. 断线恢复后画面不回：等 20 秒（被控端有 20 秒离线回收 + 重连），看云端是否被看门狗拉起。

### 6.4 指令下发返回 409
- 表示设备**不在线**（云端绝不把离线当成功）。确认设备在线后重发。
- 离线期间下发的指令**不进补发队列**（有意：离线不能当"收下了"）。

### 6.5 管理面 HTTP 大量 401
- `events.log` 出现 `HTTP 管理面鉴权失败` → 有人无令牌访问或扫端口。确认反代是否限制了来源；必要时加 IP 白名单。

### 6.6 通知"需确认"但学生点了没回执
1. 查被控端版本：旧版本（< v0.6.5 之后含确认功能的版本）不显示确认按钮——重打包升级。
2. 查 `events.log` 是否有 `设备真实执行回执 action=notify result=confirmed`；
   无则学生没点或没收到通知。
3. 查管理端回执流水是否显示 `confirmed` + reply。

### 6.6 被控端内存偏高
- 有人看（RTC 推流）时含 Chromium 属正常（数百 MB）。
- 无人看 20 秒后应自动回收：日志 `推流已停：与云端断开 20 秒…先收采集页` + `采集页已回收（Chromium 渲染进程随之退出）`。

## 7. 升级与回滚

### 7.1 云端升级
1. 备份 `.env` 与 `instruction-queue.db`。
2. 覆盖 `src/` 为新版本；`npm ci --omit=dev`（依赖变化时）。
3. 重启：停任务 → 起任务，或直接重跑 `run-cloud.cmd`。
4. 验证 `/api/devices`。

### 7.2 被控端升级
- **小规模**：远程下发 `self_update` 指令（见《OTA 发布与升级说明》）。
- **回滚**：重装旧版安装包（旧包与 sha256 需留存归档）；
  或临时设 `STE_QT_OTA_DISABLE=1` 冻结该机自更新。

### 7.3 管理端升级
- 覆盖 `deploy\` 新版本，保留原 `viewer.env`，重启 `viewer-qt.exe`。

## 8. 红线（操作纪律）

- **不要**把被控端做成 Windows 服务（Session 0 抓不到桌面）。
- **不要**手工编辑生产 `agent.env` 之外的安装器默认值（默认值仅供调试）。
- **不要**删除/移动正在被占用的 `cloud-service.log` / `events.log`。
- **不要**在未换生产令牌的情况下把 `CLOUD_WS_HOST` 设成 `0.0.0.0` 暴露公网。
- 改令牌务必**成对**（见《配置与凭据清单》第 6 节）。
