# OTA 不生效 · 加减归档（2026-10-17）

> 用户反馈：「OTA 不生效」。本档记录取证结论、三层根因、改法、验证证据、以及**仍未闭环的一件事**（stable 清单发布）——那一步需要人裁。

---

## 一、结论先行

「OTA 不生效」不是单一 bug，是**三层叠加**，缺一层都会表现为"云端发了版、设备没动静"：

| # | 层 | 病灶 | 状态 |
|---|---|---|---|
| 1 | 端侧：**不查** | 云端把最新版本只随 `registered` 回执下发一次，端侧 `applyUpdateInfo()` 也只在那一处被调用。教室机长连不重启 ⇒ 永远停在注册那一刻看到的版本 | ✅ 已修（`95a0d43`） |
| 2 | 发布：**没包** | `ota.json`（stable）自 2026-10-16 23:17 起停在 **0.6.37**；0.6.38~0.6.43 全发在 `ota-gray.json`。非灰度设备查 stable ⇒ `hasUpdate:false`，**再勤快也拿不到** | ⛔ **待裁决**（见第四节） |
| 3 | 端侧：**不自装** | `maybeAutoUpdate()` 第一句 `if (!g_updateMandatory) return;` ⇒ `mandatory:false` 时只弹托盘/岛提示。教室机无人值守，没人点「立即更新」⇒ 版本永远卡住 | ✅ 已修（`603abe7`） |

## 三、改法

### 3.1 第 1 层：端侧周期复查（`95a0d43`）

新增 `otaSelfCheck()`：

- 按 HTTP 轮询 `GET {ws→http 基址}/api/public/ota?product=agent&channel=<渠道>&current=<本机版本>`；
- 把回包**翻译成与注册回执同形**的 payload 交给 `applyUpdateInfo()` —— 版本比较/托盘/岛提示/强制升级判定**全部复用同一条路径**；
  ⚠️ 刻意不在这里另写一套版本比较：`ota.js` 注释已点明"两端各写一遍比较"正是 0.6.23 之前"正式版被判成已是最新"那个静默 bug 的来源。
- ws→http 推导与 `uploadRecordingAsync` 同款（`wss://`→`https://`、截断 `/ws/`）。

新增 `otaStartPeriodicCheck()`：

| 参数 | 默认 | 钳位 | 说明 |
|---|---|---|---|
| `STE_QT_OTA_CHECK_SEC` | 1800 | [60, 86400] | 复查周期 |
| `STE_QT_OTA_CHECK_FIRST_SEC` | 180 | ≥5 | 首次延迟 |
| `STE_QT_OTA_DISABLE` | — | — | =1 与自更新共用同一把应急刹车 |

- 同一版本只**首次**弹岛/托盘（`g_otaPromptedVer` 去重）——周期复查每 30 分钟重来一次，每次都弹就是骚扰。
- ⚠️ 启动调用**放在托盘分支之外**：离屏实测发现放里面时"托盘不可用"整段跳过，Session0/服务化环境就永远不会复查。

### 3.2 第 3 层：非强制更新的安全窗口自动装（`603abe7`）

`maybeAutoUpdate()` 第①层从"只有强制"改为"强制 **或** 安全窗口"：

```
非强制 → ① 考试模式？→ 暂缓（考试优先级最高，STE_QT_OTA_AUTO_FORCE 也不能绕）
        ② 桌面空闲 ≥ N 分钟？→ 否则暂缓，下一个周期再判
        ③ 都满足 → 自动下载安装
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `STE_QT_OTA_AUTO_IDLE_MIN` | 10（分钟） | 空闲门槛；**0 = 关掉非强制自动装** |
| `STE_QT_OTA_AUTO_DELAY_SEC` | 30 | 发现新版本后延迟多久复判（刚弹完提示就重启观感差） |
| `STE_QT_OTA_AUTO_FORCE` | — | =1 跳过空闲判据（维护窗口/探针专用，每次跳过打 warning；考试保护不受影响） |

空闲判据用 `GetLastInputInfo`（系统级最后输入，不依赖本进程焦点）：

```cpp
static qint64 desktopIdleMs()
{
    LASTINPUTINFO li{};
    li.cbSize = sizeof(LASTINPUTINFO);
    if (!GetLastInputInfo(&li)) return 0;   // 取不到 = 当作"正在使用"，宁可不升
    const DWORD now = GetTickCount();
    return qint64(DWORD(now - li.dwTime));  // 32 位无符号差，跨 49 天回绕正确
}
```

⚠️ `dwTime` 是 32 位 `GetTickCount` 值 —— **不能**拿 `GetTickCount64()` 去减（跨回绕会算出天文数字，表现为"永远不空闲"）。

同时把 ②~⑦ 的日志去掉"强制"字样（两条路共用），开头日志区分「云端要求强制升级」/「空闲窗口自动升级」。

### 3.3 顺带修：Banner 的 binding loop（真机每秒刷屏）

`IslandBannerFace.qml` 的 `width` 绑定里读了 `bTitle.implicitWidth` —— 带 `elide` 的 Text，其 `implicitWidth` 随 `width` 变化 ⇒ `width ↔ implicitWidth` 互相触发：

```
qml/island/IslandBannerFace.qml:48:9: QML Text: Binding loop detected for property "width"
```

改法：用 `TextMetrics.advanceWidth` 量自然宽（只由 text/font 决定，与 width 无关，天然不成环）。

> 这里走了两轮弯路，写进坑：第一次以为是 `bTitle.x`（由锚点驱动）与锚点互相触发 —— 改成常量占位后**仍然刷屏**；真因是 `implicitWidth`。判据：只要 Text 带 `elide`，它的 implicitWidth 就不是"自然宽"。

## 四、⛔ 仍未闭环：stable 清单（需要人裁）

**这是"OTA 不生效"最硬的一条，而且不是代码问题，是发布操作。**

现状：非灰度设备查 stable 永远得到 0.6.37 → `hasUpdate:false`。端侧再勤快复查也没用。

要让全体设备真正升上去，必须把 stable 推到当前版本。两种走法：

**A. 直接发 0.6.43 到 stable**
```bash
cd Stelarith-cloud-ws
node scripts/publish-release.mjs publish --product agent --version 0.6.43 \
     --file assets/pkg/stelarith-agent-setup-0.6.43.exe
```
- 优点：包已在，命令一条，立刻生效。
- 风险：**全体教室机会在各自空闲窗口自动升级**（新逻辑生效后）。这是大面积变更，必须人确认。
- 另注：0.6.43 是并行线打的「STE_LDC_LOG Debug 日志版」（`2834773`）——若该开关是运行期 env（默认关），则包本身安全；若是编译期，需确认不刷日志。

**B. 先 bump 到 0.6.44 重打包再发**
- 更干净（版本号唯一对应"含 OTA 修复 + 形态多样化 + banner 修复"这个二进制），但要占 C 盘空间（现剩 2.3G，打包+备份约 100MB+），且与并行线抢版本号。

**不做**的后果：代码修好了，但只要 stable 不出包，教室机依旧"已是最新"。

## 七、未验证 / 已知限制

1. **stable 未发布**（第四节）—— 端侧修好但没包，等于没生效。
2. **空闲判据在真机的"终于命中"没观测到**：本机远程会话持续有输入（idle 恒 ~0s），无法在本机构造 10 分钟空闲；B3 用 `FORCE=1` 绕过后验证的是"命中后的整链"，不是"空闲自然命中"。
3. **强制升级路径未回归**：`mandatory:true` 的自动装没重跑（改动只碰了非强制分支 + 日志文案，理论无影响，但没实测）。
4. **考试模式暂缓分支未实测**：代码路径在（`ExamMode::inst().active()`），探针没构造考试态。
5. `0.6.43` 包的 Debug 日志开关（`STE_LDC_LOG`）是否为运行期默认关 —— 未核实，影响"能不能直接发 stable"。

## 八、本批新坑（已进 MEMORY）

1. **`LNK1104 无法打开 stelarith-agent-qt.exe`** = 隔离测试实例还在跑、占着构建产物。判据：`Get-CimInstance Win32_Process -Filter "Name='stelarith-agent-qt.exe'"` 看 `ExecutablePath` 是不是 `build\`（那是我的探针，可杀）；生产在 `C:\Program Files\`（不能杀）。
2. **`GetLastInputInfo.dwTime` 是 32 位 tick** ⇒ 只能与 `GetTickCount()` 做 32 位无符号差；拿 `GetTickCount64()` 减会得到天文数字（表现为"永远不空闲"，静默）。
3. **隔离实例日志是 UTF-8，用 `iconv -f GBK` 转会把中文弄成乱码**；正确做法是 Python `open(..., 'rb').read().decode('utf-8','replace')` 再按关键词筛。
4. **写死的 30 秒延迟让探针很难取证** ⇒ 凡是"到点才动作"的新逻辑，延迟一律做成环境变量可调（本轮 `STE_QT_OTA_AUTO_DELAY_SEC`）。
