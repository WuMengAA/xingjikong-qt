## 二、真正的缺口（只有三项）

1. **多学校实体与隔离** —— 全网零实现（无 `school` 概念，`relayToSubscribers` 按 uid 订阅、无跨校边界）。
2. **作用域树（scope）** —— 零实现。现在只有「设备 uid」和「classCode」，没有可继承的层级。
3. **权限统一** —— 站点 `permissions.ts` 是角色真源，但**云端完全不校验权限**（任何持票者能做任何动作）⇒ 原稿「所有指令下发前调 `can()`」在云端**没有实现基础**。

---

## 三、必须在多校之前处理的既有隐患（否则就是「烂地基加盖」）

1. **云端业务数据是内存态**：`knownDevices` / `classIndex` **无持久化**（只有 events 日志写盘）。云端一重启，设备表与班级索引清零，靠设备逐台重连重建。→ 多校的 `school` 归属若也放内存，**重启即丢**。**多校前应先把 registry 落盘**（独立价值，且与多校解耦）。
2. **权限真源分裂**：站点 `permissions.ts` ↔ 云端「静态令牌/HMAC 票据」。云端不看权限 ⇒ **越权面**在云端，不在站点。
3. **班级 id 口径不一致**（存量问题）：站点 `classId` 形如 `class_xlzx_2028_08`（18 位，含毕业年），而云端班级码约束 `^[A-Za-z0-9_-]{6,16}$`。多校会放大此问题（每校一套编码规则）。
4. **WebSocket 广播无 scope 过滤**（原稿「坑 1」已被现状证实）：`relayToSubscribers(uid, type, payload)` 只按设备订阅关系推，**没有跨校/跨班隔离概念**。

## 四、scope 契约草案（核心交付）

### 4.1 票据载荷扩展（最小侵入、向后兼容）

**现格式（保持 5 段不变）**：`v1.<expMs>.<uidB64>.<nonce>.<sig>`，其中 `uidB64 = base64url(utf8(uid))`。

**扩展方式**：**把第 3 段从「uid 字符串」换成「claims JSON」**，段数与签名覆盖范围**都不变**：

```jsonc
// b64u(JSON.stringify(claims)) —— 仍是同一段
{
  "uid":        "WuMengAA",
  "schoolId":   "sch_xlzx",          // 缺省/null = 平台级（超管）
  "roles":      ["teacher"],
  "permissions":["device.view","device.lock","msg.send"],
  "scopes":     [
    {"type":"class","id":"class_xlzx_2028_08"},
    {"type":"grade","id":"grade_xlzx_2028"}
  ]
}
```

**云端 `verifyViewerTicket` 的解析改动（三行级）**：
```js
let claims = null, uid = '';
const raw = Buffer.from(uidB64, 'base64url').toString('utf8');
try { claims = JSON.parse(raw); } catch { /* 旧票：纯 uid */ }
uid = claims?.uid ?? raw;
```
- **旧票兼容**：解析失败当纯 `uid` 字符串，行为与今天完全一致。
- **签名强度不降**：HMAC 仍覆盖整段，claims 被改 ⇒ 验签失败。

**站点侧签发**：`mintViewerTicket(uid)` 增加一种重载 `mintViewerTicket(claims)`（传对象则序列化进第 3 段）。**格式只有一处定义**（`ticket.js`），两边不会写歪。

### 4.2 scope 树语义

- 三种 scope：`school` / `grade` / `class`；**授权父节点 = 覆盖其下所有子节点**。
- **判断**：把 `target` 归约成 `(schoolId, gradeId, classId)`，再看用户的某个 scope 是否命中。
- **目标归属**：每台设备必须能解析出这三元组。现状设备只有 `classCode` ⇒ **需要一张 class → (school, grade) 解析表**（放站点，随设备注册/绑班下发给云端；或云端持有一份）。
- **平台级**：`schoolId == null` 且 roles 含 `platform_admin` ⇒ 跳过 scope 过滤。

### 4.3 三方消费规则（唯一权限入口）

| 消费点 | 规则 |
|---|---|
| **站点**（签发方） | 登录后由 `permissions.ts` + 用户档案生成 `permissions`/`scopes`，塞进票 |
| **云端 REST**（`/api/devices` 等） | 验票 → 取 scopes → **列表按 scope 过滤**；**不接受客户端传 `schoolId`/`classId`**（防越权） |
| **云端 WS 广播** | `relayToSubscribers` 增加 scope 过滤：只推给「订阅设备落在该连接 scopes 内」者；超管另行订阅式处理（避免全量洪水） |
| **云端指令下发** | 下发前 `can(user, permission, target)` —— **当前完全缺失，必须新增** |
| **Qt 管理端** | 读票内 scopes → 渲染作用域切换器 ＋ `mayDo(action)` 门控按钮显示 |

### 4.4 向后兼容（**待拍板**）

- **旧票**（纯 uid、无 claims）语义二选一：
  - (A) 当作「保持现状 = 全权」（**推荐**：生产现在就是这么跑的，收紧会立刻断现有老师机）；或
  - (B) 当作「无 scope ⇒ 无数据权限」（更安全，但**需与站点签发同时上线**，否则断线）。
- **长期静态令牌 `CLOUD_VIEWER_TOKEN`**：**保持全权**（老机器/离线机房不能断），但**记审计**（谁、何时、做了什么）。

### 4.5 不变量（建议写进代码注释的硬规矩）

1. **权限真源只有站点**；云端与 Qt **只消费、不创造**。
2. **`schoolId` 只能从票来**，绝不接受客户端参数指定。
3. 云端任何「返回设备 / 下发指令」的路径**必须过 `can()`**；WS 广播**必须过 scope 过滤**。
4. **前端隐藏 ≠ 权限**；后端校验是唯一安全边界。
