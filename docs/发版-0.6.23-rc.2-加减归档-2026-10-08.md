## 二、本轮发布所携修复（这些才是「最新构建」的实际内容）

### 管理端（`Stelarith-viewer-qt`）
| 项 | 修复 |
|---|---|
| 登录链路 | 回拨超时收口（3 分钟，之前回拨不来就永远卡「正在登录…」且再点被「上一次还没走完」挡掉）；站点 HTML 错误页**抠出人话**（以前把整屏标签贴给用户）；换令牌兼容 `access_token`；`begin()` 清回拨缓冲；`loggedIn()` 改看票时效 |
| 退出登录 | `forgetAccount()` 完整收口：停重连 + 断 WS + 清设备表/台账 + **作废本次会话的静态令牌** + 清角色门控；`refreshAccountText()` 改**无条件**发 `accountChanged`（它同时驱动菜单显示哪一组） |
| 账户面板飞出屏幕 | **真根因**：`Popup` 未挂浮层（`Overlay.overlay` 恒 null）⇒ x/y 被解释成相对顶栏那一格的偏移，菜单整个画到窗口外。修：显式 `parent` + 每次打开现算落点 |
| 切设备画面不跟随 | `setCurrentUid` **先退订上一台**（云端只 add 不替我们取消）+ 帧**按 uid 分诊**（非当前非缩略图直接丢）+ 新增 `frameUid`，QML 用 `frameReady` 门控并显示「正在接入这台机器」 |
| 离线设备台账 | 云端 `listDevices()` 只列在线、`online` 写死 true ⇒ 管理端自建台账（消失即 `online=false` + `lastSeenAgoSec`，24h 过期、上限 200）；新增 `onlineCount` |
| 小屏窗口越界 | 右栏动作区改**可滚动** `Flickable`；默认高 760→700、最小高 680→600；`main.cpp` 新增 `fitWindowToScreen()`（**先放宽最小尺寸再夹尺寸/位置**，在 load 后/首帧/700ms/托盘唤回共四处） |

## 四、明确未完成 / 未验证（不得含糊）

1. **站点自身直链仍 404**：本地 8090 服务的是**构建产物** `build/client/`（`static/` 在构建时才同步过去）。我把包放进了工程真源 `static/downloads/`，但**没有跑站点构建**（`vite build`），所以 `http://127.0.0.1:8090/downloads/stelarith-*-0.6.23-rc.2.zip` 此刻仍 404。
   ⇒ **官网线上链路不受影响**（它走云端 OTA，实测可下载）；受影响的是站点自身的 `/downloads/` 直链。
2. **没有真机端到端功能验证**：按纪律（不跑生产进程、不发云端指令）只做了发布链路验证，两端修复的实际效果未在真机复跑。
3. **rc 版本已进公开清单**：所有已装教室机的托盘「检查更新」会提示升级到 rc.2。这是版本策略问题（用户已确认走 rc.2）。
4. **被控端 OTA 文件名不带版本号**（发布脚本主动告警）：`assets/pkg/stelarith-agent-qt.exe` 每次同名覆盖，事后无法从文件名分辨是哪个版本（只能靠 ota.json 的 version/sha256）。这是**沿用线上既有形式**（0.6.22 也如此），本轮未改变。
5. **D 盘可用空间仅剩 0.19 GB**：出包过程中一度 `ENOSPC` 出包失败。为腾空间清理了 4 个出包中间目录（`viewer/dist/pkg-0.6.14`、`pkg-0.6.23-rc.1`、失败残留 `pkg-0.6.23-rc.2`、`control/dist/agent-portable-0.6.23-rc.1`，合计约 790 MB）——**均为出包脚本自己生成的临时解压目录，未删任何 zip 成品**。空间仍未真正缓解，需要处置（见下）。
