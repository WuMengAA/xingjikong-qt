# 星集控 · 定位书 v2（2026-10-05）

> 一句话定调：**面向学校管理者的集控一体化开源便捷平台**。
> 被控端（班级一体机）+ 管理端（电脑）+ 便携管理端（手机）三端一体；
> 网页只做简单功能（API 提供 + 软件无法实现/更新困难场景的特殊功能，如 OTA 资源）。
> 预留多学校、多班级。参考成熟形态：CIMS（很成熟，是努力方向）。

---

## 一 一句话

> **星集控 = 给学校管理者的一体化集控平台。**
> 老师（管理端）点得到、看得见；教室机（被控端）默默干活；手机（便携端）随时能管。
> 网页不是主战场，是 API 出口 + 轻量兜底。

---

## 二 四块（软件 + 网页）

| 端 | 形态 | 职责 | 部署 |
| --- | --- | --- | --- |
| **被控端** | Qt（班级一体机） | 锁屏/关机/截图/通知/远控/课表展示… | 一体机，开机自启 |
| **管理端** | Qt（电脑，**已存在**，自 viewer-qt 演进） | 设备控制/通知/课表/班级管理（班主任一个班 / 学校管理员多班） | 班主任电脑、管理员电脑 |
| **便携管理端** | 手机（**电脑上 Qt 类移植**） | 精简控制：看状态/应急锁屏/通知/看课表 | 手机 |
| **网页** | 站点 | **简单功能 + API 提供 + OTA 资源**；软件实现不了或更新困难场景的兜底 | 站点 8090 |

**自更新**：被控端 / 管理端 / 便携端都要能自更新（OTA 协议已定，见下）。

---

## 三 数据模型：多学校 × 多班级（预留，必须考虑周全）

```
学校 ─┬─ 班级 ─┬─ 设备（被控端，归班）
      │        ├─ 课表（按班级）
      │        └─ 时间表/作息（全校共用）
      ├─ 角色：老师 / 班主任 / 电教委员（可调）
      └─ 用户：归属学校 → 绑定班级
```

- **学校维度必须进数据模型**：`stelarith_classes`（+school_id）、`user_class_bindings`（+school_id）、`device_bindings`（+school_id）——现在没有，预留要从建表就考虑周全。
- **课表按班级**；**时间表（作息）全校共用**。
- **角色可调**：老师 / 班主任 / 电教委员 为内置默认，权限矩阵可配置扩展。

---

## 四 角色（默认内置，可调）

| 角色 | 范围 | 权限 | 端 |
| --- | --- | --- | --- |
| **班主任** | 一个学校的一个班 | 管本班设备/通知/课表 | 管理端 |
| **学校管理员** | 一个学校的多个班 | 全校管理 | 管理端 |
| **电教委员** | 班级内 | 班级内务（点名/设备维护协助） | 管理端/便携端 |
| **老师** | 使用级 | 看/用（非管理） | 管理端/便携端 |

---

## 五 已定决策（2026-10-05 拍板）

1. **多学校**：必须考虑周全（数据模型预留，见第三节）。
2. **角色**：可调（默认三类，权限矩阵可扩展）。
3. **管理端**：存在 Qt 软件（viewer-qt 演进而来）。
4. **便携端（手机）**：电脑上 Qt 类移植（同一代码基座）。
5. **自更新**：协议已定（OTA 见云端/被控端对接规范）。
6. **课表按班级，时间表（作息）全校共用**。
7. **开源**：云端 / 被控端 / 管理端 **MIT**。

---

## 六 与 CIMS 的关系

CIMS 是很成熟的参考形态——**功能完备度、角色分层、课表/设备/通知体系都是努力方向**。
星集控以 CIMS 为对标，但**底座自研**（CIMS 退伍路径不变）：自研基座逐步承接 CIMS 的所有职责，最终停 CIMS。
