## 1 起点判断是错的（先记这笔）

我此前的主张：「`/api/classes` 只认静态令牌，得在 `viewer.env` 配 `STE_VIEWER_TOKEN`」。

**实测推翻**：

| 项 | 结果 |
|---|---|
| 云端鉴权（index.js `isViewerApi`） | 2026-10-15 已改成**先静态令牌、后登录票据**都认 |
| Python 直连 `GET /api/classes`（带 `CLOUD_VIEWER_TOKEN`） | **HTTP 200** |
| `class-dir.db` 的 `classes` 表 | **0 行** |

真因：**系统里从来没建过班**。viewer 侧 `viewerbackend.cpp:2104` 那句「票据不认」是过期注释，
代码行为本身是对的（静态优先、票据兜底）。配 `STE_VIEWER_TOKEN` 不是必需项。

```qml

// 对：本工程是 QAbstractItemModel 子类（#460 typed model）
```

教训固化：**新写的 QML 委托，必须假设"模型里有一条真数据"来写**，不能按空态写。

## 5 没修 / 没验的部分（如实列）

1. **缩略图仍显示「暂无画面」——已定位**
   `ThumbnailReporter::setReadyCheck` 要求 `!g_classCode.isEmpty()`；而云端 `bind-class`
   **只改服务端索引，不向已在线被控端下发 classCode** ⇒ 被控端不自知被绑班 ⇒ 闸门不开。
   要让画面出来，二选一：① 被控端重连（重启 agent）；② 云端补一条 `class-bound` 下发。
   （按取证避让铁律，未重启生产被控端验证。）

2. **`/api/classes` 在 Qt 里间歇 HTTP 0**
   日志反复「拉班级列表失败 HTTP 0」→「班级列表恢复正常」。同一 URL Python 稳 200 ⇒
   Qt 侧 TLS/吊销检查问题（与 GitHub 需 `--ssl-no-revoke` 同根因，也解释了「拉动作排行失败 HTTP 0」）。
   15 秒轮询会自愈。**未修**：改 SSL 校验会降低安全性，需你裁决。

3. **鼠标点击验证不可靠**
   `GetWindowRect`(1195×737) 与 PrintWindow 位图(1792×1106) 缩放不一致，按「原点 + 截图/1.5」
   换算出来的点会命中**别的项**（点班级行实际点中了「系统设置」）。
   本轮改用「向构建树注入 Timer，调用同一条 `onClassPicked` 路径」验证 —— 验证的是
   点击处理器以下的链路，**鼠标坐标本身没验**。

4. **竖屏仍未验**：本机 `minimumWidth: 940` + 屏幕可用高 977，桌面端凑不出 `width < height`。
