## 二、重新出包（只有换代码/升级时才做）

### 教室机（agent）→ NSIS 安装器

```bat
cd D:\Stelarith\Stelarith-control-qt
"C:\Program Files (x86)\NSIS\makensis.exe" installer.nsi
```
产物：`dist\stelarith-agent-setup.exe`（文件名固定不带版本号）。
发出去之前改版本号：`installer.nsi` 里的 `!define VER "0.5.x"`（三处同步：NSIS VER /
被控端 `app_version` / 面板 OTA）。然后：
```bat
copy /y dist\stelarith-agent-setup.exe D:\Stelarith\Stelarith-cloud-ws\assets\pkg\stelarith-agent-setup-0.5.x.exe
```
> NSIS 用 `File /r deploy\*` 打包 —— deploy 目录补了什么（比如新的 Qt DLL），
> 直接重跑 makensis 就会带进去，installer.nsi 本身不用动。

### 管理端（viewer）→ 绿色版 zip

```bat
cd D:\Stelarith\Stelarith-viewer-qt\deploy
"C:\Program Files\7-Zip\7z.exe" a -tzip -mx=1 -y ..\dist\stelarith-viewer-portable-0.5.x.zip .
copy /y ..\dist\stelarith-viewer-portable-0.5.x.zip D:\Stelarith\Stelarith-cloud-ws\assets\pkg\
```
> 绿色版 = 整个 deploy 目录原样打包，解压即用，无注册表。**deploy 目录本身**就是
> windeployqt 补出来的（见各工程 build 脚本），换 Qt 版本时重新 windeployqt 再打 zip。

### 云端让新包生效

```bat
cd D:\Stelarith\Stelarith-cloud-ws
taskkill /f /im node.exe        rem 或：重启计划任务 StelarithCloud
```
云端每次请求**现扫** `assets\pkg\` 目录，重启后面板「装机」卡片与 bat 自动指向新包。
（放包 → 重启 → 面板刷新，三步缺一不可。）

## 三、为什么"找不到产物"是常态

- `assets/pkg/`、各工程的 `dist/`、`deploy/` 都是**构建产物**，git 里没有；
- 这台开发机就是发包源头；git clone 到别处只有源码，跑不了装机；
- 所以**运维规程**是：改代码 → 重打出包 → 拷进云端 `assets\pkg\` → 重启云端 → 面板出新包。
  这一条线每一步都有产物路径可查，就是本文件。
