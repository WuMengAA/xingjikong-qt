## 二、重新出包（只有换代码/升级时才做）

### 教室机（agent）→ NSIS 安装器

> ⚠️ **2026-10-07 起，出包入口只有脚本一条路**。以前这里写的是"直接
> `makensis installer.nsi`，deploy 补了什么就带什么" —— 那句话是**错的**，而且已经
> 造成过事故：`installer.nsi` 自己扫 `deploy\*.*`，但 `resources\`、`translations\`、
> `position\` 这些 **windeployqt 产出的东西在 deploy\ 里永远没有**。
> 结果网上那个 70 MB 的 `stelarith-agent-setup.exe` 装出来的被控端
> **一被订阅画面就闪退**（缺 Qt WebEngine 资源）。

```bat
cd D:\Stelarith\Stelarith-xingjikong-qt\Stelarith-control-qt
build-agent-installer.bat          rem 或 Git Bash 下： ./build-agent-installer.sh
```
产物：`dist\stelarith-agent-setup.exe`（文件名固定不带版本号）。

这个入口做的事（每一步都会自己失败，不靠人眼）：
1. 组装 payload → `dist\agent-portable-<版本>\`（**与绿色包是同一份内容**）；
2. 按 `scripts\pack-manifest.mjs` 的 `REQUIRED` 逐条预检，缺一件就停；
3. 调 `makensis`，把 payload 用 `/DPAYLOAD=` 传进去、版本号用 `/DAPPVER=` 注入
   （`installer.nsi` 里**不再**有版本号，也不要再手工编辑它）；
4. 用 `7z l -slt` **回读产出物**，再核一遍必需件与"绝不外发"清单。

> 版本号唯一真源是 `src\main.cpp` 的 `kAppVersion`，脚本自己读；出包前改那一处即可
> （仍要与云端 `ota.json` 一致）。

发到公网：
```bat
copy /y dist\stelarith-agent-setup.exe D:\Stelarith\Stelarith-cloud\assets\pkg\stelarith-agent-setup-0.6.x.exe
```
> 单独校验一个包（不改任何东西）：
> `build-agent-installer.bat --check dist\stelarith-agent-setup.exe`

### 管理端（viewer）→ 绿色版 zip

```bat
del /q D:\Stelarith\Stelarith-viewer-qt\dist\stelarith-viewer-portable-0.5.x.zip
cd D:\Stelarith\Stelarith-viewer-qt\deploy
"C:\Program Files\7-Zip\7z.exe" a -tzip -mx=1 -y ..\dist\stelarith-viewer-portable-0.5.x.zip .
copy /y ..\dist\stelarith-viewer-portable-0.5.x.zip D:\Stelarith\Stelarith-cloud\assets\pkg\
```
> ⚠️ **第一行 `del` 不能省**：`7z a` 是**追加**模式，不清旧条目，同一个名字打第二次会变成两个
> 包叠在一起（140 MB 就是这么来的 —— 新条目 42 MB 塞在旧 100 MB 里，公网下下来是坏的）。
> 绿色版 = 整个 deploy 目录原样打包，解压即用，无注册表。**deploy 目录本身**就是
> windeployqt 补出来的（见各工程 build 脚本），换 Qt 版本时重新 windeployqt 再打 zip。

### 云端让新包生效

**只放包，不用重启**（2026-10-05 实测：21:30 拷完，21:31 公网 HEAD 就是新文件大小 ——
云端每次请求**现扫** `assets\pkg\`，不是启动时快照）。
只有改了云端 **src 里的代码**（比如新增装机端点）才需要重启：
```bat
schtasks /run /tn StelarithCloud        rem 或：taskkill /f /im node.exe（看门狗十几秒自愈拉起）
```
运维规程因此简化成两步：**放包（cp）→ 面板刷新**。

## 三、为什么"找不到产物"是常态

- `assets/pkg/`、各工程的 `dist/`、`deploy/` 都是**构建产物**，git 里没有；
- 这台开发机就是发包源头；git clone 到别处只有源码，跑不了装机；
- 所以**运维规程**是：改代码 → 重打出包 → 拷进云端 `assets\pkg\` → 重启云端 → 面板出新包。
  这一条线每一步都有产物路径可查，就是本文件。
