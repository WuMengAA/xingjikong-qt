# 星集控 · 竞品调研（2026-10-05）

> **调研方法**：本次实时检索受限（web 搜索服务欠费、百度百科 403、Bing 中文分词失效），
> 本稿基于**行业既有知识**整理，个别功能细节标注「待官网核实」。不构成购买/对比的完整依据，
> 关键结论建议真机或官网二次确认。
>
> 一句话结论：**「开源 + 通用硬件 + 班级课表调课 + 广播通知」的组合目前没有直接竞品**——
> 开源派（Veyon/iTALC）无课表无通知；闭源一体机派（希沃/鸿合）有课表通知但锁硬件不开源。

## 一、竞品地图（按形态分四类）

## 三、洞察与差异化

1. **最大的空白：开源 × 课表调课 × 广播通知 三者组合**。
   - 开源派（Veyon/iTALC）做「控制」，完全不懂「课表/调课/通知」这些教学管理语义；
   - 希沃系做「教学管理」，但闭源、绑硬件、按订阅收费；
   - 星集控正好站在中间：控制能力（已切自有）+ 课表调课（刚自建）+ 广播通知（已走云端）+ 开源。

2. **调课（换课）是当前竞品最弱的点**：
   - Veyon/iTALC：没有课表概念；
   - 希沃信鸽有课表展示，但**换课/调课的「申请→审批→生效」流不多见**（多是管理员直接改）；
   - 星集控已实现审批流 + 自动对调——这是可宣传的差异化功能。

3. **通用硬件是另一个差异化**：
   - 希沃/鸿合/MAXHUB 都锁定自家一体机；
   - 星集控跑在「任何 Windows 一体机/普通 PC」——对采购过杂牌一体机或已有普通电脑的学校更友好（学校现状普遍是「各种牌子混着」）。

4. **开源（MIT）是信任资产**：
   - 教育局/学校对「数据在谁手里」敏感，闭源 SaaS 常被卡；
   - 云端/被控端/管理端 MIT 可私有化部署——直接对标「不想上云、想自持数据」的学校。

5. **潜在威胁**：
   - 希沃/鸿合若开源或开放生态，硬件+软件打包优势大；
   - Veyon 若加课表/通知模块，开源免费会抢走部分用户；
   - 智慧校园 SaaS（钉钉/企微教育）从「通知/课表」切入，可能把设备集控也卷进去。

## 四、对星集控的建议（按优先级）

1. **主打的差异话术**：「开源 · 通用一体机 · 调课审批流 · 大屏广播通知」四合一，别跟希沃拼「全家桶」，拼「开源+通用+教学管理闭环」。
2. **尽快补 OTA 自更新**（竞品多数有，星集控还只是规划）——没有自更新，「装一次不用管」的定位就缺一条腿。
3. **手机端 Qt 移植**是 Veyon/iTALC 完全没有、希沃有的能力——值得做（定位 v2 已定）。
4. **多学校案例**（school_id 已预留）可在 SaaS 类竞品前打「私有化多校部署」牌。
5. **课表/调课做深**：目前是基础版，可加「代课/合班/临时课表」——竞品更不会做。

## 五、新增竞品：ClassScreenLock（2026-10-05 补充，用户提供）

> 来源：`https://github.com/ClassScreenLock/ClassScreenLock`（README 实测抓取）。
> 定位：**开源教室锁屏工具**（GPLv3，.NET 9 / Win10-11 / 管理员权限），单机优先、无需联网。

### 5.1 与星集控能力对照

| 能力 | ClassScreenLock | 星集控 | 结论 |
|---|---|---|---|
| 许可 | GPLv3 | MIT | 我们更宽松（可闭源/私有派生） |
| 按课程表时段锁屏（上课解锁/下课锁屏） | ✅ 核心卖点 | ❌ 空白 | **我们要补** |
| 锁屏防退出（拦任务管理器/强杀） | ✅ 强项 | ❌ 只有 shutdown/reboot | **我们要补** |
| URL 过滤（娱乐/游戏/短视频黑名单） | ✅ | ❌ | 空白 |
| 应用/文件拦截（含 U 盘绕过） | ✅ | ❌ | 空白 |
| 定时截图本地存档 | ✅ | ❌（只有被动抓屏推流） | 空白 |
| 摄像头定时拍摄 | ✅ 选配 | ❌ | 空白 |
| 进程级防护（异常退出自动恢复锁屏） | ✅ | ❌ | **要补** |
| 数据加密 + 三级权限 | ✅ | 部分（角色矩阵，无加密） | 可借鉴 |
| 集控中心统一管理 | ✅ 独立平台 | ✅ 云端 8788 + 管理端 | 我们更深（课表/调课/回执） |
| 调课审批流 | ❌ 无课表概念 | ✅ 自建 | **我们赢** |
| 多学校（school_id） | ❌ | ✅ 预留 | **我们赢** |
| 云平台 + 大屏通知 + 回执 | ❌ 单机优先 | ✅ | **我们赢** |
| 硬件要求 | Win10/11 + .NET9（新系统限定） | 通用 Windows 一体机/PC | 我们更广 |

### 5.2 关键判断

1. **它是"单机锁屏工具 + 独立集控"，星集控是"云端集控平台 + 教学管理闭环"**——不是同一物种，
   但它在**学生课后管控**这段是实打实的能力，星集控这段是空白（被控端只能 shutdown/reboot）。
2. **最大威胁点不是功能重叠，而是"它已经有了锁屏"**：教室场景里"下课锁屏防学生乱动"是刚需，
   学生自带 U 盘绕策略正是它的核心卖点——星集控若一直不做，这段需求会被它（或同类）接走。
3. **我们最自然的补法不是抄锁屏**，而是把**课表/调课数据喂给锁屏策略**：星集控已有
   `school_timetable` + `class_schedules` + `schedule_swaps`，做"按这节课自动锁/不锁"是顺水推舟，
   而它只有"手动按时段开关"。这是它能做但我们能做得更深的分层。

### 5.3 建议（按优先级）

1. **被控端锁屏 + 防退出**（高优先，教室刚需）：QProcess 拦任务管理器 + 定时自检恢复，
   复用现有云端指令通道（新增 `lock` 指令），**不做**URL/应用拦截（那是浏览器级/进程级工程，先不做）。
2. **课表联动锁屏策略**（差异化）：站点侧先搭"时段→锁屏规则"数据模型（作息表已有），
   下发到被控端按课表自动锁/解锁——调课后自动跟随，这是它做不到的。
3. 定时截图/摄像头：低优先，等 Qt 线有空再议。
