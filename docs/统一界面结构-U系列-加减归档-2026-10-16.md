## 一、盘点结论：后端已插件化，前端没跟上

这个方向不是"从零引入插件"，而是**把项目已有的插件思维从前端补上**。

**后端现成的东西**（`control-qt/src/plugin/`）：

| 件 | 内容 |
|---|---|
| `StelarithPluginSDK.h` | 第三方 C++ 插件 SDK：manifest `{id,name,version,author,permissions,runtime,entry,actions}`，本地 WS JSON-RPC（`ws://127.0.0.1:26789`，env `STE_PLUGIN_PORT`） |
| `PluginHost` | 插件宿主：扫描 `plugins/`、起进程、`dispatch` action、**权限门控**（manifest ∩ known） |
| `PluginAgentApi` | 插件可调的 agent 能力：`islandShow` / `notify` / `settingsGet/Set` / `subscribeEvents` |
| 云端 `plugins.json` | 插件目录（含 `downloadUrl`），`permissions` 词表里**已经有 `"island"`** |

## 二、目标结构

**一个共享 UI 基座 + 一条声明驱动全界面。**

```qml
// 每个界面单元 = 一条声明，而不是一行 if-else
{ id: "interact", title: "互动审批", icon: "check",
  surfaces: ["panel"], scope: ["viewer"], perm: "notify",
  entry: "interact/InteractPanel.qml" }
```

外壳读这张表，**自动**生成导航项、面板宿主、动作列表、命令面板条目。
权限词表**直接复用后端已有的 `island/notify/settings`** —— 端到端一个词表，
第三方插件与内置功能走同一条门控。

## 八、踩坑与认知（本轮新增）

1. **Windows 上 Qt 日志默认走 `OutputDebugString`，控制台取不到。**
   首次跑 QML 探针"成功、零输出"极易被误读为"没跑"。
   ⇒ 解法：**把结果编码进退出码**（10=通过 / 20=失败 / 30=负向如期报错），
   并设 `QT_ASSUME_STDERR_HAS_CONSOLE=1` 才拿到文字（`QT_LOGGING_TO_CONSOLE` 已废弃）。
2. **共享件落点与消费方导入路径必须逐字对齐**，否则"搬完就炸"。
   `components/` 是相对导入（`import "../components/md3"`）的目标目录 ⇒
   共享 ui 必须落回 `qml/.../components/`，而不是另起 `shared-ui/`。
3. **严格双向门禁遇到"混放目录"会误报**。
   `copy_directory` 的"产物多出即残留"判据，只在 DST **专供共享件**时成立；
   与工程自有件混放时必须降级为子集模式 —— 所以门禁加了 `SUBSET`，而不是放弃检查。
4. **`Md3Dialog` 的两份差异只有一行**（`import "."`，供同目录 `Md3Btn` 解析），
   说明"逐字重复"的副本也可能已经**悄悄漂移**；合并时取超集而非任取一份。
5. **control 侧的 Md3 是"零引用"的模板存放**（其界面是岛本身），
   但仍按同模式接线 —— 因为它是两端唯一视觉模板，将来搬迁时两端写法要一致。
