## 一、盘点结论：后端已插件化，前端没跟上

这个方向不是"从零引入插件"，而是**把项目已有的插件思维从前端补上**。

**后端现成的东西**（`control-qt/src/plugin/`）：

| 件 | 内容 |
|---|---|
| `StelarithPluginSDK.h` | 第三方 C++ 插件 SDK：manifest `{id,name,version,author,permissions,runtime,entry,actions}`，本地 WS JSON-RPC（`ws://127.0.0.1:26789`，env `STE_PLUGIN_PORT`） |
| `PluginHost` | 插件宿主：扫描 `plugins/`、起进程、`dispatch` action、**权限门控**（manifest ∩ known） |
| `PluginAgentApi` | 插件可调的 agent 能力：`islandShow` / `notify` / `settingsGet/Set` / `subscribeEvents` |
| 云端 `plugins.json` | 插件目录（含 `downloadUrl`），`permissions` 词表里**已经有 `"island"`** |

**前端是什么样**（量化盘点，全部来自实测 grep / wc）：

## 二、目标结构

**一个共享 UI 基座 + 一条声明驱动全界面。**

```qml
// 每个界面单元 = 一条声明，而不是一行 if-else
{ id: "interact", title: "互动审批", icon: "check",
  surfaces: ["panel"], scope: ["viewer"], perm: "notify",
  entry: "interact/InteractPanel.qml" }
```

外壳读这张表，**自动**生成导航项、面板宿主、动作列表、命令面板条目。
权限词表**直接复用后端已有的 `island/notify/settings`** —— 端到端一个词表，
第三方插件与内置功能走同一条门控。

## 八、踩坑与认知（本轮新增）

1. **Windows 上 Qt 日志默认走 `OutputDebugString`，控制台取不到。**
   首次跑 QML 探针"成功、零输出"极易被误读为"没跑"。
   ⇒ 解法：**把结果编码进退出码**（10=通过 / 20=失败 / 30=负向如期报错），
   并设 `QT_ASSUME_STDERR_HAS_CONSOLE=1` 才拿到文字（`QT_LOGGING_TO_CONSOLE` 已废弃）。
2. **共享件落点与消费方导入路径必须逐字对齐**，否则"搬完就炸"。
   `components/` 是相对导入（`import "../components/md3"`）的目标目录 ⇒
   共享 ui 必须落回 `qml/.../components/`，而不是另起 `shared-ui/`。
3. **严格双向门禁遇到"混放目录"会误报**。
   `copy_directory` 的"产物多出即残留"判据，只在 DST **专供共享件**时成立；
   与工程自有件混放时必须降级为子集模式 —— 所以门禁加了 `SUBSET`，而不是放弃检查。
4. **`Md3Dialog` 的两份差异只有一行**（`import "."`，供同目录 `Md3Btn` 解析），
   说明"逐字重复"的副本也可能已经**悄悄漂移**；合并时取超集而非任取一份。
5. **control 侧的 Md3 是"零引用"的模板存放**（其界面是岛本身），
   但仍按同模式接线 —— 因为它是两端唯一视觉模板，将来搬迁时两端写法要一致。

## 9.3 声明的形状（契约）

```js
{ id: "interact", title: "互动审批", icon: "check",
  scope: ["viewer"], order: 60, surfaces: ["panel", "command"],
  perm: "notify", caps: [], danger: false, admin: false,
  action: "", entry: "panels/InteractPanel.qml",
  keys: ["interact", "shenpi"], tip: "审学生点的歌 / 祝福" }
```

- `surfaces` ∈ `page | panel | action | command | island`（可多占）
- `scope` ∈ `viewer | agent | both`；`perm` 取自与后端同源的权限词表
- `panel`/`page` 面必须给 `entry`；`action` 面必须给 `action` 指令名
- entry 契约：`open()` / `close()` 必须，`openWith(args)` 可选；
  声明 `property var ctx` 收宿主注入的 `{theme, registry, host, scope, open, close}`

不是拿它当闸门把老机器锁死"）：

| 情形 | 行为 |

| 被门控的 id 被 `host.open()` | **拒绝**（不是开了个空壳） |

## 10.7 U3 新增认知

1. **「路径引用」和「类型使用」是两种引用**：删一个组件前，只 grep 路径会漏掉靠
   `import "目录"` 解析的类型使用。**判据必须是类型名**。
2. **qmllint 不查「目录导入里的类型缺失」**：它给了"0 错误"的假安全感。
   这类问题的唯一可靠出口是**运行时探针**（真实例化每个 entry）。
   ⇒ U3 的探针不是"形式主义"，它抓到了 A 档的回归。
3. **QML 的隐式作用域是迁移的隐形地雷**：裸 `th` 靠"子对象 → 组件根"解析，
   一旦把对象搬到别的文件，那条链无声断掉（不会报错，只会渲染异常/绑定失败）。
   抽取前必须**系统扫描根对象成员**，不能只看带限定前缀的引用。
4. **`property var X: Y` 里 RHS 的裸标识符替换要小心自引用**：
   把 `theme: th` 里的 `th` 换成 `theme` 会得到 `theme: theme` 绑定环。
5. **`anchors.centerIn: parent` 依赖 parent 的几何**：把内联对象搬到宿主里，
   宿主必须铺满原容器，否则全部挤到左上角。
6. **门禁会先抓到自己人的疏忽**：改完共享件忘记同步产物，门禁立刻红 —— 这正是它存在的意义。

## 11.3 执行路径的收敛（这是 U4 最有价值的一点）

改造前，**同一个动作在不同入口走不同的路**：

```
右栏「锁屏」    → runAction({l:"锁屏",a:"lock",p:"admin"})  → 内部再判 permOk/capOk/danger
命令面板「锁屏教室机」→ runAction({l:"锁屏",...})            → 同上（但绕过了 d.t 检查）
快捷行「锁屏」  → quickAction("lock") → permOk("lock") **+** runAction(...)   ← 多一道
批量条「锁屏选中的」→ runOnPicked("lock")                   ← 又是另一条
```

现在四者全部汇入 `runActionById(id)`：角色 → 能力 → 危险确认，顺序与改造前一致。

## 11.4 三个"刻意的重复"

迁移中出现了三处**看起来像冗余、实际必须保留**的设计，都写进了声明注释：

| 项 | 为什么不能合并 |

| `title` / `palName` / `quickTitle` | 同一动作在三处叫法本来就不同：按钮要短（"锁屏"）、命令面板要能自解释（"锁屏教室机"）、快捷行是口语（"发通知"）。**统一的是清单，不是文案** |

## 11.5 ★ 一处**没有**顺手改掉的现状缺陷（重要）

`backend.mayDo(p)` 的语义是：admin 恒 true；teacher 则 `!adminOnlyActions().contains(p)`，
而那张表里装的是**动作名**（lock/reboot/…），**没有 "admin" 字样**。

⇒ `permOk("admin")` 在 teacher 身份下**恒真**。而右栏按钮传的正是 `d.p = "admin"`。

| 入口 | 实际生效的门控 | teacher 下能否锁屏 |
|---|---|---|
| 右栏按钮 | `permOk("admin")` = **恒真** | **能**（越权） |
| 命令面板 | 同上（`d.p` 也是 "admin"） | **能**（越权） |
| 快捷行 | 先 `permOk("lock")`（真拦）+ 再 `permOk("admin")` | 被拦 ✓ |
| 批量条 | `runOnPicked` 里 `permOk(a)`，a = "lock" | 被拦 ✓ |

这是**既有缺陷**（右栏/命令面板的角色门控形同虚设）。但修它会改变老师实际能做的事，
属于用户该点单的范畴 —— **本次没有改**，只用 `quickGuard` 字段把快捷行那道原样保住，
