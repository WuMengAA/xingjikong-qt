# 被控端连线地址 · 加减归档（2026-10-06 晚）

起因：用户追问「**说白了，为什么连不上任何一个设备，被控端无法连接 website（website 为核心）**」。
结论：**两个独立的错叠在一起**，而且都不在管理端。

---

## 一、两个错

### 错一：被控端连云端——8788 公网根本不通，只有 443/wss 通

云端 `.env` 写明了架构：cloudflared 隧道从本机 8788 回源，公网只经 Cloudflare 443。
实测（agent / viewer 各两条）：

| 地址 | 结果 |
|---|---|
| `wss://control.245959623.xyz/ws/agent`（443） | **101 Switching Protocols** ✅ |
| `ws://control.245959623.xyz:8788/ws/agent` | **超时** ❌ |
| `wss://control.245959623.xyz/ws/viewer`（443） | **101** ✅ |
| `ws://control.245959623.xyz:8788/ws/viewer` | **超时** ❌ |

被控端 `STE_QT_WS_URL` **必填且无默认值**，而配置向导的示例偏偏是
`ws://10.0.0.5:8788/ws/agent`（`src/main.cpp:1565`）——照示例填就永远连不上。

注：云端 `provision.js` 的 `agentWsUrl()` 算的是**对的**，装机面板生成的 bat 也用它
⇒ **走面板装机不会错，手填会错**。

### 错二（"连不上 website"的真身）：站点地址被从云端地址"推导"，域名和端口各错一次

`main.cpp::siteBaseFromWsUrl()` 做 `ws://host:8788/ws/agent → http://host:8090`。生产部署下：

- **域名错**：云端在 `control.245959623.xyz`，站点在 `www.245959623.xyz`，不是一个子域；
- **端口错**：站点公网走 443（Cloudflare），8090 是内网端口，公网不通。

实测对照（决定性）：

```
https://control.245959623.xyz:8090/api/device/activate  →  超时，连不上
https://www.245959623.xyz/api/device/activate           →  HTTP 400（通了，400 只是没带参数）
```

`src/oauthbind.cpp` 里还有**同一个 bug 的另一半**（推导成 `https://control.…`，
授权页 `/oauth/authorize` 与绑定接口 `/api/device/bind` 全打到云端域上）。

---

## 二、改动

### 修改 `src/main.cpp`
- **新增** `kDefaultSiteUrl = "https://www.245959623.xyz"` —— 站点地址升为**一等配置**（唯一真源），与站点实际部署一致。
- **新增** `isPrivateHost()`：`10.` / `192.168.` / `172.` / `localhost` / `127.0.0.1` 才判内网。
- **改** `siteBaseFromWsUrl()`：
  旧＝一律从云端地址推导并拼 `:8090`；
  新＝`STE_QT_SITE_URL` 显式配置 → **仅当云端在内网**才推导（且不拼 8090）→ 否则用生产常量。

### 修改 `src/oauthbind.cpp`
- **新增** `kBindDefaultSiteUrl`（同真源）+ `bindIsPrivateHost()`（同口径）。
- **改** 站点地址取值：同样的三级顺序。
- **行为差异**：以前推导不出站点地址时 `emit failed("没配站点地址…")` 直接判绑定失败；
  现在总有常量兜底，**不再因此失败**。

### 删除
无。

### 未改（记下来，等点单）
- `src/main.cpp:1565` 配置向导的 placeholder 仍是 `ws://10.0.0.5:8788/ws/agent`（**错的**）。
- `src/main.cpp:5/848/850` 头部与块注释里"站点与云端同机、端口 8090"的旧描述。

## 五、这次抓到的坑

1. **`/api/devices` 要 `CLOUD_VIEWER_TOKEN`，不是 `CLOUD_WS_TOKEN`**（用错吃 401）。
   设备令牌用于被控端连 WS，管理端令牌用于查表，两者不是一个东西。
2. **插入型补丁不是幂等的**：脚本被跑了两次，`oauthbind.cpp` 里插出两份
   `kBindDefaultSiteUrl`（重复定义，编译直接失败）。插入前先查目标串是否已存在，
   或跑完立刻 `grep -c` 验份数。
