## 1 生产事故：Qt TLS 后端退化到 `cert-only`（P0）

### 1.1 现象（学生机 `DESKTOP-I15OM55`，用户 `XLZX3`）

```
[oauthbind] 自检：TLS 可用=否 运行时=(未加载) 后端=cert-only 应用代理类型=2
...
The backend named "cert-only" does not support TLS
QSslSocket::connectToHostEncrypted: TLS initialization failed
[oauthbind] 换站点令牌失败（HTTP 0，networkError=99：TLS initialization failed）
```

同一次启动里：`连接 wss://control.245959623.xyz/ws/agent …` 之后**永远没有** `已连上云端`。

⇒ 两个看似无关的报障是**同一个根因**：

| 用户描述 | 实际含义 |
|---|---|
| 「被控端连不上地址」 | `wss://` 建立不了（TLS 起不来） |
| 「换网站登录态失败 HTTP 0」 | `https://` 建立不了（TLS 起不来） |

### 1.2 根因链（逐层取证）

| 层 | 事实 | 证据 |
|---|---|---|
| 1 | **`HTTP 0` 不是站点返回的状态码**，而是「一个字节的响应都没收到」 | `HttpStatusCodeAttribute` 在传输层失败时是无效 QVariant，`toInt()` 得 0 |
| 2 | 真因是 **TLS 层初始化失败** | `networkError=99`（SslHandshakeFailedError）+ `TLS initialization failed` |
| 3 | Qt 当时的**活跃 TLS 后端是 `cert-only`** —— 一个只能解析证书、**不能建 TLS 连接**的退化后端 | `availableBackends()=cert-only`；`The backend named "cert-only" does not support TLS` |
| 4 | **Qt 6.12 的 TLS 后端是插件**（`{app}\tls\*.dll`），不是内置 | `D:/QTqwq/6.12.0/msvc2022_64/plugins/tls/` = qcertonly / qopenssl / qschannel |
| 5 | **windeployqt 默认只部署 certonly + schannel，不拷 openssl 后端** | `windeployqt --list relative` 只列这两个；`build/tls/` 长期只有 2 个 |
| 6 | schannel 后端在**部分机器上会加载失败**（杀软拦截 / 系统策略 / LTSC 精简），此时退化成 cert-only | 学生机实测；本机（`tls/` 有 3 个）连接正常 |
| 7 | **没有任何构建/打包流程保证 openssl 后端存在** | `CMakeLists.txt` 与全部脚本里**都没有 windeployqt 调用**；`build/tls/` mtime = 10-12 10:10（手工跑过一次留下的） |

**结论**：出包时 `build/tls/` 只有 certonly + schannel ⇒ 装到「schannel 不可用」的机器上就只剩 cert-only ⇒ **TLS 全挂**。

> **佐证**：本机安装目录 `C:/Program Files/Stelarith/tls/` 有 **3 个**（含 `qopensslbackend.dll`，mtime 10-11 17:40）—— 那是**手工救场补的**，从未固化到打包流程。典型的「改一处漏一处」。

### 1.3 处置（四层，防复发）

| # | 文件 | 改动 |
|---|---|---|
| ① | `Stelarith-control-qt/build/tls/qopensslbackend.dll` | **补入**（从 Qt 源目录拷）—— 本次包立即带上 openssl 后端 |
| ② | `build-agent-installer.sh` | 新增 **0b) TLS 后端体检**段：出包前逐个检查 3 个后端，缺则自动从 Qt 源目录补入；**补不齐直接 FATAL**（宁可不出包，也不出「装上去连不上」的半残包） |
| ③ | `installer.iss` | tls 段从 `Source: "build\tls\*"`（通配，会**静默少拷**）改为**逐个点名 3 个** —— 缺任何一个 → ISCC 当场报错 |
| ④ | `src/main.cpp` | 新增**启动时 TLS 自检**：`supportsSsl()` 为假时 `qWarning` 打出可用后端 + 明确排查路径（`tls\` 三个后端 + `libssl/libcrypto`）。**这类故障以前完全静默**，只有一个「连不上」的表象 |

**为什么 ④ 重要**：本次定位之所以难，是因为故障**没有任何自诊断**。一行启动自检把「连不上」变成「TLS 后端只有 cert-only，去查 `tls\`」。

### 1.4 验证证据

```
[pack] [tls] 后端齐全：qcertonlybackend.dll qopensslbackend.dll qschannelbackend.dll
[pack] [version] 0.6.29
[pack]    Compressing: ...\build\tls\qcertonlybackend.dll
[pack]    Compressing: ...\build\tls\qschannelbackend.dll
[pack]    Compressing: ...\build\tls\qopensslbackend.dll      ← openssl 后端确实进了包
```

- `qopensslbackend.dll` **不静态依赖** OpenSSL（`dumpbin /DEPENDENTS` 只有 CRYPT32 / Qt6Network / Qt6Core / KERNEL32 / VC 运行库）⇒ 它走 `LoadLibrary` **动态加载** ⇒ 包里已有的 `libssl-3-x64.dll` / `libcrypto-3-x64.dll`（OpenSSL 3.x，导出 `BIO_new` 等 603 个符号）正好供它用。
- 被控端编译 `EXIT=0`；`stelarith-agent-qt.exe` 与安装器内嵌版本读回 **0.6.29**。

## 2 被控端登记项修复

### 2.1 `launch_app` 白名单用 `contains` 子串匹配（P1 安全 → 免确认任意代码执行）

**原码**：`target.toLower().contains(item)` —— **子串**匹配。

**攻击链**：`file_push` 能把文件落到 `~\incoming\`（限制只有「不能带路径」+「必须有扩展名」，**不禁止起名**）⇒ 落一个 `chrome-setup.exe` ⇒ `launch_app target=…\incoming\chrome-setup.exe` ⇒ 文本含 `chrome` ⇒ 放行 ⇒ **远程免确认执行任意二进制**。

**修复（两道闸，缺一不可）**：

1. **基名精确匹配**：剥路径 + 去 `.exe` 后与白名单**全等**（`chrome-setup` ≠ `chrome` → 拒）。
2. **目录闸**：带路径的 target 必须落在**可信安装目录**（`%ProgramFiles%` / `%ProgramFiles(x86)%` / `%ProgramW6432%` / `%SystemRoot%` / `%LOCALAPPDATA%\Programs`）；非标准位置由 `STELARITH_AGENT_LAUNCH_DIRS` 显式追加。
   ⇒ 这条堵的是「把恶意二进制**直接改名成 `chrome.exe`** 再放进 incoming」绕过闸 1。

裸名字（如 `notepad`）不含分隔符 ⇒ 交给 `ShellExecuteW` 走 App Paths / PATH 系统级解析，安全。

### 2.2 `terminal_input` 无条件回 `done`

`TerminalConsole::input()` 在**会话不存在/已关闭、或上条命令还在跑**时静默 `return`，而调用方无条件回 `done` ⇒ 管理端以为「输入成功了」，实际一个字符都没进 shell。

**修复**：`input()` 返回 `bool`；调用方据返回值回 `done` / `failed`（带原因）。

## 3 云端登记项修复（4 条）

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| 3.1 | `index.js` 录像上传 | 只有**下限**（<1KB 拒）没有**上限**，`chunks` 全攒内存 ⇒ 持设备令牌者可发无限大 body 把云端 **OOM** | 加 `MAX_RECORDING_BYTES`（默认 300MB，`CLOUD_MAX_RECORDING_BYTES` 可覆盖）；超限回 **413** + `req.destroy()` |

## 4 管理端登记项修复（1 条）

`oauthlogin.cpp` 换票请求**未设传输超时** ⇒ 站点挂住（半开连接 / 中间设备黑洞）时 `QNetworkReply` 永不 `finished` ⇒ `m_busy` 不复位 ⇒ **登录按钮永久变灰**，只能重启软件。

**修复**：`req.setTransferTimeout(15000)`。
