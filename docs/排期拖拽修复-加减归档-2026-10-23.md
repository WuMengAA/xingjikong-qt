## 2 修改的既有文件

### 2.1 `Stelarith-control-qt/qml/shell/BroadcastScheduleSheet.qml`（779 → 795 行，+40/−24）

**改动 ①：MouseArea 拖拽入口重写**（行 525-564 区块）
- 旧：`onPressAndHold: if (!root.saving) ma.drag.active = true` + `onReleased` 依赖 `ma.drag.active`
- 新：删 pressAndHold，改 MouseArea 内置移动拖拽（`drag.target: card` + `drag.axis: Drag.YAxis`，移动超阈值自动开始）；`onPressed` 记 `pressY = card.y`
- 为什么：**Qt 6 起 `QQuickDrag::active` 是只读 Q_PROPERTY（无 WRITE）**，QML 赋值即抛 `TypeError: Cannot assign to read-only property "active"`（探针警告通道抓到过）。旧写法自 10-22 潜伏至今从未启动过拖拽。
- 行为差异：长按不再触发任何东西；改为「按下后移动即拖」。

**改动 ②：onReleased 落点判定重写**（本批次核心）
- 旧：`schedList.indexAt(schedList.contentX, card.y + height / 2)`
- 新：`ma.mapToItem(schedList, mouse.x, mouse.y)` → `Math.floor((contentY + mp.y) / (card.height + schedList.spacing))` → clamp 到 `[0, dayModel.count - 1]`；`root.saving` 时 idx = -1
- 为什么：拖拽中 card 与相邻行**视觉重叠**，按 card 中心查 `indexAt` 恒命中**被拖动卡自己的行**（idx == myIndex ⇒ 从不换序）；探针四候选实证：A（card 中心 indexAt）=0、B（鼠标点 indexAt）=0、**C（鼠标点算术）=1 ✓**、D（card 位移算术）=1 ✓。
- 行为差异：拖到别的行松手 → 真的换序并提交；松手点在列表上方/下方 → 钳制到首/末行（旧逻辑是 indexAt 返回 -1 一律弹回）。

**改动 ③：文案/注释同步**：头部注释「长按拖拽排序」→「拖拽排序」；提示文案「长按曲目可调整顺序」→「拖动曲目即可调整顺序」；⇕ 手柄注释「长按即触发」→「拖动即触发」。
