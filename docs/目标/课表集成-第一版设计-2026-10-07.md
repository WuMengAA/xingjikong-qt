# 星集控 · 课表集成（第一版设计，2026-10-07）

> 对应《全量设计文档》10.3「定时任务/课表集成（中）」+ 第九部分 ClassIsland 联动。
> 核心：「课表驱动设备策略」——上下课铃响，设备自动执行策略（锁屏/解锁/限网）。

## 一、目标

| 场景 | 期望 |
|---|---|
| 第 1 节上课铃 | 教室机自动锁屏（可配置） |
| 下课铃 | 自动解锁 |
| 最后一节下课 | 自动关机倒计时（可选） |
| 信息技术课 | 放宽网络（若做了网络控制） |

**与 ClassIsland 的关系**：
- ClassIsland 做**课表显示与提醒**（浮动岛），星集控做**设备控制**。
- 第一版星集控**自带简单课表配置**（不依赖 ClassIsland 也能跑）；
  ClassIsland 联动（第九部分路径 A 桥接插件）作为后置增强。

## 二、数据模型

```
TimedRule {
  id: string
  name: string            // "周一第1节"
  weekdays: [1..7]        // 0=sun/1=mon...（周一=1）
  periodIndex: number     // 第几节（1 起）
  action: lock|unlock|shutdown|notify
  params: {}              // shutdown 延时等
  enabled: bool
}
```

第一版用**现成的定时任务表**扩展：在 `schedule_shutdown/schedule_reboot` 基础上
加 `schedule_lock` / `schedule_unlock`（时间点触发），再图层表语义（周几+节次→时间点）。

## 三、被控端改动

- 现有 `schedule_shutdown/schedule_reboot` 是**一次性**定时（到点执行一次）。
- 新增 `schedule_lock` / `schedule_unlock`：一次性定时（到点锁屏/解锁）。
  - 可叠加：每节课前下发 `schedule_lock at=HH:mm`（由管理端/云端按课表批量下发）。
- 补充 `list_schedules` 已有的查表能力（含新增 action）。

**第一版不做**：被控端本地课表持久化（每次开机重新下发即可）；
遗漏容错（教室机离线时课表指令进补发队列，重连后补发——现有机制天然支持）。

## 四、管理端改动

- 集控页「定时任务」卡片扩展：加「锁屏」「解锁」动作（现有 定时关机/重启 并排）。
- 新增「课表策略」卡片（第一版简化）：
  - 选节气（如"周一第1节"）+ 动作（锁屏/解锁）+ 启用。
  - 管理端按下发策略 → 对目标设备批量 `schedule_lock at=...`（换算节次时间）。
  - 精确上课时间从**站点设置/ClassIsland 课表**读（第一版：管理端手填时间表）。

## 五、与 ClassIsland 联动（第九部分路径 A，后置）

正规做法是开发 ClassIsland **桥接插件**（C#，PluginSdk）：
- 插件订阅 `ILessonsService` 课表事件 → 转发给被控端（本地 IPC/WS）触发行为。
- 被控端状态推回插件 → ClassIsland 悬浮岛展示（"老师正在讲话"等）。
- 已部署 ClassIsland 的学校：星集控灵动岛降级为"只处理 ClassIsland 不覆盖的事件"。

第一版**不做插件**（C# 工程 + 上架门槛），先靠管理端课表策略（手填时间段）
覆盖"上课锁屏"这一核心场景。

## 六、安全与边界

- 锁屏/解锁策略只对**授权班级**下发（权限同设备控制）。
- 关机课表要明确勾选才启用（防"下课自动关机"误伤）。
- 跨周：每周末管理端重发下周课表策略（第一版不自动）。

## 七、开发顺序

1. agent `schedule_lock/schedule_unlock`（复用 schedule_shutdown 定时骨架）
2. 管理端定时卡片加锁屏/解锁 + 课表策略卡片（手填时间）
3. ClassIsland 桥接插件（后置，评估后再做）
