# 星集控 · 屏幕广播（第一版设计，2026-10-07）

> 对应《全量设计文档》10.4「最该先补五个」第 1 位：屏幕广播 —— 教学最核心功能，
> 但一直没给具体设计。本文给出**复用现有通道的务实第一版**。

## 一、目标与边界

老师把**自己屏幕**广播给学生教室机全屏显示（讲课画面），随时开始/停止。

| 维度 | 第一版 | 明确不做（后置） |
|---|---|---|
| 源 | 管理端抓屏（QScreen::grabWindow） | 指定应用窗口、多屏选择 |
| 码率 | JPEG 快照，**3-5 fps**（讲课足够，带宽友好） | 30fps 视频流（需 WebRTC/编码器） |
| 目标 | 单个班级（一组设备） | 全校、按分组 |
| 学生端 | 全屏显示 + "正在接收老师屏幕"提示 | 学生交互（提问/举手） |
| 带宽 | 错峰 + 限速（文档 2.3） | 自适应码率 |

**第一版验收**：老师点"开始广播"→ 目标班级教室机 3 秒内全屏显示老师屏幕（3fps），
点"停止"→ 全部恢复。60 台教室机同时收流不卡顿（服务器下行 ≈ 60 × 300kbps ≈ 18Mbps，可承受）。

## 二、技术路径（复用现有通道，不新造轮子）

现有链路：被控端抓屏 → 二进制帧 → 云端 `broadcastFrame` → 订阅的管理端。
屏幕广播是**反向**：管理端抓屏 → 云端 → 被控端。**复用同一套二进制帧格式 + 订阅机制**：

```
管理端 (viewer)                 云端 (cloud)                 被控端 (agent)
   抓屏 → JPEG 帧                    │                        │
   │── broadcast.start ──────────→│  记录目标班级            │
   │── 二进制帧(带广播标记) ──────→│── 转发给班级内设备 ────→│ 全屏显示 BroadcastWindow
   │                              │                            │
   │── broadcast.stop ───────────→│  停止转发                │ 恢复
```

### 关键复用点

1. **帧格式**：沿用 `makeFrame(uid, seq, mime, buf)`（v1 二进制帧）。管理端以特殊 uid
   （如 `broadcast:<classId>`）推帧，云端按"广播目标"路由而非"订阅者"路由。
2. **协议消息**：新增三个 v1 消息类型（协议版本号不变，加类型不破坏旧客户端）：
   - `broadcast.start { classId, fps }` —— 管理端发起
   - `broadcast.stop { classId }` —— 管理端停止
   - `broadcast.frame { classId, seq }` —— 帧（也可直接复用二进制帧 + 帧头 classId）
3. **云端路由**：`broadcastStart(classId)` 记录活跃广播 → 收到管理端帧时转发给
   班级内**在线**设备（用 registry 的设备表查班级），`broadcastStop` 清除。

## 三、三端改动点

### 云端（cloud-ws）
- `registry.js`：加 `setBroadcast(classId, viewerWs)` / `clearBroadcast` / `broadcastToAgents(classId, buf, seq)`；
  广播期间帧直接推给目标 agent 的 ws（`ws.send(makeFrame(uid, seq, mime, buf))`）。
- `index.js`：处理 `broadcast.start/stop/frame` 消息；广播源需鉴权（管理端令牌）。

### 管理端（viewer-qt）
- 集控页加「屏幕广播」按钮 + 目标班级选择。
- `ViewerBackend`：`startBroadcast(classId)` 起 QTimer 每 200-330ms 抓屏
  （`QScreen::grabWindow(0)` → JPEG 压缩）→ 二进制帧发送；`stopBroadcast` 停。

### 被控端（control-qt）
- 新增 `BroadcastWindow`（复用 NotifyWindow 全屏形态：深色底 + 画面 QLabel 拉伸显示 +
  "正在接收老师屏幕" 底部提示）。
- 处理 `broadcast.frame` → 显示画面；`broadcast.start` 显示提示；`broadcast.stop` 恢复。
- 广播期间**暂停本地抓屏上传**（避免同时上传两路占带宽）。

## 四、带宽与性能（文档 2.3 落地）

| 项 | 数值 | 处理 |
|---|---|---|
| 单帧 | 1280×720 JPEG ≈ 80-120KB（3fps ≈ 240-360KB/s） | QScreen::grab 后 libjpeg 质量 70 |
| 服务器下行 | 60 台 × 300kbps ≈ 18Mbps | 可承受（无需分批） |
| 教室机上行 | 广播期间暂停抓屏上传 → 0 | 必须做，否则 60 台上行叠加 |
| 错峰 | 不必要（服务器主动推，不是教室机拉） | 云端按顺序单线程推即可 |

## 五、安全与隐私

- 广播源必须是**管理端令牌**（云端鉴权，复用现有 viewer 鉴权）。
- 学生端显示"正在接收老师屏幕"（知情，非静默）。
- 老师只能广播到**授权班级**（后端校验，前端只提示——设计文档 6.3 铁律）。
- 不录音不存储，纯实时。

## 六、开发顺序（2-3 轮完成）

1. **云端**：broadcast 三消息 + 路由（独立小步，可单测）
2. **被控端**：BroadcastWindow + frame 处理（复用 exam_mode 窗口骨架）
3. **管理端**：抓屏 QTimer + 集控页按钮
4. 联调：真机 1 台管理端 + 2 台教室机验证带宽与延迟
