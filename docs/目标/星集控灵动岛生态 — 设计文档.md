# 星集控灵动岛生态 — 设计文档

> 本文档把灵动岛从"一个功能"提升为"一个平台"，定义它如何成为星集控的信息中枢，以及如何让第三方应用接入。

---

## 一、生态愿景

灵动岛不应该是星集控内部的专属组件，而应该成为**教室屏幕顶部的开放信息层**。

```
现在的灵动岛：
  星集控内部 → 灵动岛 → 学生看到

未来的灵动岛生态：
  ┌─────────────┐
  │  ClassIsland │──┐
  │  考试系统    │──┤
  │  校园广播    │──┼──→ 灵动岛平台 ──→ 学生/老师看到
  │  门禁系统    │──┤
  │  第三方插件  │──┘
  └─────────────┘
```

**核心价值**：任何应用都能向灵动岛推送信息，学生/老师只在一个地方看通知，不用在多个软件之间切换。

---

## 二、三类生态角色

| 角色 | 职责 | 示例 |
|---|---|---|
| **信息生产者** | 向灵动岛推送内容 | 星集控、ClassIsland、考试系统、第三方插件 |
| **灵动岛平台** | 接收、排序、展示、交互 | 星集控被控端/管理端的灵动岛组件 |
| **信息消费者** | 看到灵动岛的人 | 学生、老师 |

**关键**：灵动岛平台是"中立"的。它不关心信息来自谁，只关心信息的优先级、展示方式、交互方式。

## 三、灵动岛消息协议

### 3.1 统一消息格式

任何应用向灵动岛推送，都用这套格式：

```json
{
  "source": "classisland",
  "type": "lesson.start",
  "priority": 3,
  "title": "数学课开始",
  "icon": "📐",
  "duration": 5000,
  "persistent": false,
  "interactive": false,
  "actions": [],
  "payload": {
    "subject": "数学",
    "teacher": "张老师",
    "endTime": "10:45"
  }
}
```

### 3.2 字段定义

| 字段 | 类型 | 说明 |
|---|---|---|
| `source` | string | 来源标识（必填） |
| `type` | string | 消息类型（必填） |
| `priority` | int | 优先级 1-10，越高越优先 |
| `title` | string | 显示文字（必填） |
| `icon` | string | emoji 或图标名 |
| `duration` | int | 显示时长（毫秒），-1 为持续 |
| `persistent` | bool | 是否持续显示 |
| `interactive` | bool | 是否可点击交互 |
| `actions` | array | 可执行的操作 |
| `payload` | object | 业务数据 |

### 3.3 优先级规范

| 优先级 | 场景 | 示例 |
|---|---|---|
| 9-10 | 紧急 | 火警、紧急疏散 |
| 7-8 | 重要 | 考试开始、老师讲话 |
| 5-6 | 常规 | 上课提醒、消息通知 |
| 3-4 | 一般 | 课表展示、进度更新 |
| 1-2 | 低 | 装饰性信息 |

**规则**：高优先级抢占低优先级；同优先级按时间顺序。

## 六、接入方式

### 6.1 三种接入途径

| 途径 | 适用 | 复杂度 |
|---|---|---|
| **本地 WebSocket** | 同机应用（ClassIsland、考试系统） | 低 |
| **云端 API** | 远程应用（校园广播、门禁） | 中 |
| **HTTP Webhook** | 简单推送 | 低 |

### 6.2 本地 WebSocket（推荐）

被控端在 `127.0.0.1:19527` 开一个本地 WebSocket 服务，接收本机应用的消息：

```cpp
// IslandLocalServer.cpp
class IslandLocalServer : public QObject {
    Q_OBJECT
public:
    void start() {
        m_server = new QWebSocketServer("IslandLocal",
            QWebSocketServer::NonSecureMode, this);
        m_server->listen(QHostAddress::LocalHost, 19527);

        connect(m_server, &QWebSocketServer::newConnection, this, [this]() {
            auto *ws = m_server->nextPendingConnection();
            connect(ws, &QWebSocket::textMessageReceived, this,
                    &IslandLocalServer::onMessage);
        });
    }

private:
    void onMessage(const QString &msg) {
        QJsonObject obj = QJsonDocument::fromJson(msg.toUtf8()).object();
        // 校验 source 白名单
        if (!isAllowedSource(obj["source"].toString())) return;
        // 推给灵动岛
        emit messageReceived(obj);
    }
};
```

**安全性**：
- 只监听 `127.0.0.1`，不接受外部连接
- 校验 `source` 白名单，未知来源拒绝
- 消息大小限制（如 4KB）
- 频率限制（如每秒 10 条）

### 6.3 云端 API

远程应用通过星集控云端推送：

```
POST /api/island/push
Authorization: Bearer <app-token>

{
  "deviceId": "room-101",
  "message": {
    "source": "broadcast",
    "type": "broadcast.emergency",
    "priority": 10,
    "title": "紧急通知：...",
    "duration": -1
  }
}
```

云端校验 app-token 后，路由到目标设备的 WebSocket。

### 6.4 HTTP Webhook

简单场景，直接 POST：

```
POST http://127.0.0.1:19527/webhook
Content-Type: application/json

{
  "source": "weather",
  "type": "weather.update",
  "priority": 2,
  "title": "今日晴 25°C",
  "duration": 3000
}
```

## 八、多端灵动岛生态

| 端 | 灵动岛形态 | 接收哪些信息 |
|---|---|---|
| **被控端（学生）** | 顶部浮层 | 学生需知情的（老师讲话、消息、考试） |
| **管理端（老师）** | 顶部胶囊 | 系统状态（指令、文件、告警、连接） |
| **Web 后台** | 顶部胶囊 | 同管理端 |
| **手机端** | 顶部横幅 | 告警、指令结果 |
| **展板** | 不显示 | 无 |

**信息路由**：同一条消息，根据端的不同，决定是否展示、展示为什么形态。

```js
// 路由规则
function routeMessage(msg, target) {
  const rules = {
    'voice.active': { student: true, teacher: true, mobile: false },
    'lesson.start': { student: true, teacher: false, mobile: false },
    'command.progress': { student: false, teacher: true, mobile: true },
    'alert.error': { student: false, teacher: true, mobile: true },
  };
  return rules[msg.type]?.[target] ?? false;
}
```

## 九、生态治理

### 9.1 来源白名单

只有白名单内的 `source` 才能推送。默认白名单：

```
星集控自身：
  - star-control
  - star-control-agent

官方集成：
  - classisland
  - exam-system
  - campus-broadcast

第三方（需管理员批准）：
  - 用户安装的插件
```

### 9.2 频率限制

| 来源 | 限制 |
|---|---|
| 星集控自身 | 无限制 |
| 官方集成 | 10 条/秒 |
| 第三方插件 | 5 条/秒 |

### 9.3 内容审核

- 消息长度限制（如 200 字符）
- 禁止 HTML/脚本注入
- 敏感词过滤（可配置）

### 9.4 优先级保护

第三方插件**不能使用优先级 9-10**（保留给紧急事件）：

```cpp
bool IslandLocalServer::isAllowedPriority(const QString &source, int priority) {
    if (source == "star-control") return true;
    if (source == "campus-broadcast" && priority <= 10) return true;
    return priority <= 8;  // 第三方最高 8
}
```

## 十、典型生态场景

### 场景 1：上课铃响 + 老师讲话

```
ClassIsland 推送 lesson.start (优先级 6)
    ↓
星集控被控端推送 voice.active (优先级 8)
    ↓
灵动岛显示"老师正在讲话"（抢占）
    ↓
老师讲话结束，回落到"数学课开始"（3 秒后消失）
```

### 场景 2：紧急广播

```
校园广播系统推送 broadcast.emergency (优先级 10)
    ↓
灵动岛立即显示，持续显示直到手动关闭
    ↓
同时手机端推送通知给管理员
    ↓
所有其他消息排队等待
```

### 场景 3：考试模式 + ClassIsland

```
考试系统推送 exam.start (优先级 8)
    ↓
ClassIsland 推送 exam.scheduled (优先级 7)
    ↓
灵动岛合并显示："考试开始 · 数学 · 90 分钟"
    ↓
考试中，ClassIsland 的"下课铃"被抑制（考试模式优先）
```

## 十二、与 ClassIsland 的深度联动

前面单独讨论过 ClassIsland，这里从生态视角再明确一次：

| 联动方向 | 方式 |
|---|---|
| ClassIsland → 灵动岛 | 课表事件推送到灵动岛显示 |
| 星集控 → ClassIsland | 老师讲话、考试模式推送到 ClassIsland 悬浮岛 |
| 双向同步 | 双方共享一个"当前状态"，避免信息冲突 |

**优先级仲裁**：当 ClassIsland 和星集控同时要显示时，按优先级决定谁在前。老师讲话（8）> 上课铃（6）> 课表展示（4）。

## 十三、关键决策汇总

| 决策点 | 方案 |
|---|---|
| 定位 | 开放信息层，不是星集控专属 |
| 消息协议 | 统一 JSON 格式，含 source/type/priority |
| 接入方式 | 本地 WebSocket（推荐）+ 云端 API + Webhook |
| 插件体系 | manifest.json + 白名单 + 权限 |
| 优先级 | 1-10，第三方最高 8 |
| 频率限制 | 按来源分级 |
| 多端路由 | 同消息按端决定是否展示 |
| ClassIsland | 双向联动，优先级仲裁 |
| 安全 | 本地只监听 127.0.0.1，白名单，内容审核 |


**一句话总结**：灵动岛生态的核心是"开放 + 治理"——任何应用都能通过标准协议向灵动岛推送信息，但必须遵守优先级、频率、内容、来源的治理规则。ClassIsland 是第一个深度集成的合作伙伴，未来可以接入考试系统、校园广播、门禁、第三方插件。灵动岛从"星集控的功能"变成"教室屏幕顶部的开放信息层"，这是它最大的生态价值。
