# 灵动岛通用简单历史通知 — 设计

> 定位：灵动岛的“记忆层”。灵动岛显示“现在正在发生什么”，历史通知显示“刚才发生了什么”。简单、通用、不臃肿。

---

## 一、核心定位

| | 灵动岛 | 历史通知 |
|---|---|---|
| 时间 | 现在 | 过去 |
| 状态 | 进行中 / 刚发生 | 已结束 |
| 交互 | 可操作 | 只读（可跳转） |
| 生命周期 | 出现 → 消失 | 永久（直到清理） |
| 目的 | 让老师处理 | 让老师回顾 |

**一句话**：灵动岛是“待办”，历史通知是“已完成/已错过”。

---

## 二、通用性设计

历史通知不区分来源，**所有通知走同一套格式**：

```json
{
  "id": "uuid",
  "ts": 1696400000,
  "source": "star-control",
  "type": "command.lock",
  "icon": "🔒",
  "title": "锁屏完成：58 成功，2 失败",
  "category": "指令",
  "level": "info",
  "read": false,
  "ref": { "deviceIds": ["room-101", "room-102"] }
}
```

**字段说明**：

| 字段 | 说明 |
|---|---|
| `ts` | 发生时间 |
| `source` | 来源（star-control / classisland / exam / 第三方） |
| `type` | 类型（决定分类和跳转） |
| `icon` | 显示图标 |
| `title` | 一行摘要 |
| `category` | 分类（指令/告警/课表/消息/系统） |
| `level` | 级别（info / success / warning / error） |
| `read` | 是否已读 |
| `ref` | 关联对象（设备、事件），用于跳转 |

**通用性**：不管什么通知，都转成这个格式。灵动岛消失的通知自动进历史。

## 三、存储策略

### 3.1 内存 + 磁盘

```
内存：最近 100 条（快速访问）
磁盘：最近 1000 条（重启后保留）
```

内存满了自动刷到磁盘，磁盘满了删最旧的。

### 3.2 存储位置

- **Qt**：SQLite 本地库（`history.db`）
- **Web**：IndexedDB 或 localStorage
- **后端**：可选，多端同步时用

**第一版只存本地**，不做多端同步。简单优先。

### 3.3 自动清理

| 类型 | 保留期 |
|---|---|
| error / warning | 90 天 |
| 指令 / 消息 | 30 天 |
| 课表 / 系统 | 7 天 |
| info | 3 天 |

**规则**：超期自动删除，不通知用户。

## 四、UI 设计

### 4.1 入口

灵动岛收起态右侧显示一个**小图标 + 未读数**：

```
╭────────────────────────────────────╮
│  ⏳ 锁屏 42/60          🕐 3        │
╰────────────────────────────────────╯
```

- 时钟图标表示“历史”
- 数字表示**未读历史条数**
- 无未读时不显示数字
- 点击图标 → 打开历史面板

- 点击 → 跳转到相关页面（如设备列表）
- 右键 → 删除 / 标记已读

## 五、交互

### 5.1 打开与关闭

| 操作 | 行为 |
|---|---|
| 点击灵动岛历史图标 | 打开面板 |
| 点击面板外 | 关闭 |
| `Esc` | 关闭 |
| `Ctrl + H` | 打开/关闭 |

### 5.2 筛选

- 点击分类标签 → 只显示该分类
- 搜索框 → 按关键词过滤
- 支持 `source:classisland` 语法

### 5.3 批量操作

- 全部已读
- 清除全部
- 按分类清除

### 5.4 跳转

点击历史项，根据 `ref` 跳转：

| type | 跳转目标 |
|---|---|
| `command.lock` | 设备详情 |
| `alert.*` | 告警页 |
| `lesson.*` | 课表页（如果集成 ClassIsland） |
| `message.*` | 消息详情 |

**跳转后自动标记已读**。

## 六、与其他模块的关系

| 模块 | 关系 |
|---|---|
| 灵动岛 | 灵动岛消失的通知自动进历史 |
| 告警系统 | 告警是历史的一个子集，但告警额外有“未处理”状态 |
| 审计日志 | 审计是“所有操作的记录”，历史是“给用户看的摘要” |
| 手机推送 | 手机推送成功后，同步在历史里留一条 |

**关键区分**：
- 审计日志 = 完整的、不可删的、给管理员的
- 历史通知 = 摘要的、可清理的、给老师的
- 灵动岛 = 实时的、可操作的、给当下的

---

## 七、学生端的历史

学生端历史**极简**：

- 只保留最近 20 条
- 只保留 3 天
- 不可搜索
- 不可筛选
- 只显示“老师消息”和“学校通知”两类

**为什么**：学生不需要“回顾”，只需要“确认收到”。

                }

        // 列表

            Layout.fillWidth: true
            Layout.fillHeight: true

    Q_OBJECT

## 九、数据流

```
1. 通知产生（灵动岛 or 后端推送）
    ↓
2. 灵动岛显示
    ↓
3. 灵动岛消失（超时 / 用户关闭 / 状态结束）
    ↓
4. HistoryModel.add(notification)
    ↓
5. 写入内存 + SQLite
    ↓
6. 未读数 +1，灵动岛图标更新
```

**关键**：不是所有通知都进历史。**纯技术状态不进**（如心跳重连、更新下载）。

---

## 十、不进历史的内容

| 内容 | 原因 |
|---|---|
| 心跳发送 | 技术状态 |
| WebSocket 重连 | 技术状态 |
| 更新下载 | 静默进行 |
| 指令执行的中间进度 | 只记最终结果 |
| 灵动岛的实时进度 | 结束后才记 |

**原则**：历史只记“有意义的事件”，不是“所有事件”。

## 十二、一句话总结

灵动岛通用历史通知 = **灵动岛的“记忆层”**。所有通知走统一格式，灵动岛消失后自动进历史，按时间分组、按分类筛选、可搜索、可跳转。存储用 SQLite 本地库，自动清理，不做多端同步。学生端极简（只保留 3 天、20 条、两类）。核心原则：**历史只记有意义的事件，不是所有事件**。
