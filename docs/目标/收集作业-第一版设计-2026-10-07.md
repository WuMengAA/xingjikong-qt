# 星集控 · 文件分发-收集作业（第一版设计，2026-10-07）

> 对应《全量设计文档》3.4.1「收集学生作业（反向，后置）」。
> 现有文件分发是**老师 → 学生**（推送）；收集作业是**学生 → 老师**（回传）。

## 一、场景

老师下发作业任务 → 学生做完 → 教室机上交 → 老师端收到汇总（按设备/姓名分组）。

| 角色 | 动作 | 期望 |
|---|---|---|
| 老师 | 发起「收集作业」（指定目录/文件名规则） | 学生机出现"上交"入口 |
| 学生 | 把作业文件放进指定文件夹 → 点「上交」 | 文件传到老师端/云端 |
| 老师 | 收齐后查看 | 按设备分组列文件，可下载 |

## 二、技术方案（反向文件通道）

现有：老师推文件 = viewer 分片 `file_chunk` → 云端 → agent 收。
收集作业 = agent 分片 → 云端 → viewer 收（**复用同一分片协议，方向反转**）。

| 消息 | 方向 | 内容 |
|---|---|---|
| `collect.start` | 老师 → 云端 → 目标学生机 | `{taskId, dir, filenameRule, deadline}` |
| `collect.upload` | 学生机 → 云端 → 老师端 | 分片（复用 file_chunk 语义）+ 完成 |
| `collect.result` | 云端 → 老师端 | `{uid, fileName, bytes, sha256}` |

**存储（第一版）**：文件直接存**云端** `collects/<taskId>/<uid>/<文件>`；
老师端从云端下载（复用 `/recordings` 的静态托管模式）。

## 三、云端改动

- 复用现有文件上传能力：`/api/collects/upload`（学生机带设备令牌，类似
  `/api/recordings/upload`）+ `collects/` 静态托管。
- `collect.start`：记录任务（taskId → 目标 uid 列表）到内存。
- `collect.result`：汇总回执给老师端。

## 四、被控端改动

- 收到 `collect.start`：托盘/通知出现「上交作业」入口（显示目录 + 截止时间）。
- 学生点「上交」→ 扫描指定目录 → 分片上传（复用 file_chunk 分帧，方向反向）。
- 进度提示（Island：「正在上交 3 个文件」）。

## 五、管理端改动

- 集控页「收集作业」卡片：发起（任务名 + 目录规则 + 目标设备/班级 + 截止时间）。
- 查看：按任务 → 按设备列出已交文件（uid / 文件名 / 大小 / 时间），可下载。

## 六、边界

- **只收文本/常见文档**（.docx/.pdf/.txt/.md/.png 等白名单），禁可执行文件（同文件分发）。
- 大小限制：单文件默认 ≤ 50MB，可配置。
- 截止时间后禁止上交（第一版：被控端到点隐藏入口）。
- 不覆盖：学生机「上交」的文件只传不删（保留本地副本）。

## 七、开发顺序

1. 云端 collects 上传/列表/托管（复用 recordings 模式，快）
2. 被控端 collect.start 处理 + 分片上传（复用 file_chunk 帧）
3. 管理端收集卡片 + 下载
