## 二、修改的既有文件

### 1. `src/island.h`（灵动岛类声明）
- 新增 public：`setOpenPath(const QString&)` / `clearOpenPath()` / `openPath()`。
- 新增 private：`openInShell()`、`hitOpenButton(const QPoint&)`。

### 2. `src/island.cpp`（灵动岛实现，本轮改动最集中）

| 改动 | 为什么 |
|---|---|
| 图标绘制 `QRect(x, rect().top(), 26, height())` → 固定行高 **30** | 展开态高度 168 ⇒ 图标被画到左下角（截图实锤"掉底"） |
| 收起态描述：固定 `x+110` 起、110px 宽、右对齐 → 按**剩余宽度** `ElideRight` 紧跟标题 | 胶囊只有两三百宽时「正在自动重连…」被裁成「连...」再省成「…」，等于没提示 |
| 淡入淡出：`m_fadeAnim` 显式 `setStartValue/setEndValue`（dismiss→0.0，show→1.0），且 **stop → 设起止 → Forward → start** 的顺序 | ⚠️ 严重 bug，见下"自查抓到的错"③ |
| 新增 `m_dismissGuard`（600ms 单发 timer）兜底 `hide()` | 淡出动画万一没发 `finished`，胶囊也不能赖在屏上 |
| `showIsland` 自动关闭条件 `!(m_interactive && m_expanded)` → `!m_interactive` | 交互态但还收着时 6 秒自己消失，用户根本来不及点 |
| `setInteractive(false)` 时补启动自动关闭 | 从可点切回纯展示，这条若还在屏上就得定个消失时间 |
| `mousePressEvent` 分区：岛体只展开/收起；右边缘 44px「▸ 打开」区才 `openInShell()` | 见下"自查抓到的错"④ |
| 新增 `openInShell()`：`explorer.exe /select,"<绝对路径>"` | 只"定位到文件"。**不用 `QDesktopServices::openPath(文件)`**——Windows 上是 ShellExecute 打开，`.exe` 直接被跑，被控端是学生机、下发内容不能这么担保 |

## 六、明确声明「没验证的部分」

1. **没起过被控端本体进程**（用户明令"本机不开刀"）。所以：
   `NotifyWindow` 淡入淡出的**实际观感**、`file_push` 端到端（真实指令下发 → 岛弹出）、
   考试模式起止的岛文案，都**只做了代码级接线 + 组件级取证**，没有整机跑过。
2. **`trayNotify()` 的托盘气泡**没真机拍到（探针不链 main.cpp、没有托盘）。代码路径与 `notify` Popup 那条复用同一套 `showMessage`，风险低但**未验证**。
3. **`openInShell()` 会真的起 explorer `/select,`** —— 本轮**没有模拟点击**去触发（探针窗口躺桌面顶部中央，模拟点击容易被真实鼠标干扰）。命中区是纯几何判断（`rect().right()-16` 起 44px），未做点击型验证。
4. **岛的深浅色**：`setLightMode` 在 main.cpp 里**仍然没被调用**；岛只在构造时读一次系统 `colorScheme()`，之后系统换主题不跟着变。而 `NotifyWindow` 是固定深色 —— 系统浅色时两者风格会不一致。**这是本轮发现但没动的问题**，按"顺带发现只报清单"的规矩，等点单。
5. 被控端 `main.cpp:2076-2078` 通知窗 `show/raise/activateWindow` + `:1966 Qt::Tool` + `:2071 重摆正中`（前轮定位的"桌面乱蹦真元凶"）**本轮未动**，仍等点单。

## 七、自查抓到的错（自己记账）

1. **`_island_probe.py --shot` 占位参数**：`--keep` 与 6 秒自动关闭的时间线交叉，一度把"岛自己关了"误判成 bug —— 实为**另一个残留探针进程** append 同一日志。修：日志打 `pid`，采样改成逐秒连续记录。
2. **`m_fadeAnim` 没设起止值**（最狠）：淡入淡出是假的（1.0→1.0），且 `dismiss()` 首行 `if (m_fadeAnim->state()==Running) return` **恒真**，导致 6 秒自动关闭和手动 `dismiss()` **双双失效**。这个 bug 靠截图看不出来，是逐秒时间线（t=3 还 visible，t=7 手动 dismiss 后仍 visible）逼出来的。
3. **交互态会被自动关**：原判据 `!(m_interactive && m_expanded)` 虽然看着为交互态留了活口，但只在"已展开"时留；收起态照样 6 秒跑掉，用户点都点不到。
4. **一道按下就弹资源管理器**：岛 StaysOnTop 且开了交互（收走鼠标穿透），压在课件上方，学生点课件会弹出 explorer。已改分区点击（岛体只展开）。
5. `qsnprintf` 那几行编译报错（`QLCoreApplication` 不是类 → 用 `qApp->applicationPid()`；`ev->position()` 是 `QPointF` → 用 `ev->pos()`；lambda 捕获 `isl` 要显式列进捕获列表）—— 都是取证脚本的编译问题，不是产品问题。

# 追加：空闲半胶囊 + 触控适配（同日第二轮）

## 新增行为
| 项 | 内容 |
|---|---|
| 空闲态 `Shape::Idle = 36` | 无任务/通知时收回顶部（y=10）显示一条 **120×36 半胶囊**，中央横杠 + 下向箭头 |
| 常驻 | 空闲态开启时 `dismiss()` **不再 hide，改 enterIdle()**；开机在托盘就绪后 `ensureIdle()` 常驻 |
| 开关 | `setIdleEnabled(false)` 或环境变量 `STE_QT_ISLAND_IDLE=0` ⇒ 退回"用完即隐"老行为 |
| 空闲可操作 | 点一下 / 下拉 24px 以上 ⇒ 展开；上推 ⇒ 收回。空闲时点展开且从无内容 ⇒ 占位文案「暂无进行中的通知 / 有新的动态会在这里提示」 |

## 触控适配（教室大屏多为触摸屏）
1. **动作从 press 挪到 release**：手指按下有肉眼不可见的抖动，原来"按下即展开/打开"，轻滑一下就被判成点击（表现为拉一下直接弹资源管理器）。现在 press 只记起点，release 才判定。
2. **新增 `mouseMoveEvent` 手势**：`|dy| >= kDragSlop(24px)` 才算拖拽，下拉展开 / 上推收起；发生过拖拽的 release **不再当点击**。
3. **命中区放宽**：`hitOpenButton()` 上下各 +8px；空闲胶囊整体可点（触控目标 ≥ 36px 高）。
4. **不用 `WA_AcceptTouchEvents`**：默认已把触点合成为鼠标事件，自己接管 QTouchEvent 只会多一层复杂度。
5. **不依赖 hover**：所有可点反馈都写在静态绘制里（「▸ 打开」常显），触屏没有悬停态。

## 交互细节修正
- 新增 `m_contentActive`：空闲态展开后上推 ⇒ **直接回半胶囊**（不再三段跳 展开→标题胶囊→空闲）；活动态展开上推 ⇒ 回标题胶囊（保留标题）。
- 浅色态前景不透明度 170 → 215（深色 190 → 225）：底色退让可以，符号不能跟着糊。

## 没验证的部分（追加）
1. 开机常驻那一步（main.cpp `ensureIdle()`）**只在探针里验证了 `ensureIdle()` 本身**，没有真的起被控端看开机效果（不开刀）。
2. 真实**触摸屏**上的手感（手指拖拽 vs 鼠标拖拽的差异）没条件验；手势逻辑是靠进程内合成鼠标事件验的。
3. 空闲胶囊**常驻后可交互** ⇒ 顶部中央 120×36 不再鼠标穿透。教室大屏上这块位置若正好压着课件按钮，会吃掉一次点击。若不可接受，把 `enterIdle()` 里 `setInteractive(true)` 改回 `false`（那样横杠箭头就只是装饰）。
