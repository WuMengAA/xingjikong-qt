# 字号与对比度 · 加减归档（0.6.14）

> 起因：用户报「**字体、对比度太小了**」。
> 原则：先量再改 —— 字号和对比度都是**数出来**的，不是看出来的。

---

## 一、量出来的现状（改之前）

### 字号分布（qml/Main.qml + qml/components/*.qml，共 123 处声明）

| 字号 | 处数 | 原定语义（UI 规范） |
|---|---|---|
| **11** | **65** | 「注」—— 最小档 |
| 12 | 39 | 「正」 |
| 13 | 12 | 「徽标」 |
| 14 | 2 | （规范外） |
| 15 | 2 | 「标题」 |
| **10** | **2** | **规范明写"没有这一档"** |
| 20 | 1 | 大数字 |

**问题**：规范定的最小档 `11` 恰恰是**用量最大的一档（65 处）** ⇒ 等于"最小档当了主档"。

### 文字对比度（WCAG 2.x 相对亮度公式，算出来的）

| 令牌 | 暗色旧值 | 对底 `win #0A0A0A` | 判定 |
|---|---|---|---|
| `fg3` 辅助文字（按钮字、说明） | `#5A5A5A` | **2.87:1** | ❌ 低于 AA 正文线 4.5:1 |
| `fg4` 最弱（离线设备名、禁用态） | `#3A3A3A` | **1.74:1** | ❌ 连大字号线 3:1 都不到 |
| `ph` 占位符 | `#4E4E4E` | **2.38:1** | ❌ |

`fg3` + `fg4` 合计 **65 处** —— 暗色下最常读的就是它们。

#### 2. `qml/components/Btn.qml`（**回归修复，重要**）

```diff
- color: btn.theme.fg3
+ color: btn.strong ? btn.theme.win : btn.theme.fg3
```

**为什么**：`strong`（反白）态是 `inv`（浅底 `#F0F0F0`）+ `fg3`（字）。
原来 `fg3 = #5A5A5A` 落在浅底上还有 **6.05:1**；把它提亮成 `#8A8A8A` 后
**掉到 2.95:1** —— 也就是说"提对比度"这个动作本身**会让反白按钮变糊**。
反白态的字必须跟着反转（用 `win` 近黑）—— 这才是稿子写的"`#F0F0F0` 底 + 黑字"。
修后：暗色 **17.4:1**、亮色 **16.1:1**。

#### 3. `qml/components/InputField.qml`

| 改动 | 为什么 |

| `colPh`：`th.fg4` → `th.ph` | 占位符借"最弱文字色"是语义错位；`ph` 此前是**死令牌（0 引用）**，现在归位 |

| `th: null` 时 `colFg` 等仍需可用 | 保持原设计 |

## 四、取舍与"没做的"

### 有意的取舍

1. **`fg4` 目标定 ≥ 4:1，不是 4.5:1。**
   它是"次要文字"（离线设备名、禁用态），需要与 `fg3`（5.73:1）**保持层次**。
   而且离线状态另有"圆点变暗"作为**第二编码**，不靠颜色单独承载关键信息。
2. **画面上那行"画面未变化 · 已暂停刷新"保持固定灰 `#8A8A8A`，不跟主题。**
   它浮在远程画面上，底色是对方桌面（不可控）—— 跟主题走反而可能在浅色画面上消失。
3. **不引第三方 UI 库 / 不改字体家族。**
   用户说"字体太小"，量出来是**字号档位**问题（最小档当主档），不是字体选型问题。
   改字体家族会整体改变字宽、牵动全部布局，收益不确定 —— 不做。

### 没验证的（如实说）

1. **真实观感**：离屏自检只能证明"能加载、无报错、布局数值正确"，
   **看不出"好不好看"**。字号抬一档后的实际阅读舒适度、对比度是否够，**需要您在真机上扫一眼**。
2. **亮色模式**：令牌两侧都改了，但**没有在亮色下真跑过**（默认 `darkMode: true`）。
   亮色改动是按同一套公式算的，逻辑上等价 —— 但属于"未运行时验证"。
3. **被控端的 stderr 改动**：已编译通过、已与两端同步，
   但**没有真的触发过"双开"场景**去看那行中文是否正常（要开两个实例才能触发）。
4. **`Card` / `EmptyState` 仍是 0 引用**（页面里手写卡片/空态）—— 本轮没动，见 UI 规范「下一步」。
