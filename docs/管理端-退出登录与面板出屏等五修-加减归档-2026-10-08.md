## 三、修改的既有文件

### 3.1 `src/viewerbackend.h`
| 改动 | 为什么 |
|---|---|
| 新增 `Q_PROPERTY(QString frameUid … NOTIFY frameChanged)` + `frameUid()` + `m_frameUid` | 每帧记"这张画面属于哪台设备"。切换设备后旧帧还在路上，不记归属就没法判"这张该不该上屏" |
| 新增 `Q_PROPERTY(int onlineCount … NOTIFY devicesChanged)` + `onlineCount()` | 设备表现在含**离线**条目，`devices.length` 是"我知道几台"而不是"在线几台"，顶栏会虚高 |
| 新增 `QHash<QString, QJsonObject> m_devLedger` + `kLedgerKeepMs`(24h) | 设备台账（见 3.2 refreshDevices） |

### 3.2 `src/viewerbackend.cpp`
| 位置 | 改了什么 | 为什么 |
|---|---|---|
| `setCurrentUid()` | 切换时**先 `unsubscribe` 上一台**；再作废旧画面（`m_frameUid` 清空、`m_frame` 清空、静态判定复位、`emit frameChanged/statsChanged`） | 云端 `subscribeViewer` 只 `v.subs.add()`、**从不替我们取消**；被控端是"有人看才抓屏发帧" ⇒ 不退订，旧设备一直发帧，两台的帧写同一个 `m_frame` ⇒ 「切换只显示第一台」。旧画面不撤掉的话，新设备第一帧到之前屏幕上还挂着上一台的桌面（老师照着旧画面操作新机器＝事故） |
| `applyFrameBytes()` | 开头**按 uid 分诊**：非当前设备且非缩略图 ⇒ 丢弃；缩略图 ⇒ 只写缩略图槽后 return（**不再写 `m_frame`**）；接受主帧时记 `m_frameUid` | 同上的第二半；另外原来缩略图帧会覆盖主画面（多班面板一开主画面就在几台之间乱跳） |
| `refreshDevices()` | 新增**设备台账**：把云端这批在线设备记进 `m_devLedger`（`online=true` + `lastSeenAt`）；云端表里消失的记为 `online=false` + `lastSeenAgoSec`；24h 过期清理 + 上限 200；组装成"在线在前、离线按最近掉线在后"的 `m_devices` 下发 | 云端 `listDevices()` 只列当前连着的（`online` 还写死 true）；而界面早就按"有台账"写好了（离线筛选/状态点/`offlineDevices()` 告警/批量把离线直判失败）⇒ 那些功能恒等于空 |
| `onlineCount()` | 新增 | 见 3.1 |
| `refreshAccountText()` | 结尾改成**无条件** `emit accountChanged()` | 原实现"文案没变就不发信号"，但 `accountChanged` 还驱动 `loggedIn`/`accountName`/菜单显示哪一组（登录组 vs 退出组）。**退出登录后文案恰好还是"未登录…"（没变）⇒ 信号不发 ⇒ 菜单不切组** ⇒ 用户看到"点了退出登录，还是登录着" |
| `forgetAccount()` | 完整收口：停重连（`m_retryStopped`）、清鉴权失败态、清空设备表**与台账**、清 `currentUid`/`frameUid`/`m_frame`、关闭 WS、`authed=false`、**本次会话内作废静态令牌**（仅在配了站点地址时，老机器纯静态令牌不能作废）、写清状态与日志、`refreshGateState()` | 原来只 `clearAccount()`：socket 还挂着（界面继续显示设备表、继续能下指令）、重连逻辑还在转 ⇒ "点了退出却还在用" |
| `onDisconnected()` | 无凭据时（= 刚退出登录）说"已退出登录"，不再套用"云端鉴权失败，已停止重连：" | 退出登录被报成鉴权失败会误导用户去改配置 |
| `onTextMessage()` `auth-fail` 分支 | 票被云端拒时：**若本机还有网站会话 ⇒ 静默去站点换一张新票并重连**；没有会话才提示重新登录 | 票（云端 30 天）和网站会话（站点 30 天）是两样东西，票废了会话往往还好着 ⇒ 这就是「过期后无法自动登录」 |
| `onTextMessage()` `AU1002/AU1003` 分支 | 同上（云端说"票过期/无效"时先尝试静默换票） | 同上 |
| 头文件 | `#include <algorithm>` | 台账清理用 `std::sort` |

### 3.3 `src/main.cpp`
| 改动 | 为什么 |
|---|---|
| 新增 `fitWindowToScreen(QWindow*)`：**先**放宽窗口最小尺寸（否则 `setGeometry` 被 minimumSize 顶回去），**再**夹尺寸、夹位置 | 小屏上窗口比可用区还大 ⇒ 底部标签栏被切在屏幕外；插拔投影后窗口坐标可能留在已不存在的屏幕上 ⇒ 点托盘也叫不回来 |
| 四处调用：`engine.load()` 之后、首帧 `frameSwapped`、700ms 定时、托盘唤回时 | **只夹一次不够**：`engine.load()` 返回时 Qt 还没把 QML 请求的尺寸应用到窗口（加了诊断日志后实测：那一次调用"看起来不用夹"，紧接着窗口才被撑大） |
| 新增 includes：`<QScreen>`、`<QGuiApplication>`、`<QQuickWindow>`、`<memory>` | 同上 |

### 3.4 `qml/Main.qml`
| 改动 | 为什么 |
|---|---|
| 新增 `readonly property bool frameReady: backend.frameCount > 0 && backend.frameUid === backend.currentUid`；画面 `source` 由它门控；空态 `visible: !root.frameReady` 且文案分"正在接入这台机器" | 切换设备后旧帧不能冒充新设备 |
| 静态角标 `visible` 改用 `root.frameReady` | 同上 |
| **右栏动作区包进 `Flickable`**（`contentHeight: rightCol.implicitHeight`，内层 `ColumnLayout` 去掉 `Layout.*`、宽自己写） | 原来它是固定高度的一列，装不下只会溢出到窗口外 ⇒ 窗口没法压矮。代码里本来就有注释写着"下次该改成可滚动" |
| `width/height/minimumWidth/minimumHeight`：1180x760 / 940x680 ⇒ 1180x700 / 940x600 | 1280x720 屏 + 标题栏 + 任务栏只剩约 649px，760/680 必被切 |
| 三处计数改用 `backend.onlineCount`（顶栏「N 台在线」、概览"在线"、左栏卡片标题） | 设备表现在含离线条目 |
| `selectAll()` / `runOnPicked("")`（全部在线）只取 `online !== false` | 把离线机器一起发过去只会换回一串注定失败的回执，账面上像"下发失败" |

### 3.5 `qml/components/AccountMenu.qml`
| 改动 | 为什么 |
|---|---|
| 删掉 `anchorGlobal/overlayGlobal/ax/ay/avW/avH/wantH` 与基于它们的 `x/y/height` 绑定 | **前两次修都栽在这里**：绑定只求值一次并缓存，而 `Overlay.overlay` 在弹窗打开前是 `null` |
| 新增 `function place()`（每次打开现算）+ `Popup { parent: hostLayer }` + `toggle()` 先 `place()` 再 `open()` | **真根因**：不显式给父层时，Popup 落在"声明处"的坐标空间 = 顶栏那一格（150x28）。探针实测 `parent=AccountMenu_QMLTYPE_63`、`Overlay.overlay === null` ⇒ x=926 被当成"胶囊右边 926px" ⇒ 菜单被摆到窗口外 1900px，**一个像素都没画出来**（而 `visible/opened` 全是 true、日志一片正常）。`hostLayer` 是铺满窗口、z=9990 的 `acctLayer`，挂在它上面 x/y 天然就是窗口坐标 |

## 五、明确**没验证**的部分

1. **退出登录的鼠标实点**：合成 `PostMessage` 的鼠标消息进不到 Qt Quick 的 Popup（实测点了没反应），
   而真实输入注入（`SendInput`）会移动用户的鼠标指针 —— 按"不动桌面"的纪律**没做**。
   已验到的是：菜单可达（抓图）+ 后端逻辑闭环（代码级）。**"点一下真的退出"需要人在真机上点一次。**
2. **切设备的端到端**：需要两台在线设备且不跑生产进程 ⇒ 本轮只做了代码级修复。
   日志判据已埋好（`丢掉非当前设备（uid）的帧 N 张`、`退订上一台 …`），现场复现时一眼能确认。
3. **离线台账的真掉线**：没制造断电/断网场景。台账是**进程内内存态**，重启后从空开始重建
   （没有做持久化 —— 判断为不需要；如果希望"重启也记得上周有哪几台"，需要另加落盘）。
4. **窗口"底部被切"这一现象**：用户在我取证期间把显示改成了 2560x1440（Qt 逻辑区 1707x960），
   当前窗口已能装下 ⇒ 本机此刻**不复现**。修法是防御性的（1280x720/1366x768 那类屏必现），
   没有在真·小屏上复拍过。
5. **OTA 未发布**：见第六节，等用户决定。
