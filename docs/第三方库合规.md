# 星集控 · 第三方库合规（2026-10-07 首版）

> 对应《全量设计文档》10.3「第三方库合规」—— MIT 开源项目用了 GPL 库会毁掉整个项目，必须逐项登记。

## 一、原则

1. **许可兼容**：项目目标是 MIT 开源。所有第三方依赖必须**许可兼容**（MIT / BSD / Apache-2.0 / LGPL 有条件可用）。
   **GPL/AGPL 传染性许可的库一律禁止**（除非整体改 GPL，那等于放弃开源）。
2. **逐项登记**：新引入任何依赖，先查许可，再进下表。
3. **Qt 例外说明**：Qt 本身是 **LGPL-3.0 / GPL-3.0 / 商业** 三重许可。
   本项目**静态链接** Qt —— 按 LGPL 条款，必须以可再分发形式提供 Qt 库文件
   （绿色包里本来就带着全部 Qt DLL，满足 LGPL 第 4 条"允许用户替换库"的要求）。
   若转商业闭源，需购买 Qt 商业许可。

## 二、依赖清单（逐项核验）

### Node.js（云端 + 管理端工具链）

| 包 | 版本 | 许可 | 用途 | 核验 |
|---|---|---|---|---|
| ws | 8.22.0 | **MIT** | 云端 WebSocket 服务；被控端/管理端打包时用的 ws 客户端 | ✅ 兼容（2026-10-07 查 package.json license 字段） |

云端 `package.json` dependencies 仅 ws 一项；`node_modules/ws/LICENSE` 为 MIT 全文。
**npm 传递依赖**：ws 无运行时依赖（纯实现），无传递链。

| FFmpeg（GPL/LGPL 双许可） | 若用 GPL 构建则传染；若用 LGPL 需动态链接 + 逐项确认编译选项。**第一版录制功能明确不用 FFmpeg**（设计文档 3.6 的录制方案后置，实现时先做许可评审） |

## 三、新依赖引入流程（强制）

1. 查许可（npm view <pkg> license / GitHub LICENSE 文件），**不是** README 里说的。
2. GPL/AGPL → 直接否（除非用户明确同意整体改 GPL）。
3. 兼容许可 → 加入本表 + commit message 注明「新增依赖 <pkg>@<ver>，许可 <X>」。
4. 静态链接 LGPL（Qt）→ 确认分发物携带对应 .dll / .so。

## 四、检查清单（发版前）

- [ ] `package.json` 的每个 dependencies 都在本表登记
- [ ] node_modules 里没有 GPL/AGPL 包（`npm ls --prod` 抽查）
- [ ] Qt 绿色包携带 Qt DLL（LGPL 再分发要求）
- [ ] 新增 C++ 库已登记（libopus 等用之前先写进来）
