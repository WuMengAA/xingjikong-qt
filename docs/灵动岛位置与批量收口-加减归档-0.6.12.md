# 加减归档 · 灵动岛锚点 + 输入框绑定循环 + 批量收口（管理端 0.6.12）

日期：2026-10-07
版本：0.6.11 → 0.6.12
触发：真机截图 —— 灵动岛展开面板**贴在左上角盖住左栏**，且写着「通知 0/1」不动。
排查中又抓到 0.6.11 自己引入的一个回归（输入框主题绑定循环）。

---

## 一、灵动岛 / Toast 跑到左上角（截图那个现象）

**根因：锚点写在了 `root` 上，而 `ApplicationWindow` 不是 `Item`。**

```qml
Item {
    anchors.top: root.top                       // ← root 是 ApplicationWindow（Window）
    anchors.horizontalCenter: root.horizontalCenter   // ← Window 没有 horizontalCenter
```

`Window` / `ApplicationWindow` 继承自 `QWindow`，**不是 Item**，没有 anchors 体系、也没有 `horizontalCenter`。
于是这个锚点赋了个 undefined，**静默失效**（不报错、不打印），Item 就退回默认位置：x=0。表现就是截图里那样，
面板从窗口最左边开始长，正好压在左栏的按钮上。

**改**：锚 `parent`（ApplicationWindow 的直接子项会进 `contentItem`，它是 Item）：

- 灵动岛容器：`anchors.top: parent.top` + `anchors.horizontalCenter: parent.horizontalCenter`
- 全局 Toast：`anchors.bottom: parent.bottom` + `anchors.horizontalCenter: parent.horizontalCenter`

**实测证据**（临时探针，跑完已摘掉）：`PROBE island x=590 y=52 w=0 parentW=1180 rootW=1180 | toast x=576 w=28`
—— 590 正是 1180 的中点（宽度为 0 时居中于中心线）。修前这里是 `x=0`。

## 二、输入框主题绑定成了自己（0.6.11 的回归）

0.6.11 抽 `InputField` 时，调用点写的是 `th: th`。QML 绑定表达式的右值先在**组件实例自己的作用域**里找，
`th` 恰好就是 InputField 自己声明的属性 ⇒ **自己绑自己**，真机日志刷 7 条：

```
QML InputField: Binding loop detected for property "th"
```

后果是 `th` 一直是 null，组件退回内置的一组暗色兜底色 —— **亮色外观下文字色仍会是近白**
（等于 0.6.11 那件事没真正修完）。

**改**：6 处（Main.qml）改为 `th: root.th`（明确限定作用域）。
`CommandPalette.qml` 那处本来就是 `th: pal.theme`，不受影响。

## 三、批量下发「0/1」永远不动

截图里灵动岛写着「通知 0/1」且不消失。链路是这样断的：

- `batchStart(label, total)` 把 `batch.active = true`，灵动岛据此显示 `done/total`；
- 只有**收到回执**（`Connections.onResultReceived`）才会 `batchStep()` 推进；
- 而当时顶部写着「0 台在线」—— **设备早就离线了**。`sendAction()` 只检查 `currentUid` 非空、
  不检查在线，指令发出去、云端没人接、一个回执都不会来 ⇒ `done` 永远是 0，
  灵动岛永远亮着「0/1」。

**两处补齐（4.5「结果汇总」该有的收口）：**

1. **离线的当场结账**：下发前用 `root.isDevOnline(uid)`（认云端 `online` 字段）过一遍，
   不在线的**不发**，直接 `batchStep(uid, false, "设备不在线")`；toast 改报「已下发 N 台，M 台不在线」。
   `runOnPicked`（锁屏/关机）与通知按钮两条路径都改了。
2. **整体超时兜底**：新增窗口层 `Timer { id: batchTimeout }`，`batchStart` 时按台数给 10s~60s
   （每台 4 秒，[10s, 60s] 夹取），每 `batchStep` 一次就重推；到点仍没齐 → `batchTimeoutClose()`
   把剩余算失败、`active=false`，并 toast「等超时了，N 台确认，M 台没回话（多半是掉线）」。

## 四、过程中的一次事故（如实记）

摘除临时探针时，脚本用 `s.find('        Timer {')` 找起点 —— 匹配到了**文件里第一个 8 空格缩进的 Timer**
（不是探针那个），一路切到 `onTriggered: console.log` 之后，**删掉了中间 1000 多行**（2565 → 1557 行）。

处置：坏文件备份到 `.workbuddy/Main.qml.broken` → `git checkout -- qml/Main.qml` 回到 0.6.11 提交 →
用一份**锚点字符串 + 行号双重定位**的补丁重做全部改动（本次三处修改都是脚本化的，可重现）。
教训：**删除区间必须先确认起点唯一**，别用"第一个匹配"当锚。
