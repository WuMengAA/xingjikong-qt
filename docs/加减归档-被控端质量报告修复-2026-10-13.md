## ② 修改的既有文件（13 个）

### P0

**`src/audio_player.h` / `audio_player.cpp`（A1 · 音频每帧 reset 撕裂）**
- **旧**：单缓冲 `m_buffer`；`write()` 每帧先 `waveOutReset()` 停掉正在播的上一帧，再 `waveOutWrite()`。
- **新**：8 槽轮转（`kSlots=8`）。每槽独立 `WAVEHDR m_hdrs[i]` + 独立 `QByteArray m_bufs[i]`；`write()` 从轮转起点找**空闲槽**（`!(dwFlags & WHDR_INQUEUE)`），若该槽有旧 PREPARED 先 unprepare → 深拷贝 PCM → prepare → write；**全槽在播则丢这一帧**（语音实时优先，不阻塞、不积压）。`closePlayer()` 遍历所有槽 unprepare。
- **行为差异**：① 不再砍上一帧尾巴 ⇒ 消除必然出现的周期性「咔咔」；② 不再有「QByteArray 重分配」与「驱动异步读同一块内存」的争用；③ 主线程不再每 20ms 做一次同步 `waveOutReset`。

**`src/exam_mode.cpp`（A8 · 黑名单杀进程 fork 子进程）**
- **旧**：`killBlacklisted()` 每轮 `QProcess` fork `tasklist.exe`（解析 CSV）拿进程表；每个黑名单进程再 fork 一次 `taskkill.exe`，`waitForFinished(1000)` 阻塞主线程。
- **新**：`CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS)` + `Process32FirstW/NextW` 枚举（`PROCESSENTRY32W`，`fromWCharArray` 取名字，仍过 `normalizeProcName`）；杀进程用 `OpenProcess(PROCESS_TERMINATE | PROCESS_QUERY_LIMITED_INFORMATION)` + `TerminateProcess`。**零 fork**。新增 `#include <tlhelp32.h>`。
- **保留**：三重内核闸门（`processIsUntouchable` + `NtQueryInformationProcess` Session 查询）与「打不开句柄＝按保护放过」的保守策略，一格未动。
- **行为差异**：① 不再每秒级 fork 子进程（60 台机同时跑不再打 CPU）；② 不再阻塞主线程；③ 终止失败按「保护」处理、不重试并记错误码。

### P1 / P2

**`src/main.cpp`（A4 · `markTerminalDone` 失败降级）**
- `qInfo(...)` → `qWarning(...)`，文案改「重启后可能重复执行」。
- **行为差异**：落盘失败在监控里从「普通信息」升为「警告」。⚠️ 报告建议的「回执带 `persisted:false`」与「写备用位置」**未做**（见 ⑦）。

**`src/main.cpp`（A5 · `sendHeartbeat` 的假 try/catch）**
- 删除 `try { g_ws->ping(); } catch (...) {...}`，改为直接 `g_ws->ping();` + 说明注释。
- ⚠️ **报告此处有误**：`QWebSocket::ping()`（Qt 6.12，`qwebsocket.h:112`）签名是 **`void`**，不存在「返回值被忽略」。真正的问题只是「try/catch 掩盖了 ping 不抛异常、也不返回状态」这一事实。行为差异：无功能变化，只去掉误导代码。

**`src/terminal_console.cpp`（A6 · `qPrintable` 悬空指针）**
- `qWarning("...%s", qPrintable(err ? *err : QString()))` → `qWarning().noquote() << "..." << (err ? *err : QStringLiteral("已有会话"))`。
- **行为差异**：不再对临时 `QString` 取裸指针。

**`src/oauthbind.cpp`（A7 · CSRF state 弱随机）**
- `std::srand(std::time ^ &randomHex)` + `std::rand()%16` → `QRandomGenerator::system()->generate()`（Windows 走 `BCryptGenRandom`）；新增 `#include <QRandomGenerator>`。
- **行为差异**：state 不可预测（原来种子含秒级 time，搜索空间极小）。
- ⚠️ 同款 bug 在**管理端 `oauthlogin.cpp` 也有一份**（报告原话），**不在本次范围**（只改被控端），登记。

**`src/main.cpp`（A9 · `captureAndSend` 空转 timer）**
- **旧**：无条件 `QTimer timer; connect(...); timer.start(kFrameIntervalMs);`，而 `captureAndSend` 第一件事就是判 `STE_ENABLE_WS_FRAME_PUSH`（默认关）⇒ 每 2s 空转。
- **新**：启动时判定一次，只有 `STE_ENABLE_WS_FRAME_PUSH=1` 才 `new QTimer(&app)`；`QMetaObject::invokeMethod` 的「立即触发首帧」改判 `frameTimer` 非空。
- **行为差异**：默认不再每 2s 唤醒事件循环。

**`src/island.cpp`（A10 · `setEnabled` API 混用）**
- 删 `m_quick->setEnabled(on || !m_idle)`，只保留 `m_quick->setAttribute(Qt::WA_TransparentForMouseEvents, !on)`。
- **行为差异**：不再让 QQuickWidget 走「禁用态」渲染/停更；穿透语义单一化（精确可点区仍由 QML `MouseArea.enabled` 管）。

**`src/schedule_clock.h` / `schedule_clock.cpp`（B4 · 函数级 static 状态）**
- `static QDate s_builtFor`（`tick()` 内）→ 成员 `QDate m_builtFor`。
- **行为差异**：多实例不再互相干扰；状态可被测试重置。

**`src/noise_monitor.h` / `noise_monitor.cpp`（B5 · 抢全局线程池）**
- `QThreadPool::globalInstance()->start(...)` → 成员专用池 `m_pool`（`setMaxThreadCount(1)`）；新增 `#include <QThreadPool>`。
- **行为差异**：噪音采集独占一个后台线程，不再和摄像头抓拍/录制抢全局池。

**`src/system_volume.cpp`（B6 · COM `S_FALSE` 判断错）**
- `const bool needUninit = SUCCEEDED(hr);` → `const bool needUninit = (hr == S_OK);`。
- **行为差异**：`S_FALSE`（本线程已初始化过 COM）时**不再**调用 `CoUninitialize`，避免多减引用计数拖崩其它 COM 使用者。`RPC_E_CHANGED_MODE` 归一逻辑保留。

**`src/whale_audio.cpp`（C1 · 临时文件不随版本更新）**
- 临时文件名 `stelarith_whale_<basename>.wav` → `stelarith_whale_v<applicationVersion>_<basename>.wav`。
- **行为差异**：升级后 qrc 里的 wav 变了会重新落地（原来「存在就复用」⇒ 永远播旧版）。依赖调用方设了 `applicationVersion`（被控端＝`kAppVersion`）。

**`src/main.cpp`（C2 · 非 JSON 文本静默丢弃）**
- `qInfo("[agent-qt] 收到云端文本（非 JSON）：%s", ...)` → `qWarning("...（非 JSON，疑似协议不匹配）...")`。
- **行为差异**：协议不匹配在日志里更醒目。

**`src/notification_gate.h`（C5 · 未用参数）**
- `bool allow(Kind k) const { return !m_examActive; }` → 加 `Q_UNUSED(k);` + 注释说明「有意未参与判定，预留按 Kind 精细放行」。
- **行为差异**：无功能变化。
