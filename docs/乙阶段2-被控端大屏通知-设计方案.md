## 一、要解决什么

CIMS 退伍后，教室大屏通知目前**只通 CIMS**（站点广播 → CIMS command_queue → ClassIsland 插件渲染）。
停 CIMS = 大屏广播断。乙-2 的目标：**被控端（stelarith-agent-qt）自己渲染大屏通知**，
广播改走云端 WS 指令通道（`POST /api/instructions {action:"notify"}`），彻底脱离 CIMS。

## 二、权威依据（对齐现成契约，不发明形态）

三种通知形态是 CIMS 时代就定义好的，载荷结构已在站点广播里定型：

| 形态 | action（stelarith_task） | 语义（旧插件实现） |
|---|---|---|
| **popup** | `popup_notice` | 一行大字遮罩（标题：正文合并），随长度自适应字号 |
| **island** | `island_notice` | 课表岛滚动条（内容滚动浮层） |
| **fullscreen** | `fullscreen_notice` | 全屏紧急遮罩（同样一行大字，更强调） |

旧插件渲染（已实测取证）：
- 「标题：正文」合并为一行，无正文仅标题；字号随长度自适应（BuildSingleLineFontSize）
- 时长：显式 `DurationSeconds`（0~3600）严格照用；未指定 = 默认 5s，长内容抬高下限（2.5 + 字数×0.12）
- 请求级 flag：语音播报 / 特效 / 声音 / 置顶（载荷 flags 控制）
- 同内容 30s 去重 + 短时限频（防止轮询错误刷屏）

## 三、载荷契约（站点广播已定型，agent 对齐解析）

```json
{ "action": "notify",
  "params": {
    "kind": "popup" | "island" | "fullscreen",
    "title": "通知标题",
    "content": "正文（可空）",
    "seconds": 10,            // 0~3600；缺省 = 自适应
    "notice_id": 57,          // 回执对账用（回执要带它）
    "flags": { "speech": true, "sound": false, "topmost": true, "effect": false }
  } }
```

> 注：云端 `sendInstruction` 已通用转发任何 action（离线返回 offline 不谎报），
> **云端零改动**。只加一道"action 校验"白名单可选（防乱发）。

## 四、agent 侧实现（Qt Widgets）

### 4.1 executeAction 加 `notify` 分支

```cpp
if (action == "notify") {
    // 解析 params：kind/title/content/seconds/notice_id/flags
    // 构造 NotifyWindow（见 4.2），show() 后按秒数自动关闭
    // 回执：done（显示了）/ failed（解析失败或窗口打不开）
}
```

### 4.2 NotifyWindow（大屏通知窗口）

- **QWidget，无边框 + 置顶**：`setWindowFlags(Qt::FramelessWindowHint | Qt::WindowStaysOnTopHint | Qt::Tool)`
- **全屏尺寸**：popup/fullscreen 覆盖整个工作区（`screen()->geometry()`，多屏取主屏或远程指定屏）
- **渲染**：一个 `QLabel`（居中、大字、加粗、单行不换行超长省略）——复刻旧插件"一行大字"形态
- **island 形态**：顶部细条滚动（QLabel 横向滚动动画），非全屏遮罩
- **字体自适应**：长度 → 字号（短则大字，长则缩小，同旧插件逻辑）
- **时长**：QTimer 到点自动 close（0 则用自适应公式）
- **去重/限频**：进程内 key（title+content）30s 去重 + 最短间隔，与旧插件一致
- **多实例安全**：新通知顶掉旧窗口（同一时间只一个），防止堆叠

### 4.3 回执

显示成功 → 回执 `{ok:true, result:"done", detail:"notify 已显示"}`；
解析失败/打不开 → `failed`（绝不报 done 其实没做——铁律）。

### 4.4 与云端/站点的闭环

```
站点 broadcast.ts → POST 云端 /api/instructions {uid, action:"notify", params}
  → 云端 sendInstruction（在线才发，落盘+回执配对）
  → agent executeAction("notify") → NotifyWindow 显示 → 回执 done
  → 云端 recordResult → 站点回执聚合（notice_deliveries）
```

## 六、验证方案

1. **dev 链路**：agent 连 dev 云端 → 站点广播测试通知 → agent 弹窗 → 回执 done → 站点回执表有记录
2. **负向**：agent 未实现前收到 notify → "未知指令" failed（fail-safe，不崩）
3. **形态**：popup/island/fullscreen 各发一条，截图验证渲染
4. **时长**：显式 seconds vs 自适应，确认到点自动关
5. **去重**：同内容 30s 内两条 → 只弹一条
