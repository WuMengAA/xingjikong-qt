# 学习笔记 · ClassIsland 2.1.0 设计对标（2026-10-17）

> 用户给了 9 张 ClassIsland 2.1.0.1 运行截图（顶栏岛、组件库、外观、更新、插件页、基本设置、关于页），要求「学习」。
> 本文是**借鉴清单与判断**，不是改动点单——哪些要做、何时做，等用户逐条拍板。

## 一、样本里最值得学的 6 件事

### 1. 顶栏岛 = 一屏多信息位，且「预告」占了独立位
截图顶栏从左到右：节日/活动倒计时（红色强调"还有 0 天"）→ 天气（文案+温度+多图标）→ 日期+周次+单双周 → 大号时钟 → **「明天」课程预告（下节课"自化物"）**。
- 我们的岛目前是"单通知"语义（一条通知 + 历史），概览面信息位远没这么密。
- **可借鉴点 A**：「下节课/明天课程」预告位——课表数据我们插件已有（StelarithControlPlugin 做了课表同步），岛端只差一个展示位。
- **可借鉴点 B**：周次换算（"第 7 周 单周"）——以"学期开始时间"为锚点换算周次与单双周，配合多周轮换课表。我们课表同步若还没做周次维度，这里是现成口径。
- **可借鉴点 C**：倒计时置顶 + 颜色强调（红色"0 天"）——重要事件的紧迫感表达。

### 2. 组件库 + 四种容器 = 组合式编排思维
组件库里除了原子组件（时钟/天气/课程表/倒计时/正在播放/实时歌词），还有**滚动容器、分组容器、轮播容器、堆叠容器**四种容器，用户可以拖拽自由组合。
- 我们的 UiRegistry/UiPanelHost 是**面板级**声明化（14 面板单一真源），还没有"原子组件 + 容器编排"这一层。
- 判断：**短期不必学**——我们的定位是集控受控端，界面由管理端统一下发（facesOn/facePanelOn 已有），自由编排反而破坏集控一致性。**但"轮播/堆叠"两个容器语义**值得记：岛面信息位不够时轮播切换，比堆密度更符合"灵动岛"小面积现实。

### 3. 外观全参数化
界面缩放、背景颜色/不透明度、**圆角半径（滑到最大即半圆）**、行间隔、分体主界面、主题（明亮/跟随系统）、自定义字体（默认 HarmonyOS Sans SC）。
- 我们岛已有 G2 超椭圆六档圆角（Canvas + C++ 同口径），是"固定设计"；他们是"用户可调"。
- 可借鉴点 D：把圆角档位/主题做成**管理端下发的外观参数**（不是端上自由调），集控场景下由老师统一配置。字号线索也值得记：HarmonyOS Sans 教室机覆盖良好（我们踩过教室机 CJK/符号 tofu 的坑，`SvgIcon`/单字汉字是现行解）。

### 4. 更新体系与我们 OTA 对照
他们的更新设置：更新模式（自动检查并安装）、**更新通道（稳定通道）**、**强制检查更新（即使此版本比当前版本更旧也更新）**。
- 我们：ota.json（UTF-8 无 BOM）+ mandatory + 空闲≥10min 自动装 + otaSelfCheck 周期复查——**"自动安装"已对齐**。
- 差距两条：① **通道概念**（stable/beta 双通道）我们没有，现在只有"stable 必须 bump 后发"；② **强制降级**（比当前旧也装）我们的 mandatory 只管"必须升级"不管"回滚"。若未来线上事故需要快速回退，这是个缺口。

### 5. 插件生态里的竞品/同类功能
已安装页有两个和我们直接相关的样本：
- **ClassGuard 离班助手**：下课一段时间后自动检查 USB 设备是否弹出、指定软件是否仍在运行，防教师离班遗落东西。——我们的 U盘模块（WM_DEVICECHANGE + Centered 询问）目前只做**插入**侧；**拔出检测 + 离班提醒**是现成的增强方向，且与"考试静默"逻辑可复用。
- **考试提醒**：从学校考试看板同步班级考试，开考前提醒并打开考试大屏。——这正是我们集控下发通道（wss）天然擅长的事：管理端排考 → 端侧到点提醒 + 联动。
- 其他可记：FancyAnima 主打"CPU 渲染、低端设备更流畅"（教室机性能敏感的又一佐证）；样式注入器（运行时注入 Avalonia 样式热重载）我们 QML 侧对应物是 qml/ 目录整目录热替换，不缺。
- **我们的 StelarithControlPlugin 出现在已安装列表且勾选启用**（0 下载 0 星 = 本地私有安装，非市场发布）。
  ⚠️ 2026-10-17 用户纠正：**这只能证明插件被宿主加载，不证明"宿主插件 + 本地 StelarithAgent 代理"的功能链路跑通**。
  要下"跑通"的结论，还需逐项取证（均为待点单清单，不是已验证事实）：
  1) 课表/作业/组件配置同步是否真的从集控流到端上并渲染；
  2) 集控播报、远程切班指令能否下发并生效；
  3) 状态上报是否出现在管理端；
  4) 上岛组件（课表/作业）在岛上是否真的显示；
  5) 锁屏/截图等 OS 级动作经本地代理执行是否成功回执。

### 6. 教学安全模式与性能开关
- **教学安全模式**：崩溃时自动按预案处理（显示崩溃报告/自动退出），保证教学不中断。我们端侧有 StelarithAgentGuard 每 10 分钟拉起，**保活已覆盖**，但"崩溃现场报告"（日志落盘 + 下次启动可见）值得对齐——排障时现在靠离线取日志。
- 性能三开关（动画级别可禁用、禁用动画等待、降低进度条精度）：教室低配机优化思路，与我们 `-j1`/低端机现实同源。若以后岛在低端机上掉帧，这三条是现成的降级开关清单。

## 二、明确不学的（含理由）

| 项 | 理由 |
|---|---|
| 用户自由编排组件库 | 集控场景界面由管理端统一下发，端上自由编排破坏一致性 |
| classland:// URL 协议 | 我们有 443/wss 集控通道，第三方调起不是我们的入口形态 |
| 分体主界面 / 独立设置窗口 | 我们的被控端定位是"无窗 agent + 岛"，没有主界面可分体 |
| 插件市场 | 宿主生态是 ClassIsland 的；我们走内置模块层（src/modules）+ 管理端下发 |

## 三、结论（优先级判断，待点单）
1. **拔出检测/离班提醒**（借鉴 ClassGuard）——U盘模块现成地基上小步增强，性价比最高；
2. **下节课/明天课程预告位**——插件已有课表数据，岛端加一个概览信息位；
3. **OTA 通道 + 强制回滚**——涉及 ota.json schema 与装机卡，动线上真源，需谨慎；
4. 崩溃报告落盘、外观参数下发——排障与体验增强，其次。

以上仅清单。做哪条、什么顺序，等用户点单。
