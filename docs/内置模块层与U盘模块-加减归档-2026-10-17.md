## 四、接口/契约变化

| 面 | 前 | 后 |
|---|---|---|
| 动作分派 | `executeAction` → 进程外插件 | **先 `g_moduleHost->dispatch`（内置优先）**，未认领才走进程外插件 |
| 未启用内置模块的动作 | 无此概念 | 回执「内置模块 %1 未启用（插件市场里打开它）」 |
| QML 面板 | 无 modules 数据 | `agentUi.modules`（QVariantList 快照）+ `agentUi.moduleEnable(id,bool)` + `modulesRefreshRequested` |
| 事件投喂 | `forwardEvent` 只给进程外插件 | **同步**投喂内置模块（ModuleHost::forwardEvent） |

## 七、新踩坑（最贵两条，已入记忆）

1. `PostThreadMessageW` 投的 WM_DEVICECHANGE 到不了 `QAbstractNativeEventFilter`；SendMessage 到 Qt 顶层窗口能到。
2. moc 对 .cpp 输入生成的 TU 不含原文件 ⇒ QObject 夹具类必须拆头。
3. cl 链接步带 /TP 会把 .lib 当源码编（Qt6Core.lib C2018）；MSYS 把 `/EHsc` 当路径转换 ⇒ cl 参数走 Python subprocess。
4. 存量味道（待点单）：`md3/Md3Btn.qml:11` 自定义 `enabled` 盖掉 Item.enabled ⇒ 祖先 enabled 传导失效。
