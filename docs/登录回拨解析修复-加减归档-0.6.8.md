# 0.6.8 加减归档 · 登录卡在"授权回拨校验没过"

真机日志（用户提供）：

```
[oauth] 站点=https://www.245959623.xyz 客户端=xingjikong_native 密钥=不带（公开客户端）
[oauth] 正在打开授权页（回拨 http://127.0.0.1:61385/oauth-callback，state=710e0ab8…）
[oauth] 已用内嵌登录窗口打开授权页
[oauth] WARN 回拨被拒：path=/oauth-callback state匹配=否 带code=是
[account] FAIL 授权回拨校验没过（地址不对或状态不匹配），请重新登录
```

**`state匹配=否 带code=是`** 这个组合就是答案：回拨确实回来了（path 对、code 拿到了），
偏偏 state 对不上 —— 说明**不是**站点没回拨、也不是网络问题，是**我们解析出来的 state 不是原值**。

---

## 一、根因：请求行尾部的 ` HTTP/1.1` 被当成了 state 的值

回拨请求长这样（QTcpServer 收到的原文，第一行是请求行）：

```
GET /oauth-callback?code=4a1b2c3d&state=710e0ab8deadbeef HTTP/1.1
```

老代码：

```cpp
const QString requestLine = lines.first().trimmed();
const QString target = requestLine.mid(requestLine.indexOf(QLatin1Char(' ')) + 1);  // ← 取到行尾
const QString path = target.left(target.indexOf(QLatin1Char('?')));
const QUrlQuery qq(target.mid(target.indexOf(QLatin1Char('?')) + 1));               // ← 含 " HTTP/1.1"
```

`mid(第一个空格之后)` 取的是**从第一个空格到行尾**，于是 query 串被污染成
`code=4a1b2c3d&state=710e0ab8deadbeef HTTP/1.1`。

- `path` 在 `?` 之前 ⇒ 干净 ✅
- `code` 落在第一个 `&` 之前 ⇒ 干净 ✅
- `state` 排在最后、**直接被行尾污染** ⇒ 读成 `710e0ab8deadbeef HTTP/1.1` ❌

**为什么症状恰好是"code 对、state 错"**：被污染的是"行尾前最后一个参数"，
而 state 恰好总是排在最后。换任何参数名都同理。

### 逻辑复现（不连站点，纯语法）

```
请求行 : GET /oauth-callback?code=4a1b2c3d&state=710e0ab8deadbeef HTTP/1.1

老写法 mid(空格之后)
   path  = '/oauth-callback'
   code  = '4a1b2c3d'                     ✅
   state = '710e0ab8deadbeef HTTP/1.1'    ❌ 不匹配

新写法 section(1,1)
   path  = '/oauth-callback'
   code  = '4a1b2c3d'                     ✅
   state = '710e0ab8deadbeef'             ✅ 匹配
```

## 二、改动

### 管理端 `Stelarith-viewer-qt`

**`src/oauthlogin.cpp`**
- 请求行解析：`requestLine.mid(第一个空格之后)` → **`requestLine.section(QLatin1Char(' '), 1, 1)`**
  （按 方法 / 目标 / 协议 切三段，只取中间那段）。
- 回拨缓冲：`static QByteArray pending` → 成员 `m_pending`。
  函数级 `static` 是**所有实例共用一份**，上一次登录/上一个连接的残留会污染这一次的解析。
- 回拨被拒的日志补上"收到 `xxxxxxxx…` / 期望 `xxxxxxxx…`"，以后一眼看出差在哪。

**`src/oauthlogin.h`**
- 新增成员 `QByteArray m_pending;` + `#include <QByteArray>`。

**`CMakeLists.txt` / `src/main.cpp`**：版本 `0.6.7 → 0.6.8`。

### 被控端 `Stelarith-control-qt`（同源代码，同一处 bug）

**`src/oauthbind.cpp` / `src/oauthbind.h`**：三处同样修改（解析 / 缓冲 / 日志）。

## 四、出包过程中抓到的一个流程问题（**已修**）

第一次编译 0.6.8 时，CMake 的 `POST_BUILD copy_directory qml → build/qml/Stelarith`
把工作区里**未提交**的 `qml/Main.qml`（含别人正在写的 66 行"考试模式"面板）整个拷进了 `build/`，
于是**第一版 0.6.8 包里混进了仓库里没有的界面代码**。

已处理：`git show HEAD:qml/Main.qml > build/qml/Stelarith/Main.qml` 换成**提交版**，
确认"考试模式"残留 0 处、qmllint 无 error 后**重新出包并重新发布**（sha 由 `52ee5269…` 变为 `6d8d25fd…`）。

> **教训**：`build/` 是"工作区当前状态"的快照，不是"仓库当前状态"的快照。
> 出包前要确认工作区里没有别人的在途改动，否则产物与提交对不上、也不可复现。

## 五、另一个现象（用户附图 1）：管理端以管理员权限运行，系统浏览器起不来

截图是 Edge 的提示：**"Microsoft Edge 未响应，因为现有实例正在以提升的权限运行"** ——
管理端被以管理员身份启动，而 Edge 已在普通权限下运行，两者不能混用同一实例。

这正好印证了 0.6.7 把授权页改成**内嵌窗口**是必要的：
日志里 `[oauth] 已用内嵌登录窗口打开授权页` 说明**这条路已经绕开了该问题**。

（顺带：截图里的 CSP 报错 `Refused to load … cloudflareinsights.com/beacon.min.js`
是站点页面拦第三方统计脚本，**与登录无关**，不用管。）
