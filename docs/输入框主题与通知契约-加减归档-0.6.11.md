## 一、新增

| 文件 | 行数 | 职责 |
|---|---|---|
| `qml/components/InputField.qml` | 42 | 统一的单行输入框。承 `TextField`，自带底色（透明）、描边（聚焦时加深）、文字色、占位色 |

**为什么要有这一个文件（这就是"无法输入内容"的根因）**

界面上 7 处输入框以前每个调用点只写 `color: th.fg`，**没有一个设 `background`**。
于是输入框沿用 Qt 自带的系统调色板：

| 外观 | th.fg（文字） | 系统默认底 | 结果 |
|---|---|---|---|
| 暗色 | `#FAFAFA`（近白） | 白 | **白底白字，打进去一个字都看不见** |
| 亮色 | `#161616`（近黑） | 白 | 能看（恰好没撞） |

用户看到的现象是"这框没法输入内容"，实际是**输入成功但看不见**。
控件级样式在每个调用点各写一遍 = 写一遍漏一遍，漏的那遍就是 bug，所以抽成一个组件。

### 2. 通知弹窗接上契约（`qml/Main.qml`，66 行 → 190 行）

**改之前**（界面自己拼了一份参数，跟被控端对不上）：

```js
backend.sendAction("notify", {
    "title": …, "content": …, "seconds": 8, "tts": true,
    "flags": { "severity": ntCol.ntSeverity }
})
```

对照被控端 `notifyFromParams()`（`Stelarith-control-qt/src/main.cpp:1978`）：

| 界面发的 | 被控端读什么 | 结果 |
|---|---|---|
| 没有 `kind` | `params["kind"]`，缺省/未知 → popup | 形态永远只能弹窗，选不了灵动岛/全屏 |
| 顶层 `tts: true` | **只读 `flags.speech`** | **朗读永远不生效** |
| `flags.severity`（任何形态都带） | 只在 fullscreen 下读 | **"重要/紧急"点了等于没点** |
| `seconds: 8` 硬编码 | `params["seconds"]` | 改不了 |

**改之后**：全部经 `NotifyParams.buildNotifyParams()`（那份已有 `scripts/test-notify-params.mjs` 的 16 条断言，本次跑过 PASS=16 FAIL=0），界面只负责收集：

- 形态三选一：弹窗 / 灵动岛 / 全屏
- 朗读 chip → `flags.speech`
- 紧急确认 chip → `flags.emergency_confirm`（不自动关 + 置顶）
- 秒数输入（空 = 按字数自适应，上限 3600）
- 严重度：非全屏时**置灰并写明"只有全屏才生效"**（被控端就是这么读的，不假装能选）
- 字数提示：标题 >24 / 正文 >64 时提前说"会截到 N 字"（截断由被控端做，管理端只提示）
- 发送：走 `root.batchStart` + 逐台 `sendAction`，支持多选设备（以前只发给 `currentUid` 一台）

### 3. 收流页临时文件（`src/viewerbackend.cpp` + `.h`）

日志里一直在报 `FAIL 收流页写不进临时文件 …/Temp/stelarith-viewer-rtc-<pid>.html（拒绝访问）`。
0.6.9 已经把文件名带上进程号，**仍然失败** —— 说明根因不是名字撞车，是**目录**：

- `Temp` 是公共目录，系统清理、实时防护扫描、别的程序都在那儿落文件；
- 文件名再唯一，撞上一次就 `open` 失败，而 `QFile::open` 失败一次就完蛋。

改法（两处一起）：

1. 目录挪到**本应用自己的缓存目录** `QStandardPaths::CacheLocation`，不再跟 Temp 抢；
2. 文件名交给 `QTemporaryFile` 发 —— 系统保证唯一且**原子创建**，撞了会自己换名重试；
3. `setAutoRemove(false)`（文件要留给 WebEngine 加载，析构时绝不能删），路径存进新成员
   `m_rtcHtmlPath`，`~ViewerBackend` 里删掉，不在缓存目录堆垃圾。

新增头文件成员：`QString m_rtcHtmlPath;`
