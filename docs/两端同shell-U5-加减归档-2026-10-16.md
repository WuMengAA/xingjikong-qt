### 3.4 关键设计决策（每一条都有理由）

| 维度 | `UiPanelHost` | `UiPageHost` | 为什么这样定 |
|---|---|---|---|
| 显隐语义 | `open()` / `close()` 叫它才出来 | **由 `currentIndex` 说了算**，页没有 open/close | 面板是"叫才出"，页是"切过去就在" |

## 六、踩坑与认知（本轮新增）

1. **改共享 sample 清单会连带破既有探针**。加 2 条 `page` 声明就让 U2 探针的「清单 4 条」假红。
   教训：**改共享 fixture / 清单后，必须把依赖它的探针全部跑一遍**（本次 4 个探针都跑了）。
   这与 D 档「改共享件要跑两端门禁」是同一条纪律的延伸。
2. **QML 绑定看不进函数内部**。写 `pages: registry ? registry.navItems() : []` 时，QML **追踪不到**
   `registry.items` / `registry.env` 的变化 ⇒ 声明清单变了页清单不会重算。
   解法：在绑定里**显式触达**依赖（本文件的写法 + 注释说明）。
   ⚠️ 这与 U2 的 `UiRegistry` 把 `items` 做成 `readonly property` 是同一个套路的两个面。
3. **`createObject` 注入 ctx 优于 `Loader + onLoaded`**：后者的 `onLoaded` **晚于**
   entry 的 `Component.onCompleted`，entry 若在那时读 `ctx` 会拿到 `undefined`。
   照 `UiPanelHost` 的做法 `comp.createObject(host, { "ctx": ... })` 才是安全的。

### 8.5 ★ 探针抓到的真问题（本轮最有价值的一条）

**`qmllint` 报 0 Error，但页面根本加载不了**：

```
SettingsPage.qml:576:1: Expected token `}'
```

原因：原文件里设置页的 `Item {` 在 **1549** 行（1548 是它的注释行），我按 1548 起提 ⇒ body 多带了一个

⇒ **纪律**：抽完任何 QML 块，**先跑 `awk` 括号平衡，再跑加载探针**，最后才看 qmllint。

**探针自己写错的一条断言**（也记下来）：`it.ctx === ctx` 恒为假 ——
JS 对象跨 `createObject` 边界会被**包装/复制**，比引用必然失败，要比**内部字段**
（`it.ctx.window === fakeWin`）。这个坑在任何"给动态创建的组件传 JS 配置"的场合都会遇到。

### ★ 结构（被 moc 逼出来的三连坑，全部实测）

1. **AUTOMOC 把被 include 的头单独编译成一个 TU** ⇒ 头里不能引用 main.cpp 的任何
   符号（原 header-only 直调 static 函数的设计首编即炸 C2065 ×N）。
   ⇒ 改「**快照 + 信号**」：AgentUi 只持纯内存成员（inline getter/setter 不引用外部
   符号），真实读写由 main.cpp 的 `agentUiWire()`（connect 请求信号）+
   `agentUiFill()`（friend 直接改成员，不触发 switchChanged）完成。提权开关
   （自启/桌面快捷）**写完重读快照再 publish —— UAC 被拒时界面自动回弹**，不假勾。

## §十二 用户报「控制面板看不见」——三层根因（2026-10-16 深夜）

用户一句话报障，实为**三个独立缺陷叠在一起**，任何一个单独存在都会让面板"看起来是空的"。
最贵的是：**三者都不产生主日志的 QML ERROR**，qmllint 也全绿。

### 12.1 缺陷一：页声明漏写 `scope` ⇒ agent 端被契约默认值全过滤

- `UiContract.js:60` 里 `scope` 的默认值是 **`["viewer"]`**；`AgentPages.js` 的 5 条页声明
  **全都没写 scope** ⇒ 归一成 viewer 专属 ⇒ `visible()` 在 agent 端返回 false
  ⇒ `navItems()` 空 ⇒ **页宿主无页 + 底导航无项**（一起消失，只剩顶栏）。
- 为什么 viewer 端没暴露：默认值对 viewer **恰好正确** —— 这是个"默认值陷阱"。
- 修：5 条声明各加 `scope: ["agent"]`（含注释说明为何必写）。
- 门禁：`shared-qml/scripts/test-manifest-scope.mjs`（**只对 agent 端强制"显式写且含 agent"**；
  viewer/sample 只做结构检查 + `note` 提示"14/14 条依赖默认值"，**不替它们做主**）。
  负向实证：临时摘掉 scope 行 ⇒ 精确报 2 条 FAIL；恢复 ⇒ 15/0。

### 12.2 缺陷二：两个页用了 `QtQuick.Controls` ⇒ 被控端部署没有这个模块

真机日志（唯一线索，藏在宿主日志里）：

### 12.8 勘误：§12.3 的判断是错的，真凶是**截图工具没有 DPI 感知**

**先说错在哪**：§12.3 断言"窗口 895×677 超出屏幕（1244×701）⇒ 底导航落到屏幕外"。
那个"屏幕尺寸 1244×701"其实来自**另一个窗口的 rect**，不是屏幕。真实屏幕是 **2560×1440（150% 缩放）**，
工作区 2488×1440，窗口物理 **1342×1016** —— **从来没溢出过屏幕**。

**真正的坑（本轮最贵，差点让整个排查走偏）**：

| 现象 | 我看到的 | 真相 |
|---|---|---|
| 设置页 value 列空白 | 以为 Text 没渲染 | value 在逻辑 x≈801 ⇒ **物理 x≈1201 > 截图宽 895** ⇒ 根本没截到 |
| 底导航不可见 | 以为 Md3NavBar 没画/quilt | nav 在逻辑 y≈560 ⇒ **物理 y≈840 > 截图高 677** ⇒ 也没截到 |
| 红条/蓝条不显示 | 以为"窗口底部整块不渲染" | 同上：它们在截图范围之外 |
| 标尺每段 120px（应 80） | 一度以为是渲染缩放 | **80 逻辑 × 1.5 = 120 物理** ⇒ 这才暴露了问题 |

**根因**：`GetWindowRect` / `PrintWindow` 在**未声明 DPI 感知**的进程里返回**虚拟化（逻辑）坐标**，
而屏幕上真实渲染的是物理像素。于是"按窗口 rect 抓图"只抓到了左上 2/3 × 2/3，
右侧一列与底部一条**永远在截图之外** —— 看起来就像"界面少画了东西"。

**修**：三个探针脚本开头加 `SetProcessDpiAwareness(2)`（PER_MONITOR_DPI_AWARE），
之后 `GetWindowRect` 返回物理坐标、位图也是物理尺寸 ⇒ 一次拿到完整窗口。

**纪律（新增）**：**任何"按窗口矩形截图 + 判空白"的手段，必须先声明 DPI 感知**；
否则在小屏/缩放屏上会稳定地给出"哪里都没画"的假象。判据要落在**物理像素**上。

**保留的决定**：§12.3 的窗口改造（尺寸按可用屏幕 86% 计算 + 居中）**保留**，
但它不是 bug 修复 —— 它是**稳健性改进**（小屏机器上窗口会自适应，不会顶出工作区）。归属要说清。
