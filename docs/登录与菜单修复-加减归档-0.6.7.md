# 0.6.7 加减归档 · 登录打不开 / 菜单飞出屏幕 / 设备列表太原始

修的是用户真机上报的 5 条：**① 完全接不到被控端 ② 登录调用浏览器失败 ③ 集控界面拉完了原始
④ 登录状态点击后出现在屏幕外 ⑤ 无法连接服务器**。

---

## 一、五条现象各自的真因（先给结论）

| # | 现象 | 真因 | 属于 |
|---|---|---|---|
| ① | 完全接不到被控端 | **两个原因叠加**：(a) 本机从未登录成功（`account.json` 不存在）⇒ 没有接入票 ⇒ 代码**根本不连**云端；(b) 生产云端实测只挂 **2 台 `test_machine_01/02`**，真教室机没连上来 | (a) 代码链路 (b) **被控端部署问题** |
| ② | 登录调用浏览器失败 | 只靠 `QDesktopServices::openUrl` 一条路；它在本机返回 false 之后，**`m_busy` 没复位** ⇒ 第二次点登录被"上一次还没走完"直接挡掉，且不发任何信号 | 代码 bug ×2 |
| ③ | 集控界面拉完了原始 | 设备行只有裸 `uid`（`test_machine_01` 这种），没有在线状态、没有版本，看不出是哪台 | 代码（缺展示） |
| ④ | 登录状态点击后出现在屏幕外 | Popup 的 x/y 是**窗口级**（Overlay.overlay）坐标，代码拿的是**父项相对**坐标 `acct.x/y`；且 `overlayH - height - 8` 在菜单比窗口高时是**负数** | 代码 bug |
| ⑤ | 无法连接服务器 | 同上①(a)：没凭据时 `connectToCloud()` 直接 return 并写"没登录，连不上云端"。**不是地址问题**——实测 `wss://control.245959623.xyz/ws/viewer` 握手返回 **101** | 代码链路 |

## 二、新增 / 修改 / 删除

### 修改 `src/oauthlogin.h`
- 头注释重写：把"为什么不内嵌 WebEngineView"的旧结论作废（理由已不成立——收流页那个离屏
  `QWebEngineView` 本来就在进程里跑，Chromium 上下文是现成的）。
- 新增方法：`openAuthUrl()`（三层兜底）、`openEmbeddedWindow()`（内嵌窗）、`closeLoginWindow()`。
- 新增成员：`QWidget *m_loginWin`（头文件只前向声明，不引入 WebEngine 依赖）。
- 新增环境变量：`STE_OAUTH_EMBEDDED=0` 强制走系统浏览器（排障用）。

### 修改 `src/oauthlogin.cpp`（核心）
1. **打开授权页三层兜底**（原来只有一层）：
   - ① 内嵌 `QWebEngineView` 窗口（**首选**，不依赖系统有没有默认浏览器）
   - ② `QDesktopServices::openUrl`（回落）
   - ③ 都不通 → `failed()` 原因里带上授权网址，让用户自己粘地址栏
   回拨逻辑**一行没改**：内嵌窗口访问 `127.0.0.1:<临时端口>/oauth-callback` 与系统浏览器完全一样。
2. **`m_busy` 全部退出路径复位**（原来 3 条路径漏了）：
   `openUrl` 失败 / 回拨校验失败 / 请求头为空 —— 修之前这三种情况之后**再点登录毫无反应且不报错**。
   顺序统一为「先落状态、再 `emit failed`」，否则界面收到 failed 时 busy 还是 true，按钮一直灰着。
3. **关窗＝取消登录**：内嵌窗设 `WA_DeleteOnClose`，`destroyed` 回调里若 `m_busy` 仍为真则复位 +
   停端口 + 发 `failed("登录窗口被关掉了…")`。修之前关掉窗口同样会把状态卡死。
4. **成功后延迟 1.2 秒关窗**：让"登录成功"那页能被看见，别在换令牌时窗口突然消失。
5. 换令牌失败（`onTokenFinished` 的两条失败分支）也补了 `closeLoginWindow()`。

### 修改 `qml/components/AccountMenu.qml`（弹窗飞出屏幕）
```qml

// 修之后：先把胶囊位置换算进 overlay 坐标系，再四边夹取
```

`contentItem` 加 `clip: true`（被截短时不许画到框外）。

### 修改 `qml/Main.qml`（设备列表"太原始"）
设备行新增右端小字与状态点，全部取云端**真实返回**字段，不编造：
- 状态点：离线转暗色（`modelData.online !== false` 才算在线——老版本云端不带这个键时按在线处理，
  免得整列一夜全灰）
- 右端小字：在线显示被控端 `version`；离线显示 `lastSeenAgoSec` 换算的"刚断线 / N 分前"
- uid 加 `elide` 并让出右侧空间，长机器名不再压到小字上

### 修改 `CMakeLists.txt` / `src/main.cpp`
版本 `0.6.6 → 0.6.7`（两处，CMake 会校验一致、不一致 `FATAL_ERROR`）。

## 四、没验证 / 没做的部分（说清楚）

- **真机 GUI 未验**：内嵌登录窗口的实际渲染与交互、菜单新位置的手感、设备行小字的排版，
  离屏自检跑不了键盘与真实窗口，只能证明"能加载、属性没写错"。
- **"完全接不到被控端"有一半不在管理端**：生产云端现在只有 2 台测试机在线。
  真教室机要连上云端是**被控端部署/配置**的事（被控端指向的云端地址、令牌、端口），
  管理端修到"能登录、能连"为止，剩下的得去查那几台教室机。
- **设备"可读名字"仍然没有**：云端只给 `uid`。班级名/别名/位置这类字段**没有数据源**，
  不编造（拼音首字母、序号美化一律不做）。真要显示名字，得先让被控端上报。
- **没有动 C++ 业务层**：`src/viewerbackend.cpp` 一行未改。

## 五、这次抓到的、值得记的坑

1. **失败路径必须复位状态机**。`m_busy` 只在成功路径复位，是"点了没反应"这类最难查问题的典型来源 ——
   它不报错、不崩溃，只是永远不动。
2. **Popup 的坐标是 overlay 坐标**，不是父项坐标；混用两个坐标系在小窗口/嵌套布局里必然出屏。
   更隐蔽的是 `overlayH - height - 8` 这种"看起来有夹取"的式子，菜单一高就变负数。
3. **单点依赖系统浏览器**在教室机上是会真出事的（没默认浏览器、关联被改坏、权限上下文不同）。
   进程里已经有 WebEngine 时，内嵌是零成本的兜底。
