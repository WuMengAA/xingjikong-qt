## 三、D-2 `IslandRoot.qml` 拆分：方法论已落地，完成 2/12 块

### 3.1 为什么不能"一口气拆完"

先量化改造量：`IslandRoot.qml` 里 **`root.` 前缀引用 370 处**（其中 `root.th.` 123 处、`root._` 98 处）。

QML 的**隐式作用域**是这件事的真正代价：内联对象里的**裸标识符**（`th`、`_idle`）靠「子对象 → 组件根」隐式解析，一旦搬进独立文件，**这条链无声断掉**（不报错，取值恒 `undefined`）。2026-10-10 的 U3 就踩过：当时只 grep 带 `root.` 前缀的引用，漏掉 **87 处裸 `th`**，搬完整套面板配色变默认值。

⇒ 拆分的正确形态是「**逐块抽 + 每块用探针证明零差异**」，不是一次性大改。所以本档交付的是**方法论 + 验证工具 + 前两块**，剩余 10 块按 §3.5 的切缝表继续。

### 3.3 新增：`Stelarith-shared-qml/scripts/diff-island-tree.mjs`（182 行）

比对器的三个技术要点（都是实测踩出来的）：

1. **必须剥掉 QML 编译期匿名序号**。探针打的是 `metaObject()->className()`，QML 给匿名内联对象编的名字带序号：`QQuickRectangle_QML_21`、`IslandRoot_QMLTYPE_11`、`WhaleMascot_QMLTYPE_6_QML_20`。**这些序号改一行代码就变**（实测同一份代码不同跑次也会变：`QMLTYPE_6` ↔ `QMLTYPE_0`）⇒ 循环剥 `_QMLTYPE_\d+$` / `_QML_\d+$`。
2. **抽出的组件名要显式映射回匿名名**（`--rename IslandIdleFace=QQuickItem`）。这是拆分**唯一允许的差异** —— 用参数显式声明，而不是默默忽略。
3. **两类非确定性项要区别对待**：
   - **时钟文本**（`HH:mm`）：内置忽略（`--keep-time` 可比）。实测同模式两次跑只差这 1 项。
   - **动画驱动属性**：`WhaleMascot` 呼吸浮动（`floatAmplitude: 3`），其 `Image.y` 实测三连跑得 `-1.01067` / `-1.01621` / `-1.10437` —— **每次都不同**。用 `--ignore-line 'QQuickImage.*y=-'` **显式排除**，不用放大 `--tol` 掩盖（那会同时放过真实的 0.1 级偏移）。

## 七、踩坑与认知（本轮新增）

1. **QML 匿名类名不是稳定标识**。`metaObject()->className()` 带编译期序号（`_QML_21` / `_QMLTYPE_11`），**同一份代码不同进程/不同跑次都可能在变**（实测 `WhaleMascot_QMLTYPE_6_QML_20` ↔ `WhaleMascot_QMLTYPE_0_QML_12`）。任何"用 class 名做基线比对"的做法都必须先剥序号。
2. **基线必须区分「非确定项」的两种成因**：时间源（时钟）与动画相位（鲸鱼呼吸）。前者用正则内置忽略，后者用 `--ignore-line` 显式排除；**都不要用放大容差糊过去** —— 放大 `--tol` 会同时放过真实的亚像素级布局偏移。
3. **`--actions` 这类"看着该生效"的探针参数，要先验它真的生效**。本次差一点就把"零差异"当成"动作按钮可见态已验证"——是去查 `root._actions.count` 才发现它是 `0`。
4. **冻基线的正确姿势**：拆分后才发现某个态没冻基线时，用 `git show HEAD:<path>` 取原版临时放回、跑完**立即 `cp` 恢复**，并用 `diff` 校验恢复完整（本次已做）。比"回滚改动"安全，也比"不验证"负责。
5. **门禁的正则要去注释再匹配**。`/kMinContentW/` 命中的是我自己写的**注释**（那注释正是在说明这个缺口）⇒ 假红。凡"检测代码特征"的门禁，先剥注释行。

## 八、U5「两端同 shell」—— 待用户裁决方向（附实测）

### 8.1 实测：两端的"shell"现状**根本不对等**

| 端 | 界面构成 | 形状 |
|---|---|---|
| **被控端 control-qt** | `qml/` 下**只有两个探针**（`Main.qml` 21 行、`Showcase.qml` 124 行，**都不进 exe**）。真正的界面是 **C++ 全绘**：`src/island.cpp`（1564 行）的 `IslandOverlay` + `QQuickWidget` 加载共享 `IslandRoot.qml` | **没有 shell**，就是一颗岛 |
| **管理端 viewer-qt** | `qml/Main.qml` **3218 行**（页面栈 / 侧栏 / 面板宿主 / 命令面板）+ `layout/` + `mobile/` + `panels/` + 10 个 Dialog | **完整 shell** |

⇒ 「两端同 shell」这四个字有三种互不相同的解读，**代价与风险差一个数量级**，必须先定方向：

| 解读 | 内容 | 代价 / 风险 |
|---|---|---|
| **A. 给被控端也造 shell** | 被控端长出侧栏/页面/导航 | ⚠️ 与既有产品定位（`docs/被控端形态方案-Rust加简单图形化-讨论稿-2026-10-01.md`：极简、只有一颗岛、不打扰上课）**直接冲突**。这是**产品变更**，不是重构 ⇒ 必须用户拍板 |
| **B. 抽共享 shell 基座** | 把 viewer 的 shell 骨架（页面栈/面板宿主/导航/命令面板）下沉 `Stelarith-shared-qml/ui/`，让"未来任何端"都能装配同一套 | 纯重构、可做，但**眼前只有 viewer 一个消费者** ⇒ 是"为不存在的需求做抽象"，与用户「不在大便上叠叠乐」的偏好相冲 |
| **C. 统一"岛宿主契约"** | 把 `IslandHost` 提升到共享目录，两端以同一机制挂岛（含几何预算单一真源） | 与 D 档 §二 高度重叠，**收益实在**（消除"两处手写必须同值"），**风险低**（不碰产品形态） |

**我的建议：先 C，A/B 等用户明确表态。** C 是把 D-1 已经做了一半的事做完（预算门禁已建，只差宿主共享化）。
