## 一、排查方法与实测证据（先测再下结论）

对线上站点做**只读 HTTP 探测**（python urllib，不改任何状态）：

| 探测 | 实际响应 | 结论 |
|---|---|---|
| `POST /oauth/token`（grant_type+client_id+假 code，**不带** client_secret） | **400 `invalid_grant`** | 客户端校验**已通过**（只卡在 code 无效）⇒ 管理端"不带密钥"是**对的** |
| 同上但带**空** client_secret | 400 `invalid_grant` | 同上 |
| 同上但带**乱填** client_secret | **401 `invalid_client`** | 站点走 PUBLIC 哨兵分支：**必须明确不带** |
| `GET /oauth/authorize`（参数齐全、redirect_uri=http://127.0.0.1:18080/oauth-callback） | **200**，标题「授权登录 \| Stelarith」 | 授权页正常、loopback 回拨规则接受该地址 |
| `POST /api/console/desktop/session` 无 token | **401**「缺少 Authorization: Bearer…」 | 换票端点存在、鉴权正常 |
| `GET /api/console/desktop/session` | 405 | 符合预期 |

**我最初的两个假设都被自己的探测证伪**：
- ❌「站点要密钥、管理端没带」→ 实测站点是 PUBLIC 客户端，**要求不带**。
- ❌「换票端点已下线」→ 实测存在且行为正确。

⇒ **服务端整条链路健康，问题在客户端或账号环境。** 这一步没靠猜。

站点侧相关实现（只读）：
- `src/lib/server/oauth-clients.ts` `validateClient()`：`clientSecret(rec)` 空 ⇒ 直接 false；等于 `"PUBLIC"` ⇒ 要求对方不带。
- `src/routes/api/console/desktop/session/+server.ts`：401 会话失效 / **403「该账号没有查看集控的权限」** / 500 站点没配密钥。
- `src/lib/permissions.ts`：`viewConsole` 由**称号**授予（电教委员 / 任课教师 / 广播员 / owner·admin）。

## 二、管理端代码修改（5 处，均为真缺陷）

| # | 文件 | 改动 | 为什么 |
|---|---|---|---|
| 1 | `src/oauthlogin.cpp` / `.h` | 新增**登录总超时** `kLoginTimeoutMs = 3min` + 成员 `QTimer *m_timeout`；`stopServer()` 里统一 `stop()` | 回拨永不到达时 `m_busy` 永真、临时端口不关、界面永远"正在登录…"，**再点只命中"上一次还没走完"= 点了没反应**。这是"无法登录"最典型的可复现形态 |
| 2 | `src/oauthlogin.cpp` `begin()` | 开局 `m_pending.clear()` | 它是**成员**缓冲（不是 static，见 :257 的既有修复），上次取消/超时留下的半截请求行会污染本次回拨解析 |
| 3 | `src/oauthlogin.cpp` `onTokenFinished()` | 响应键**兼容 `access_token`**（原只认 `token`）；失败文案从 HTML 里取 `<title>` | 站点哪天回归标准 OAuth2 只发 `access_token`，原代码会当场判"没拿到令牌"——全流程走完却登不进去 |
| 4 | `src/viewerbackend.cpp` | 新增 `humanizeSiteError()`；`onSessionTicketFinished()` 用它，并按 401/403/500 各补一句"接下来该做什么" | 站点出错回的是**整张 SvelteKit HTML 错误页**，原因在 `<title>`；原来把 256 字节 HTML 原样塞进界面 ⇒ 用户看到一屏标签、**"登录失败但不知道为什么、也不知道找谁"** |
| 5 | `src/viewerbackend.cpp` `loggedIn()` | 由"票非空"改为**看票是否仍在有效期内**（`ticketUsable()`），与 `refreshAccountText()` 口径一致 | 30 天票过期后仍显示"已登录"、实际连不上，且找不到重新登录入口 |

行为差异：登录失败时用户现在能读到**一句人话 + 一句该怎么做**（如「该账号没有查看集控的权限（请到站点后台给它授权，或改用有权限的账号）」），不再是 `HTTP 403` 或一屏 HTML。

## 六、明确声明「没验证的部分」

1. **管理端登录的根因仍未被最终确认**。服务端与客户端代码两面都已排查，但**没有用户的现象原话**：
   没在本机跑过管理端做真实登录（避免动云端连接与用户桌面），也没拿到用户的 `viewer-run.log`。
   若用户界面提示「**该账号没有查看集控的权限**」，那属于**站点账号权限**（`viewConsole` 称号），
   不是客户端 bug —— 需在站点后台给该账号授予称号。
2. 本轮修的 5 处客户端缺陷**只做了编译验证**（管理端构建 exit 0、出包自检通过），**没做真实登录回归**
   （登录要打开浏览器/内嵌窗口、走真人授权，属"本机不开刀"范围）。
3. 被控端：dsh 整改后**只重跑了手势/空闲态探针**（时间线：下拉→展开、反向锁定、上推→空闲），
   未重新出全部三态截图；`notify`/`file_push` 等端到端仍未跑（不开刀）。
4. 被控端包**未做解压后的实机自检**（脚本自检通过 ≠ 装到教室机能跑）。
