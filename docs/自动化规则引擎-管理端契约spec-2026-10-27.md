# 定时自动化规则引擎 · 管理端契约 Spec（Phase 3 · 2026-10-27）

> 配套代码：被控端 `Stelarith-control-qt/src/automation_engine.{h,cpp}` + 岛面 `Stelarith-shared-qml/island/IslandAutomationFace.qml` + `IslandRoot.qml` 接入。
> 本文档是**契约**：规定管理端（viewer / 云端 / 任何会下发指令的客户端）如何与被控端自动化引擎对话。
> **不修改任何既有 backend**（viewerbackend / cloud 路由 / island.h 既有 API）；只在 `executeAction` 内**追加** 5 个 `automation_*` 分支，纯转发壳。

---

## 0. 设计边界（铁律，不可越过）

| 角色 | 职责 | 是否在本批实现 |
|------|------|----------------|
| **被控端 `AutomationEngine`** | 规则存储、1s 节拍调度、触发→条件→点火 | ✅ 已实现 |
| **被控端岛面 `IslandAutomationFace`** | 本机列表 / 启停 / 新建 / 删除（老师当场就能用） | ✅ 已实现 |
| **被控端 `executeAction` 桥** | 把引擎点火出的设备指令真正执行（复用 launch_app 白名单等） | ✅ 已接线 |
| **管理端下发 / 拉取接口** | 经既有 WS 指令通道把规则推到被控端 | ✅ 契约已定义，分支已加 |
| **管理端 UI（viewer 规则编辑面板）** | 远程编辑 / 批量下发 | ❌ 本批**不做**（仅留契约与 action 名，供后续批次） |
| **云端持久化 / 多机下发** | 规则模板存云端、按班批量下发 | ❌ 本批**不做**（引擎只消费单机的 `automation.json`） |

**核心约束（来自用户拍板方向）**：自动化是**被控端能力、主入口在岛**。"岛才是老师的手"——规则引擎在被控端本机自运行，**不依赖管理端在场**。管理端只经本契约下发 / 拉取，**绝不直接执行**。

## 1. 规则数据模型（JSON）

一条规则的完整形态（落盘 `%LOCALAPPDATA%/xingjikong/automation.json`，是 JSON 数组）：

```jsonc
{
  "id": "uuid-or-stable-string",   // 必填；管理端 upsert 必须带，用于幂等覆盖
  "name": "每天 8 点上课铃",        // 展示名
  "enabled": true,                 // 默认 true
  "trigger": { ... },              // 触发器（三选一）
  "condition": { ... },            // 条件（可空 = 无条件）
  "action": { ... }               // 要执行的设备指令
}
```

### 1.1 触发器 `trigger`

| `type` | 字段 | 含义 | 调度方式 |
|--------|------|------|----------|
| `time` | `time: "HH:MM"` | 每天固定时刻 | 到点窗口内触发，错过 60s 不补发，次日同刻 |
| `interval` | `intervalMin: N` | 每 N 分钟 | 距上次运行满 N 分触发；历史空则距 now 起算；跳过已过的多个周期 |
| `event` | `event: <见下表>` | 事件驱动 | 由对应子系统在发生时调用 `engine->onEvent(name)` |

`event` 取值（被控端事件源 → 引擎事件名 **严格一致**）：

| 事件名 | 触发时机 | 被控端接入点（对接位置，本批状态） |
|--------|----------|------------------------------------|
| `boot` | 引擎构造完成 | ✅ 已接（`main.cpp` 引擎创建后 `onEvent("boot")`） |
| `idle` | 系统进入空闲 | ⏳ 待接（接 `SetThreadExecutionState`/钩子或电源事件） |
| `classStart` | 上课铃 / 课表命中 | ⏳ 待接（接 `schedule_clock` 上下课回调） |
| `classEnd` | 下课铃 / 课表命中 | ⏳ 待接（同上） |
| `screenLock` | 系统锁屏 | ⏳ 待接（接 `WTSRegisterSessionNotification`/WinEvent） |
| `screenUnlock` | 系统解锁 | ⏳ 待接（同上） |

> ⏳ 标记的事件：本批**只接了 `boot`**（保证引擎一启动就评估一次开机型规则），其余事件接入点见 §4，属后续批次，不在本批范围。

### 1.2 条件 `condition`（全部可选，缺省 = 无条件通过）

```jsonc
{
  "days": [1,2,3,4,5],   // 星期 1=周一 .. 7=周日；不填=每天
  "after": "HH:MM",      // 时间窗起点（含）；不填=不限
  "before": "HH:MM"      // 时间窗终点（不含）；注意支持跨午夜（before<after 视为跨夜）
}
```

- 时间窗 `[after, before)`；`after` 与 `before` 可只填其一。
- 跨午夜例：`after:"22:00", before:"06:00"` = 每晚 22:00 到次日 6:00。

### 1.3 动作 `action`（复用 `executeAction` 既有词表，零新攻击面）

| `kind` | 必填参数 | 转成的 `executeAction` 指令 | 安全约束 |
|--------|----------|------------------------------|----------|
| `notify` | `title`（必填，空=非法） | `notify`（`title`/`content`/`seconds`/`from:"automation"`） | 受考试模式 / 本机开关 / 黑名单门控（走 `notifyFromParams`） |
| `set_volume` | `value:0-100` | `set_volume`（`value`） | 0-100 钳制 |
| `mute` | — | `set_volume`（`value:0`） | — |
| `unmute` | `value?:0-100`（默认 75） | `set_volume`（`value`） | 0-100 钳制 |
| `lock` | — | `lock` | — |
| `screenshot` | — | `screenshot` | 落盘 + 本机知情提示（走既有分支） |
| `launch_app` | `target`（必填，空=非法） | `launch_app`/`open_app`（`target`） | **复用 `STELARITH_AGENT_LAUNCH_ALLOWLIST` + 内置安全名单双闸** |

> ⚠️ 引擎**不**直接调子系统；`fireRule()` 把动作组装成与 `executeAction` 同形的 `QJsonObject`，经
> `actionRequested` 信号由 `main.cpp` 转发执行。任何引擎能做的事，都等于"管理端自己发对应指令能做的事"——
> 因此**没有新增攻击面**，只是把"按时钟/事件触发"这条调度逻辑补上。

## 2. 管理端 ↔ 被控端 指令契约（WS action 名）

管理端经既有 WS 指令通道（与 `ping`/`lock`/`screenshot` 同源）下发下列 action。**铁律：action 必须登记进
`kActionNames[]`，否则被控端自称不会做、管理端按钮置灰**（详见 `main.cpp` 该数组上方注释）。

| action | 入参（`params`） | 回执 `out` | 语义 |
|--------|------------------|------------|------|
| `automation_list` | 无 | `data.rules` = 规则原貌数组 | 拉取该机全量规则 |
| `automation_upsert` | `rule` = 完整规则对象（**必须含 `id`**） | `result:"ok"|"failed"` | 新增或覆盖（按 `id` 幂等） |
| `automation_remove` | `id` | `result:"ok"|"failed"` | 删除指定 id |
| `automation_toggle` | `id`, `enabled:bool` | `result:"ok"|"failed"` | 启 / 停指定规则 |
| `automation_run` | `id` | `result:"ok"` | 手动立即运行（仍判条件，不满足不点火） |

**入参约定**：规则字段一律放在 `params.rule`（对 `upsert`）或 `params.id`（其余）下，
**不要**把 `action`/`trigger` 等顶层字段直接摊平到 `params`，以免与指令外层 `action` 键冲突。

### 2.1 下发示例（管理端 → 被控端）

```jsonc
// 每天 8:00，周一至周五，弹出"上课"通知
{
  "action": "automation_upsert",
  "rule": {
    "id": "class-bell-morning",
    "name": "每日上课铃",
    "enabled": true,
    "trigger":  { "type": "time", "time": "08:00" },
    "condition": { "days": [1,2,3,4,5] },
    "action":  { "kind": "notify", "title": "上课了", "content": "请安静，准备上课", "seconds": 8 }
  }
}
```

```jsonc
// 每 30 分钟把音量拉到 60%
{
  "action": "automation_upsert",
  "rule": {
    "id": "vol-60-every-30",
    "name": "定时音量",
    "trigger":  { "type": "interval", "intervalMin": 30 },
    "action":  { "kind": "set_volume", "value": 60 }
  }
}
```

### 2.2 拉取回执示例（被控端 → 管理端）

```jsonc
{
  "result": "ok",
  "data": {
    "rules": [
      { "id":"class-bell-morning", "name":"每日上课铃", "enabled":true,
        "trigger":{...}, "condition":{...}, "action":{...} }
    ]
  }
}
```

## 3. 岛面（被控端本机入口）契约

`IslandAutomationFace` 直连 C++ 引擎（`automationRef`），**不走 WS**、**不依赖管理端在场**：

- 列表态：`automationRef.ruleSummaries`（C++ 算好的摘要：触发文案 / 动作文案 / 下次运行 / 状态 / 错误）
- 启停：`toggleRule(id, enabled)`
- 删除：`removeRule(id)`
- 立即运行：`runNow(id)`
- 新建 / 编辑：`addRule(rule)` / `updateRule(rule)`（表单在 QML 内组装完整 rule JSON）
- 面仅在引擎注入后出现（`IslandRoot.automationFaceOn` → faceModel `id:6`「自」）

> 岛面与管理端下发**共用同一套引擎 API**（`addRule`/`removeRule`/`toggleRule`/`runNow`/`listRules`/`upsertFromRemote`），
> 因此"老师在岛上当场建的规则"和"管理端远程下发的规则"落到**同一个 `automation.json`**，互不冲突。

## 4. 事件源对接点（后续批次待接，本批仅 `boot`）

引擎已暴露 `Q_INVOKABLE void onEvent(const QString &name)`。各子系统在对应时刻调用即可激活 `event` 型规则：

| 事件 | 推荐接入点（文件 / 函数） | 状态 |
|------|---------------------------|------|
| `boot` | `main.cpp` 引擎构造后 | ✅ 已接 |
| `screenLock` / `screenUnlock` | `island.h` 或 WTS/WinEvent 回调 | ⏳ 待接 |
| `classStart` / `classEnd` | `schedule_clock.cpp` 上下课触发 | ⏳ 待接 |
| `idle` | 电源/输入空闲检测 | ⏳ 待接 |

接入方式（纯增量，不破坏既有签名）：在既有回调里**追加一行** `g_automationEngine->onEvent("xxx");`，
前提是 `g_automationEngine` 非空（引擎构造晚于这些子系统初始化时需在创建后补一次）。

## 5. 安全与运维

- **持久化**：`%LOCALAPPDATA%/xingjikong/automation.json`（与 `island_history.json` 同族目录），UTF-8 缩进格式，便于人工排查。
- **点火审计**：每次点火 `emit engineLog`（带规则名 + 动作摘要），落被控端日志。
- **失败可见**：动作非法（`notify` 缺 `title` / `launch_app` 缺 `target` / 未知 `kind`）→ 规则 `lastError` 写入摘要，岛面红字提示，**不影响其他规则**。
- **错过不补发**：`time` 触发器若在 60s 窗口外才到（机器休眠/卡顿），直接推到次日，不补点火——避免苏醒后集中爆发。
- **攻击面**：引擎不引入任何新能力；所有可执行动作均经 `executeAction` 既有白名单与门控。
