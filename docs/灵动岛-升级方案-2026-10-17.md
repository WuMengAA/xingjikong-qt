## 一、结论摘要（TL;DR）

1. **岛的「展示层」已经基本做满，「数据层」几乎是空的。** 五档外框（胶囊/居中/全屏/通栏/角标）、
   四套面版式、G2 圆角、历史/搜索/投稿、鲸鱼、频谱、文件进度都已落地并有两端同源 + 机器门禁。
   但岛的模型仍然是 **一条内容**：新内容顶掉旧内容（`island_bridge.cpp:118-138` 的注释原话
   「真要多状态，得先让 showIsland 支持并存（另一个立项）」）。
2. **三个断层决定升级主次**：**单任务**（无并行/优先级/队列）、**单来源**（插件可推但无来源归属、
   无优先级上限、无限流）、**单端**（被控端发生的事传导不到管理端）。
   《操作上的创新》里的「任务中心」、生态文档里的「开放信息层」，都卡在这三处，而不是卡在视觉。
3. **建议按 T → P → B → A 四档推进**（定义见 §五）：
   - **T 档（任务中心）**：把岛的唯一数据单位从「当前这条内容」换成「任务（Task）」，
     支持并行、优先级、抢占/回落、进度、逐任务动作。
   - **P 档（协议与治理）**：把已有插件通道（`127.0.0.1:26789`）升级为带来源、优先级、
     限流、去重、动作回调的消息协议；**先补治理再做能力**。
   - **B 档（能力传导）**：被控端岛事件上传云端 → 管理端岛聚合展示（含聚合/限流规则）。
   - **A 档（结构债）**：`IslandRoot.qml` 3020 行的剩余拆分、双绘回退策略、门禁补齐。
4. **一个必须先做的半小时级补丁**：插件当前已经能调 `island_show`（`pluginhost.cpp:208-218`），
   但**没有频率限制、没有优先级、没有来源归属、`fromAdmin` 恒 false**（`pluginhost.cpp:215`）。
   这是一条已在生产通道上的治理缺口，应在任何新功能之前补上（§5.2 的 P0-0）。
5. **不建议做的四件事**：新增第二种本地端口（19527）、给被控端加键盘快捷键、允许第三方富文本/HTML、
   让第三方使用优先级 9–10。理由见 §九，均有反例或成本依据。

> ⚠️ 工作量数字（§十）是**基于已归档项目节奏的推测**，不是承诺。本文未做真机实验；
> 文中行为结论来自源码与归档，仅两个静态门禁在本轮实跑过（见 §2.7）。

## 四、升级总体设计（一个核心抽象 + 三条支撑线）

### 4.1 核心抽象：任务（Task）是岛的唯一数据单位

**设计原则**：任何要显示的东西——通知、文件传输、语音对讲、媒体播放、插件消息、
邻机状态——都实例化为一个 **Task**；岛只做两件事：**仲裁出前台任务**、**渲染前台与任务列表**。

```
上游（本机模块 / 云端指令 / 插件 / 邻端事件）
        │  upsert / update / finish
        ▼
   TaskStore（C++，唯一状态）
        │  仲裁：priority → ts；同 tag 合并；过期扫描 1Hz
        ├──► 前台 Task  → IslandRoot 概览面/对应形态
        └──► 其余 Task  → states 列表（展开态任务列表 / 状态面）
```

**Task 字段（建议）**：

| 字段 | 类型 | 语义 | 缺省 |
|---|---|---|---|
| `id` | string | 稳定标识（更新/完成/动作回传用） | 自动生成 `t-<seq>` |
| `tag` | string | 同类去重键（`file`/`media`/`voice`/`notice`/`plugin:<id>:<k>`） | = `id` |
| `kind` | string | 语义类别（notice/alert/exam/voice/file/media/plugin/peer） | `notice` |
| `source` | string | `self` / `admin` / `plugin:<id>` / `peer:<device>` | `self` |
| `title` / `desc` / `icon` | string | 显示字段（icon 为既有 lucide 名） | — |
| `priority` | int 1–10 | 抢占依据 | 5（通知）/ 4（文件）/ 8（对讲）/ 3（媒体） |
| `form` | enum | 五档外框（沿用 `IslandOverlay::Form`） | Capsule |
| `severity` | string | 仅 Fullscreen 生效 | 空 |
| `sticky` | bool | 不自动过期（等动作/等完成） | false |
| `expireAt` | qint64 | 到期时刻（`sticky` 时忽略） | now+duration |
| `progress` | double | -1 = 无进度条 | -1 |
| `actions` | list | `[{id,label,role}]` | 空 |
| `state` | enum | running / paused / done / failed | running |
| `fromAdmin` | bool | 历史排序与标记（复用现有语义） | false |

**生命周期状态机**（与现有 `archiveToHistory` 对齐）：

```
创建 → 前台（running）→ {完成 done / 失败 failed / 过期 expired / 被更高优先顶下 → 后台}
后台 → 前台（当前台退出）｜完成 ｜ 被丢弃（超出上限）
任何离开前台/结束 → archiveToHistory()（沿用现有归档与分类）
```

### 4.2 显示仲裁（必须单点、可复算）

1. **前台 = 排序第一**：`priority` 降序，同优先级 `shownTs` 新者优先。
2. **抢占/回落**：更高优先任务插入即切前台（几何动画沿用现有 `animateGeometry`）；
   前台结束或过期 → 回落到下一个；不允许「无主」状态（空闲则回 Idle）。
3. **同 tag 合并**：同 tag 的新任务 → 原地更新（进度/文案），不重新插队、不重复入历史。
4. **过期扫描**：**单个 1Hz QTimer 扫全表**，不为每个任务开 timer（否则 60 台设备 × N 个任务
   会变成数百个定时器，定时器数量比任务数量更容易失控）。
5. **上限与溢出**：最多 8 个任务；溢出丢弃「优先级最低且最旧」的；`sticky` 与优先级 9–10 不丢。
6. **考试门控**：插入前统一过 `NotificationGate`（`notification_gate.h`）；拒绝即静默，不记 error。
7. **历史兼容**：`archiveToHistory` 保持现有分类/未读/日期分组口径（`island.cpp:493-620`）。

### 4.3 兼容层（老调用零行为变化）

| 旧 API | 映射 |
|---|---|
| `showIsland(title, desc, icon, durationMs, form, fromAdmin)` | `upsertTask{tag:"notice", priority:5, fromAdmin, expireAt:now+durationMs}`，**仍顶掉上一条 notice**（同 tag 合并 ⇒ 行为等价） |
| `showWithActions(...)` | `upsertTask{tag:"notice", sticky:true, actions, onAction}` |
| `setFileTransfer(name, bytes, total)` | `upsertTask{tag:"file", priority:4, sticky:true, progress}` |
| `setMediaSession(...)` / `clearMediaSession` | `tag:"media"`，优先级 3 |
| VoiceHub 开始/结束 | `tag:"voice"`，优先级 8，sticky |
| 考试模式开始/结束 | `tag:"exam"`，优先级 9 |

**验收判据**：在 T 档完成后，现有 **14 处** `islandShow` 调用点（`grep -c 'islandShow(' src/main.cpp` 得 15，
其中 1 处是函数定义）的**外部行为**（形态、时长、回调、历史条目数）与改动前逐项一致；用探针 + 历史 JSON 对比证明。

### 4.4 协议 v2（插件通道，向后兼容）

```jsonc
// 插件 → agent（api 调用）
{ "type": "api", "id": "17", "call": "island_show", "args": {
    "v": 2,
    "id": "weather-1",            // 可选；不传则服务端生成并回传
    "tag": "weather",             // 可选；同类合并
    "title": "今日晴 25°C",
    "desc": "下午有雨，记得带伞",
    "icon": "sun",
    "form": 1,                    // 沿用现有 int → Form 映射
    "durationMs": 5000,
    "priority": 3,                // 1..8（插件上限）
    "persistent": false,
    "progress": -1,
    "actions": [ { "id": "detail", "label": "查看" } ]
  }
}
// agent → 插件（动作回传，新增）
{ "type": "island_action", "id": "weather-1", "actionId": "detail" }
// agent → 插件（api 结果，扩展）
{ "type": "api_result", "id": "17", "ok": true, "taskId": "p-weather-1" }
```

- **新增调用**：`island_update`（按 id 改文案/进度）、`island_hide`（按 id 收起）。
- **向后兼容**：v1 参数（无 `v/id/priority`）走默认值，返回结构只增不改。
- **动作回调**：插件需在 SDK 注册 `setIslandActionHandler(...)`；未注册则按钮点击回 `failed`，
  且**服务端不显示按钮**（能力协商：welcome 的 `granted` 里加 `island:actions`）。

### 4.5 治理（与协议同批落地）

| 项 | 规则（建议） | 依据 |
|---|---|---|
| 来源上限 | 插件 `priority ≤ 8`；9–10 保留给 `self`/`admin` | 生态 §9.4 |
| 频率 | 插件令牌桶 5 条/秒、突发 10；超限静默丢弃并计数 | 生态 §9.2 |
| 长度 | title ≤ 120 字符、desc ≤ 400 字符；单条 JSON ≤ 4 KB | 防止横幅/历史被长文撑爆 |
| 去重 | 同 `tag` 合并；同 `source+title` 在 10s 内合并 | 防插件轮询刷屏 |
| 开关 | 设置页「允许第三方向灵动岛推送」+ 来源列表（可禁用单个插件） | 教师可控 |
| 审计 | 被拒原因分类计数（权限/限流/长度/优先级），日志可查 | 排障 |
| 考试静默 | 全部来源（含插件/邻居）过 `NotificationGate` | 既有铁律 |

### 4.6 传导（B 档）与聚合

**数据流**：agent `island_event` → cloud 环形缓冲（每设备 20 条 / 10 分钟）→ 订阅的管理端 WS
`island-event` → viewer 岛。

**聚合规则（B 档成败关键）**：

| 规则 | 建议值 | 理由 |
|---|---|---|
| 折叠窗口 | 同 `(device, kind)` 3 秒内合并为一条 + 计数 | 60 台同时收到文件会瞬间刷屏 |
| 全局速率 | 管理端岛入口 ≤ 5 条/秒，超出合并为「N 条新事件」 | 保护 QML 绑定与教师注意力 |
| 行数上限 | 前台 1 + 列表 8 | 与 T 档上限一致 |
| 优先级映射 | 紧急（9–10）不折叠；常规折叠 | 紧急广播必须逐条可见 |
| 抑制 | 高优先级在场时，低优先级只进列表不入前台 | 避免「通知互相顶」 |
| 撤回 | 设备端任务结束 → 管理端对应聚合行 1 秒内消失 | 否则「12 台设备屏幕被截取」会永久挂着 |

### 4.7 交互（分端克制）

| 端 | 允许 | 不允许 | 理由 |
|---|---|---|---|
| 被控端（学生） | 点击展开/收起、下拉、确认/快捷回复、打开收到的文件夹 | 右键菜单、快捷键、暂停/取消任务 | 无人值守 + 学生注意力；破坏性操作已收进小区块（`island.cpp:2033-2043`） |
| 管理端（教师） | 双击默认操作、右键/长按任务菜单、快捷键、逐任务暂停/取消/重试、跳转设备 | 拖拽设备到岛（P3 再议） | 教师是操作者，岛是工作台 |

### 4.8 结构（A 档）

- **C++**：`TaskStore` 先作为 `island.cpp` 内的独立段落地，稳定后抽 `island_task.{h,cpp}`
  （避免一次性搬文件导致「改了没反应」类问题）。
- **QML**：按 `docs/灵动岛-D档…§3.5` 的切缝继续，但**先重新量行号**（原表基于 2148 行，
  现为 3020 行）。优先抽无回调块（Footer/Spectrum/Header），再抽 Collapsed/Media
  （顺带落 `IslandMediaFmt.js`），最后 Search/Submit/History。
- **双绘**：C++ `paintEvent` 回退保持「QML 缺失时能显示」即可，**不承诺逐像素 parity**；
  现有一致性由常量门禁（`test-island-metrics.mjs`）+ G2 同参保证。是否降低回退保真度见 §九-5。

## 八、风险、反例与适用边界

1. **事件风暴（B 档的最大反例）**：见 §5.3。若聚合规则不能把 60 台常规日压到「教师可读」的量级，
   B 档应只做「紧急事件传导」，不做全量。
2. **低端机性能**：3020 行 QML + Canvas G2 + `QQuickWidget`（教室机可能软件渲染）。
   `IslandRoot` 的绑定重算与 Canvas 重绘在 60Hz 下是否可接受，**目前无数据**。
   建议 Phase 0 用探针测「空闲/展开/任务列表 8 行」三态 CPU 与帧时间，设阈值（如展开态 ≤ 8% 单核）。
3. **第三方滥用**：伪造「紧急疏散」、刷屏、钓鱼文案。对策：优先级上限、来源标注、教师开关、
   审计日志；**不做**内容审核（无法可靠实现，且引入隐私问题）——改为「默认关闭第三方推送，
   由教师显式开启」。
4. **教学秩序**：岛占屏幕顶部正中，是师生最常看的位置。因此新能力默认**不打断**：
   非紧急任务只在展开态列表可见；常驻轻状态用 Mini 角标；考试模式全静默（既有门控）。
5. **双绘漂移**：C++ 回退与 QML 两套版式会持续分叉。当前靠常量门禁兜底，但字段级差异
   （如任务行按钮）无法自动比对。建议明确「回退只保底、不保真」，并在 QML 加载失败时降级为
   **单行横幅**而非完整卡片（见 §九-5）。
6. **兼容性**：云端/管理端旧版本不认新字段时必须继续工作；协议只增不改（§4.4）。
7. **适用边界**：本方案针对 Windows 教室机（Qt Widgets + QQuickWidget）与管理端桌面/Android。
   Android 的岛资源走 qrc 与 `qml-patch` 热更（`docs/灵动岛系统性升级-AC档…§一`），
   B 档在移动端只建议「告警/指令结果」，不做全量任务列表。
