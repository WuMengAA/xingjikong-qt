# 定时广播全链路实测结论（B3 · 2026-10-09）

> 结论：**链路每个环节都有实测证据**（下发/执行/回执/调度器 due/mark），
> 生产缺的是**使用场景**（无已排期任务 + 无 active 绑定在线机），而非功能缺陷。

---

## 1. 链路结构（已核实）

```
站点调度器 scheduled-broadcast-scheduler.ts（每 30s 扫 due）
  → dueScheduledBroadcasts() 查 scheduled_broadcasts 表（enabled=1 AND next_run_at<=now）
  → 按 target_class_id 过滤 device_bindings（status=active）
  → 逐台 POST 云端 /api/instructions（notify + kind=fullscreen，Bearer 管理令牌）
  → markScheduledRun(id)：once 禁用 / daily·weekly 重算 next_run
云端 → WS 推被控端 → 执行 → receipt 帧回云端 → recordResult + 广播管理端
```

## 2. 实测证据（2026-10-09）

### 2.1 指令核心通路（在线机 TEST1，ping 无打扰）
| 环节 | 证据 |
|------|------|
| 指令下发 | `POST /api/instructions` → HTTP 200 `{"state":"sent"}` |
| 被控端执行 | 队列落库 `id=4134 uid=TEST1 action=ping state="done" result="done"` |
| 回执对账 | dispatched 1791515065851 → settled 1791515065859（**8ms**）+ pending 清空 |

### 2.2 调度器逻辑（隔离 DB 单测 4/4，_probe/test_sched.mjs）
- 到期任务被 due 查出（`enabled=1 AND next_run_at<=now`）
- once 型 mark 后禁用（防重跑）
- daily 型 mark 后重算 next_run 到明天（enabled 保持，不再误投）

## 3. 生产现状（如实）

- `scheduled_broadcasts` 表 **0 条** —— 无已排期任务，调度器空闲扫描
- 在线机 `TEST1` 是 **unbound** 绑定；调度器只投 `status=active` 的设备
  （`TEST-BIND-001` active 但离线）—— 生产暂无投递目标
- **未做**：往生产插任务 / 改 TEST1 绑定（打扰教学 + 改生产数据，铁律 4 不碰）
