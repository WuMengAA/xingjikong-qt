# 星集控 · 系统总图（2026-10-25）

> 本文只写**设计**：这个系统由什么组成、身份怎么流动、各部分边界在哪。
> **状态指针不在这里**（唯一真源：`docs/星集控-指挥台-唯一真源-2026-10-02.md`），
> 也不代替各批的加减归档。

---

## 一、目标（一句话）

一个云端，四张面，**一条身份主线**：组织 → 班级 → 设备 → 用途。
任何"这台设备/这个人能做什么"的判断，都只能从这条主线推出来，不允许各界面自己长规则。

## 二、四张面（各自的职责边界）

| 面 | 谁用 | 职责 | 不该做的事 |
|---|---|---|---|
| **云端**（8788 + 站点） | 全体 | 唯一真源：组织/班级/成员/身份/设备注册/用途/指令与回执 | 不存"某台机器本地才知道"的东西；不做界面逻辑 |
| **OOBE**（被控端首次启动） | 现场装机的人 | 设备**唯一一次**登记身份：绑定归属 + 确定用途 | 不承担日常配置（那是设置页）；不只绑班不问用途 |
| **被控端外壳**（agent QML） | 教室现场 | 按用途呈现：教室端=班级面，广播端=广播台 | 不做跨班管理；不自己判断权限 |
| **管理端**（viewer） | 管理员 / 班主任·老师 / 广播室 | 按身份呈现能力：班级事务（含本班设备管控）/ 多班集控 / 广播排期 | 班级看板与集控台是**同套设备管控的不同作用域**（本班 vs 全部），并非两套系统 |

## 三、身份主线（先定身份，再谈功能）

### 3.1 设备身份是两维，不是一个字符串

```
设备身份 = (归属码 code, 用途 role)
   code：班级码 / 广播站码（同一命名空间，见 broadcast-club「station（班级/广播站码）」）
   role：classroom 教室端 | broadcast 广播端
```

- **OOBE 第一步问用途**，第二步才问码 —— 因为用途决定绑的是什么。
- 用途**选完即生效**（不等绑定成功）：选广播端后点"稍后配置"也是合法路径。
- 云端为权威：register 只在新登记时采信自报，之后一律以云端 `knownDevices.role` 为准；
  回执随 `registered` 下发，端侧落 `devrole.txt`（与 `classcode.txt` 同款）。
- 管理端改用途 → 设备重连即切外壳（复用 classCode 的反向下发，不新开推送通道）。

### 3.2 人员身份三档（用户裁决）

| 档 | 判定来源 | 能做什么 |
|---|---|---|
| 管理员 | 云端票 `platform_admin` / scopes | 建班/删班、设备用途、跨班集控、全局配置 |
| 班主任·老师 | `class_members` 的 owner / teacher | 本班事务：名单、考勤、课表、通知/作业、本班设备入口 |
| 广播室 | `broadcast_club` 令牌（带 station） | 自己归属站点的排期与广播，不触及班级其它功能 |

> 现状缺口（如实记）：viewer 的班级列表仍来自全量 `/api/classes`，
> `adminMyClasses()` 已能按 membership 返回"我的班"但**没接给 viewer**；
> 广播室目前是**独立入口**（用户裁决：保持独立，不并进 viewer 三身份）。

## 四、两条写入红线（最容易踩的地方）

1. **按班写入只在班级看板**：名单 / 考勤 / 课表 / 班务 / 发布。
2. **按设备写入主要在设备集控，但班级页可以包含本班设备管控**：
   批量下发、远控、监控的"全集"在集控页；班级页是**老师视角的本班子集**——
   锁定 / 关机 / 重启 / 截图 / 音量三档 / 专注 / 噪音监测，作用域限定**本班在线设备**。

   两页的边界是**作用域与使用者**，不是"班级页不许有设备操作"：
   - 班级页 = 班主任·老师，作用域=本班，使用对象=任课教师；
   - 设备集控页 = 管理员，作用域=全部设备，使用对象=管理员。
   控制管理功能**可以共用同一套实现**：都走 `host.runActionById` + `pick-*` 指令 +
   云端 per-device 鉴权，只是喂进去的 uid 集合不同（本班 vs 全部）。

   历史担忧（班级页长出电源动作→变成第二个集控台、两套口径漂移）的解法**不是删掉
   班级页的面板**，而是让两页共用**同一个权限出口与同一套动作函数**——这样"关机"在
   班级页和集控页是同一个出口，不会按 membership / scopes 各判一遍。

## 五、数据落点（"不要本机了"）

| 数据 | 落点 | 键 | 备注 |
|---|---|---|---|
| 班级目录 | 云端 `class-dir.db` | classCode | 班级码唯一真源，含别名与外部码 |
| 班级房间（消息/成员） | 云端 `class-room.db` | classCode | 持久房间，不是进程 |
| 学生名单 | 云端 `class-room.db` · `class_students` | 学号（幂等） | 借同一 sqlite 连接（避免 SQLITE_BUSY） |
| 班级课表 | 云端 `class-room.db` · `class_timetable` | classCode | 整份 profile 原样存，≤512KB |
| 设备用途/归属 | 端侧 `devrole.txt` / `classcode.txt` + 云端 `knownDevices` | uid | 端侧是缓存，云端是权威 |
| 排期/曲库 | VoiceHub（外部） | station | 云端只代理，不落第二份 |

## 六、这件事没做完的部分（明确挂账）

1. 管理端设备列表还没显示用途（云端已输出 `role`，viewer 未消费）。
2. 班级看板已保留本班设备管控（`ClassActionPane` / `ClassToolPane` 照常）；下一步是把
   集控页的同套设备管控与班级页**统一实现**（共用函数 + 同一云端权限出口），落实"功能
   共用"，避免两页各写一套导致口径漂移。
3. 广播端的"站"尚未成为云端一等实体：当前 station 复用 classCode 命名空间，
   没有独立的广播站表与站点侧校验（先跑通身份，再谈站点治理）。
4. 考勤、课表 UI 未接（云端 API 已就位）。
