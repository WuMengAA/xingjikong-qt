# 被控端（control-qt）UI 迁移方案

> 编制：2026-10-30 ｜ 范围：`Stelarith-control-qt/qml/`（48 个 QML/JS 文件，5746 行 .qml）
> 目标：把被控端 UI 统一到 **`Theme` 令牌 + `App*` 组件**（单一真源 = `Stelarith-shared-qml/ui/`）
> 依据：用户 2026-10-29 UI 规范（去边框／禁硬编码 Hex／禁裸用 Button／单文件 ≤300 行）＋
> 「老师实际面对的是被控端那台讲台机，能力主入口在被控端」铁律
> **本文件只描述现状与计划；未获裁决的档位一律不动。**

---

## 0. 一句话结论

被控端当前**同时存在三套互不相通的 UI 语言**，而且它们作用在**互不相交的文件上**：

| # | UI 语言 | 覆盖面 | 规模 | 是否合规 |
|---|---|---|---|---|
| A | **`App*` + `Theme`**（共享库正源） | 只有 1 个按钮（本轮之前：0） | 引用 1 处 | ✅ 合规 |
| B | **`ash/` 自有件**（家制 shadcn 复刻） | 设置页整块（1 个页壳 + 9 个 Sec* 页） | 9 件 / 699 行 / 78 处 Hex / 17 处 border | ❌ 违反「去边框、禁硬编码 Hex」 |
| C | **`Md3*`**（上一代 MD3 组件） | 插件/记录/时段/自检/广播台 + OOBE 对话框 | 18 处实例 | ❌ 待退役 |

**所以这件事不是一次「换名字」，而是要把 B、C 两套各自为政的视觉体系并入 A。**
迁移量真正的大头不是 18 处 Md3（那只占 1 天），而是 **ash 的 699 行**和 **131 处散落的硬编码 Hex**。

**1.b-2 关键裁决点：AshTheme 与 Theme 的调色板不同源**
两者都源自 shadcn 的 zinc 系，底色几乎一致（`#09090B` / `#FFFFFF` vs `#FAFAFA`），但：

| AshTheme | Theme | 差异性质 |
|---|---|---|
| `background` `#09090b`/`#ffffff` | `color.background` `#09090B`/`#FAFAFA` | 浅色底**微变** |
| `card` `#09090b`/`#ffffff` | `color.surface` `#18181B`/`#FFFFFF` | 深色下卡片**从同底变亮一档**（去边框必需） |
| `primary` `#fafafa`/`#18181b`（中性灰） | `color.primary` `#D0BCFF`/`#6750A4`（**品牌紫**） | **语义级色变** |
| `border` `#27272a`/`#e4e4e7` | 无对应（规范禁边框） | **要删，不是要换** |
| `radiusSm/Md/Lg/Xl` = 4/6/8/12 | `radius.sm/md/lg/xl` = 8/10/14/20 | 全面放大 |
| `gap` = 12 | 无（规范只 4/8/16/24） | 需就近取 8 或 16 |
| `controlH/Hlg/Hsm` 36/40/32 | 由 `AppButton size` 表达 32/40 | 概念换层 |

⇒ **ash→Theme 会改变观感，不是零风险重构。** 尤其「中性灰主按钮 → 品牌紫主按钮」，
这是设计决策，必须用户点头（见 §5 裁决项 D1）。

#### ⚠️ 端到端探针为什么坏了（重要，且是后续所有批次的前置）

`AgentShell.qml` 在 2026-10-29 QtShadcn P0 批次里新增了 `import QtShadcn` 与
`QtShadcnTheme { id: shadcnTheme }`（第 2、27 行）。
而 `_agent_ui_probe.py` 的 `LIBS` 列表**没有** `QtShadcn.lib`
（`build/_qtshadcn/src/QtShadcn.lib` 存在，产品 exe 靠 `target_link_libraries(... QtShadcn)` 链上）。
QtShadcn 是**静态 QML 模块**，类型注册随 lib 走 ⇒ 探针不链它就 `is not a type` ⇒ 壳加载不出根对象。

**后果必须写在明处：在没有修好这个探针之前，被控端任何 UI 改动都只能做到
「单页实例化 + 结构门禁」这一档，无法做整壳回归、无法出截图、无法验交互。**

#### 另一个隐患：构建产物里的死文件

`build/qml/components/Md3.qml`（10-25 15:09，**10 KB，非 singleton 旧版**）仍在。
共享库早在 10-25 就把 `Md3.qml` 移入 `theme/` 并改成 `pragma Singleton`，但 `copy_directory`
**只拷不删** ⇒ 旧件永久残留。当前所有页面都用 `import "../components/theme"` 吃单例，
所以没炸；但只要哪个文件改用裸 `Md3.` 或依赖 `import "../components"` 的隐式注册，
就会和 `theme/qmldir` 里的 `singleton Md3` 撞名（`Md3 is ambiguous`）。
`check-island-parity.cmake` 以 `SUBSET=ON` 运行，**不追究产物多出的文件** ⇒ 静默。

## 2. 分档清单

### 档 ① 机械替换（有现成 App 件、接口同构、不动布局）

| 对象 | 数量 | 位置 | 映射 |
|---|---|---|---|
| `Md3SwitchRow` → `AppSwitchRow` | 1 | AgentPlaySchedulePage:45 | **100% 同构**：`text` / `checked` / `supporting` / `onToggled(bool)` 全对齐 ⇒ 真·零思考替换 |
| `Md3Btn` → `AppButton` | 11→9（本批已做 2） | PluginsPage 34,35,92,168,176／PlaySchedule 113,121／Records 52,94 | `variant`：`filled→primary`、`tonal→secondary`、`text→ghost`、`outlined→ghost`；`height:30 → size:"sm"`（32）；默认高 40 两边一致；**均无 `icon:` 使用** |

**规模**：剩 10 处实例 / 3 个文件。**每批 1–2 文件**，无需改布局、无需改 import。

### 档 ② 换布局（必须改子项 anchors → Layout）

| 对象 | 数量 | 位置 | 为什么不能机械换 |
|---|---|---|---|
| `Md3Card` → `AppCard` | 7 | PluginsPage 48,117／Records 30,72／PlaySchedule 34／SelfCheck 32／BroadcastConsole 48 | **结构性差异**（见下） |
| `Md3Dialog` → `AppDialog` | 1 | oobe/AppDialog.qml:19 | **接口完全不同**：Md3Dialog 是 `opened/title/text/actions/actionClicked(index,role)`；AppDialog 是 `opened/closed/content/default contentData`。属于**重写**，不是替换 |

`Md3Card → AppCard` 的具体坑（4 处必须同时改，漏一处就报 `Cannot specify anchors for items inside ColumnLayout`）：

```
Md3Card：default property alias content: inner.data   // inner 是普通 Item，子项写 anchors.left/right/top 到 parent
AppCard：default property alias contentData: contentBox.data  // contentBox 是 ColumnLayout
```

1. **外层容器**：这些卡当前都挂在 `Column`（不是 ColumnLayout）里，靠
   `anchors.left: parent.left; anchors.right: parent.right` 撑满。
   `Column` **不支持** `Layout.fillWidth` ⇒ 必须把外层 `Column` 换成 `ColumnLayout`，
   而后者的子项又不能再写 `anchors` ⇒ 波及同级所有兄弟节点（标题 Text、按钮 Row 都得改）。
2. **卡片内第一层容器**（`Column { anchors.left/right/top: parent }`）→ `Layout.fillWidth: true`，`anchors` 全删。
3. **`variant: "filled"/"outlined"` 无对应**：AppCard 只有 `shadow: bool`，**不支持 variant** ⇒
   插件卡的「outlined 目录卡 vs filled 插件卡」区分会消失（见 §5 裁决项 D2）。
4. `Repeater` 的 delegate 里写 `anchors.left: parent ? parent.left : undefined`
   （PluginsPage 50-51、119-120 这种防御写法）在 ColumnLayout 里要整个删掉。

**规模**：7 卡 / 5 文件，但每个文件都要连带改外层容器 ⇒ **每批只做 1 个文件**。

### 档 ③ 缺件（共享库没有，需新增或就地降级）

| 缺的东西 | 用在哪 | 影响 | 处置建议 |

| 无 `AppCardTitle` 等价物 | 设置页 9 个 Sec* 全用了 `AshCardTitle` | 设置页无法动 | 用 `Text{font.weight:Medium}` 内联，或新增件 |
| 无 `AppInfoRow` 等价物 | 设置页 7 个 Sec* 用了 `AshInfoRow` | 同上 | 用 `AppListItem` 近似（需核对 padding 语义） |

### 档 ④ 令牌层（`Md3.*` / `tok.*` / `Ash.*` → `Theme.*`）

| 子档 | 现状 | 数量 | 备注 |
|---|---|---|---|
| ④-1 `Md3.*` 单例令牌 | AgentBottomNav 9、AgentShell 2、ash 1 | **12 处 / 3 文件** | 只 `Md3.cCont/cOutlineVar/cOnSurfaceVar/labelM/durShort/cSecondaryCont/cOnSecondaryCont/cOnSurface/dark` 这几个名；量小 |

## 4. 风险点

1. **视觉回归代价高（最高风险）**
   被控端是讲台机现场界面，老师上课时正在用。改错一个按钮颜色不会崩，但会被当场看到。
   ⇒ 档②（换布局）必须一个文件一批；**每批最好有一次肉眼核验**（本机起 build/ 实例，
   不碰 `C:\Program Files\Stelarith\`）。

2. **端到端探针当前是坏的**（§1.d）
   在批 0-a 修好之前，批 2 之后的所有改动**只能靠单页探针**，整壳（底导航 + 页宿主 + 广播浮层）
   的回归是盲区。这不是「暂时将就」，而是「必须修否则不许继续」。

3. **`Md3Card → AppCard` 是连锁改动**
   外层 `Column → ColumnLayout` 会波及同一父节点下**所有**兄弟项。实际改动行数通常是
   「卡片本身 5 行」的 5–8 倍。`Repeater` delegate 里带 `parent ? ... : undefined` 的防御
   锚点写法必须整块删掉，否则运行时报 anchors 冲突。

4. **emoji 图标在本机渲染成 tofu**
   `Md3Btn.icon` 的注释写着「emoji 占位（Lucide 接入后换 SVG）」。被控端现在**没有**任何
   `icon:` 使用（底导航已改 `SvgIcon` 走 `resources/icons/*.svg`）。
   ⇒ 迁移时**不要顺手把 emoji 引进 AppButton**；要图标就走 `SvgIcon`。
   顺带：任何新写的图标名必须先对照 `resources/icons/` 实体文件。

5. **单文件 300 行上限**
   当前 `BroadcastScheduleSheet.qml` 795 行、`BroadcastClubPage.qml` 541 行已**超限**。
   迁移这两处时（批 7 涉及 ConsolePage，浮层是它的兄弟件）**不允许再往上加行**：

   既满足「不要紫色」，又保住 ash 现有观感。**这一条已经把最大的观感风险消掉了。**

2. **`AshTheme.gap = 12` 在 `Theme.spacing` 里没有对应档**（规范只有 4/8/16/24）
   9 个设置页大量用它。替换时逐处取就近值（8 或 16），**每处都会造成几像素位移** ——
   这是最琐碎、最容易看走眼的部分，建议单开一批专门做。

3. **`AshTheme` 有 46 处 Hex，`Theme` 只有一张色板**
   ⇒ 废弃 `AshTheme` 后这 46 处 Hex 自然消失。这是废弃路线相对「保留但重基于 Theme」的**主要收益**：
   后者只是把 78 处 Hex 从 ash 件挪进 ash 件，仍是两套调色板。

### 10.5 建议执行顺序（4 批，每批可独立回滚）

| 批 | 内容 | 文件数 | 风险 |
|---|---|---|---|
| **A1** | 只换「无外观差异」的两个：`AshCardTitle → AppCardTitle`、`AshInfoRow → AppInfoRow` | 9 | 低（尺寸／字号一致；`AppInfoRow` 多了 elide，长 URL 会省略号） |
| **A2** | `AshSwitchRow → AppSwitchRow`（100% 同构）+ 删 `AshSwitch` | 5 + 1 | 低 |
| **A3** | `AshButton → AppButton(solid/secondary/ghost)`、`AshCard → AppCard(muted)`、`AshInput → AppInput` | 9 | 中（border 消失、圆角 4/6/8/12 → 8/10/14/20 全面变大） |
| **A4** | `AshDialog → AppDialog`（重写）+ 退役 `AshTheme` + 删 ash 目录 | 2 + 9 | 中（`AgentSettingsPage` 的重置确认弹窗是唯一消费者，单独验） |

> A1/A2 做完即可删 `AshCard.qml` / `AshSwitch.qml`；`AshTheme.qml` 必须留到 A4。

### 10.6 代价与风险

- **改动量约 1100 行**，其中约 800 行是「调用方把 `AshXxx` 改成 `AppXxx` + 属性改名」的机械活，
  真正的判断点集中在 3 处：主色语义（已定 solid）、12px 间距缺档、`AshDialog` 重写。
- **观感一定会变**：圆角整体变大（8→14）、边框消失、12px 间距被吸到 8/16。
  不是「等价重构」，是「改版」⇒ 每批都要出截图给你看。
- **回滚成本低**：ash 件与调用页同在 control-qt 单仓，逐批 commit，`git revert` 单批即回到旧观感。
  `AshTheme` 留到 A4 才删，前三批随时可退回。
- **不要顺手改 `Stelarith-shared-qml` 的既有件**来迁就 ash；缺什么用本轮新加的件，
  还缺就走 D3 流程请示。

### 10.7 明确不做的

- 不保留「ash 与 App 长期并存」：那正是要消灭的两套语言。
- 不为少改代码而把 ash 的 border 原样搬进 App（违反去边框规范）。
- 不在 `AgentShell.qml` 里给 ash 做适配层（会造第三套）。

### 10.8 与 Md3 清理的关系

两条线**并行不冲突**（文件不相交），但**建议 Md3 先清完**：Md3 只剩 18 处、成本低，
先做完能立刻把「三套语言」降到「两套」，再动 ash 时判断面更干净；
且 ash 的 A3 批要动 `AgentSettingsPage`，而 Md3 批不碰它，先清 Md3 不产生额外冲突。
