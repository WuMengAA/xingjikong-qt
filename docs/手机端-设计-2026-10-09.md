# 手机端（管理端伴侣 App）设计（2026-10-09）

> 背景：Qt for Android 评估——管理端移植可行。手机端定位 = **老师口袋里的
> 管理端伴侣**：随时看教室状态、收通知、发关键指令，不做重操作（远控/广播主场
> 留在桌面端）。
> 形态：**独立精简 Qt Quick 工程**（非复用 viewer-qt），理由见 §3。
> 依据：viewer-qt CMake 依赖实测 + Qt 6.8 Android 支持矩阵 + 云端能力。

---

## 0. Qt 版本决策 + QML 原则（2026-10-09 用户裁决，理解要点）

### 0.1 Qt 6.12 LTS（用户拍板，取代最初 6.8 假设）

- **Qt 6.12 是最新 LTS**（2026-09-30 发布，5 年维护）——星集控需长期维护，直接以 LTS 起步避免未来迁移
- **Android 支持**：API 28–36（Android 9–16）、arm64-v8a + x86_64；NDK r26b/r27c + Clang 17.0.2；Gradle 9.5.1 + AGP 9.2.1；JDK 17
- **关键行为变更（必须处理）**：Android 返回键从「退出」改为 `moveTaskToBack()` 退后台——若要「按返回退出」，需在 QML 显式处理 `Keys.onBackPressed`/`onClosing`
- **已知坑（真机测试注意）**：部分低端设备 OpenGL 驱动缺陷（字形缓存异常 / `makeCurrent(): no EGLSurface` 崩溃）；PositionSource 需主动请求精确位置权限

### 0.2 QML 原则（Qt 官方立场，本工程铁律）

> **QtWidgets 从未打算用于移动设备**——Android 上 QtWidgets 可能 UI 不刷新。**移动端一律 QML**。

- ✅ 手机端 = **纯 QML**（QtQuick + QuickControls2），已审计：main.cpp 用 QGuiApplication、backend 纯 QObject、CMake 零 QtWidgets 依赖
- ✅ 桌面端（被控端 control-qt / 管理端 viewer-qt）继续 QtWidgets —— **桌面是 QtWidgets 的成熟主场**，不强迁
- ✅ 分层原则：**同一套逻辑（云端协议/指令）三端共享，UI 层按端选型**——桌面 Widgets、移动 QML、网页站点

### 0.3 建议验证路径（用户原话「重点在理解」的落地）

先在**真机跑通最小 Demo**（QML 界面 + WebSocket 通信），验证编译环境 + 基本交互无碍，再全面展开。

## 1. 定位与边界

### 要什么（手机端能做的）
| 能力 | 说明 |
|------|------|
| 教室概览 | 在线/离线数、连接状态、灵动岛摘要（推送）|
| 设备列表 | 分班看状态、一键 ping |
| 通知/广播 | 收到关键事件推送（灵动岛）|
| 轻指令 | 关机/重启/锁屏（确认式，不做批量）|
| 监控摘要 | 回放列表（点看缩略图），**不**做实时大画面（带宽/电池）|
| 测试手电 | 考试模式开关（教师端控制）|

### 不要什么（留桌面端）
- ❌ 远控输入（指哪打哪——桌面鼠标体验）
- ❌ 语音对讲/通话（winmm 依赖，桌面已有）
- ❌ 屏幕广播/大画面
- ❌ 复杂的课表编辑器（只读展示）

## 2. 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| UI | Qt Quick + Qt Quick Controls 2 | QML 跨平台，Android 原生支持 |
| 通信 | Qt WebSockets（管理端 ws 通道同款）| viewerbackend 现有 WS 协议直接复用 |
| 鉴权 | CLOUD_VIEWER_TOKEN（复用）| 同一套管理令牌，云端零改动 |
| 数据 | 与 viewerbackend 同协议（devices/events/instruction-result）| 云端广播协议已就绪 |
| 存储 | QSettings | Android 支持 |
| 状态推送 | Android 前台服务 + 通知 | 教室机连不上也有兜底轮询 |

**不含**：WebEngine（Android 不支持 + 肩包）、Widgets（QML 纯）、winmm（无音频）。

## 3. 为什么独立工程（不复用 viewer-qt）

viewer-qt CMake 实测依赖：
```
Core Gui Quick QuickControls2 Network WebSockets Widgets
WebEngineWidgets WebChannel Svg
```
- **WebEngineWidgets/WebChannel Android 不支持**（必须剔除）
- Widgets 是桌面壳（托盘/关窗），Android 无此概念
- 复用 = 大量 `#ifdef ANDROID` 满飞，维护地狱

**独立工程**：`Stelarith-mobile/`（新目录），只引入纯 QML + WS 后端（
`mobilebackend.h/cpp`，仿 viewerbackend 的 WS 栈，drew 掉桌面专有代码）。
与 viewer-qt 共享：云端协议、令牌、组件（MarqueeText/IslandClock/WhaleMascot/
CameraCenter 缩略版）。

## 4. 目录结构（草案）

```
Stelarith-mobile/
  CMakeLists.txt            # 纯 Quick + WebSockets
  src/mobilebackend.{h,cpp} # WS 栈（devices/events/指令）
  qml/Main.qml              # 底部标签：概览 / 设备 / 监控 / 我的
  qml/components/            # 复用 + 手机适配（大触控 56px）
  android/AndroidManifest.xml
  android/build.gradle       # Qt for Android 打包
```

- ⚠️ NDK 28.2 vs Qt 6.8 兼容（官方推荐 r26/r27）——先降级再试
- ⚠️ Android 前台服务（Android 12+ 限制）——推送用「短 WS + 周期轮询」兜底
- ⚠️ WS 长连接在 Android 后台会被系统杀掉——需前台服务或 notification-foreground-service
- ✅ QSettings/Network/WebSockets 都 Android 支持（官方文档已核）
