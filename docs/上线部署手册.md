# 星集控 · 上线部署手册

> 适用版本：**v0.5.0**（三端统一版本号）
> 目标形态：**公网上线**（教室机与管理端可跨网络连入云端）
> 本文档为「你来提供环境资源、我据此落地」的施工蓝图。文末第七节列出**需要你提供**的清单。

---

## 0. 总览

### 0.1 三端与端口

| 端 | 程序 | 角色 | 默认端口 | 网络方向 |
|---|---|---|---|---|
| 云端 | `stelarith-cloud-ws`（Node.js） | 中转站：设备注册 / 指令下发 / 事件流水 / OTA 清单 | **8788**（HTTP + WebSocket） | 公网可达 |
| 被控端 | `stelarith-agent-qt.exe`（Qt6） | 教室机：抓屏推流 / 收指令执行 / 自更新 | 无监听端口 | 主动外连云端 |
| 管理端 | `viewer-qt.exe`（Qt6 + QML） | 老师机：看画面 / 下发指令 | 无监听端口 | 主动外连云端 |

### 0.2 连接拓扑

```
   教室机 (agent)                    云端 (cloud-ws :8788)              老师机 (viewer)
   ─────────────                     ────────────────────              ──────────────
   ws://…/ws/agent  ───────►  ┌──────────────────────────┐  ◄───────  ws://…/ws/viewer
   (设备令牌鉴权)              │  /ws/agent  被控端接入     │            (viewer 令牌/票据鉴权)
                              │  /ws/viewer 管理端接入     │
   ◄─── 指令 / OTA 下发 ──────  │  /api/*     管理面 HTTP    │  ─────►   /api/devices, /api/ota/latest
   ──── 画面/回执上报 ───────►  │  ota.json   OTA 清单       │
                              └──────────────────────────┘
                                        ▲
                        公网入口（TLS 反代，见第三节）—— 建议由 Nginx/Caddy 终结 wss/https
```

### 0.3 依赖顺序

`cloud-ws` 必须先起；`agent` 与 `viewer` 都连云端。三者版本号一致（v0.5.0）。

## 1. 前置条件

| 项 | 要求 | 备注 |
|---|---|---|
| 云端主机 | Windows / Linux，x64 | 本机现为 Windows |
| Node.js | **≥ 24**（生产实测 v24.14.0） | 云端用 `node:sqlite`（实验特性）落盘指令队列，低版本无此模块 |
| 被控端 | Windows 10/11 教室机，管理员权限 | 需要交互会话（锁屏/输入注入/抓屏） |
| 管理端 | Windows 10/11 老师机 | |
| 域名 | 一个可解析到云端公网 IP 的域名 | 用于 TLS（wss/https）。若走 Cloudflare 隧道可省公网 IP |
| 证书 | TLS 证书（Let's Encrypt 即可） | 反代终结 |
| 磁盘 | 云端 ≥ 5GB 空余；被控端 ≥ 2GB | 云端日志/队列会增长，需日志轮转（见运维手册） |

## 2. 云端部署

### 2.1 就位

1. 拷贝整个 `Stelarith-cloud-ws` 目录（含 `src/`、`package.json`、`node_modules/`、`run-cloud.cmd`、`cloud-watchdog.cmd`）到目标机，例如 `D:\Stelarith\Stelarith-cloud-ws`。
2. 若无 `node_modules`：`npm ci --omit=dev`（唯一依赖 `ws`）。

### 2.2 生产配置 `.env`

复制 `.env.example` 为 `.env`，**逐项换成生产值**（生成方法见《配置与凭据清单》）：

```ini
CLOUD_WS_PORT=8788
# 被控端接入令牌（教室机 agent.env 的 STE_QT_WS_TOKEN 必须与之一致）
CLOUD_WS_TOKEN=<强随机 32+ 位>
# 管理端长期令牌（老师机 viewer.env 的 STE_VIEWER_TOKEN 必须与之一致）
CLOUD_VIEWER_TOKEN=<强随机 32+ 位>
# 浏览器票据签名密钥，必须与站点 .env 的 CLOUD_VIEWER_SECRET 一致
CLOUD_VIEWER_SECRET=<强随机 32+ 位>
CLOUD_HEARTBEAT_TIMEOUT_MS=30000
CLOUD_SWEEP_INTERVAL_MS=5000
CLOUD_EVENTS_FILE=events.log
# 监听地址：直连公网用 0.0.0.0；若同机有反代，建议 127.0.0.1（见第三节取舍）
CLOUD_WS_HOST=127.0.0.1
# OTA 清单文件（发布新版本时更新，见《OTA 发布与升级说明》）
CLOUD_OTA_MANIFEST_FILE=ota.json
CLOUD_QUEUE_DB_FILE=instruction-queue.db
```

> ⚠️ **启动即自检**：云端启动会检查三项令牌，若仍为内置开发值会**打印醒目告警**。生产日志里不应再出现这类告警。

### 2.3 启动方式（二选一）

**方式 A · 计划任务（推荐，开机自启 + 崩溃自愈）**

- `StelarithCloud`：触发器 `At startup`，运行身份 `SYSTEM`，执行 `run-cloud.cmd`。
  ```bat
  schtasks /create /tn StelarithCloud /tr "D:\Stelarith\Stelarith-cloud-ws\run-cloud.cmd" /sc onstart /ru SYSTEM /rl HIGHEST /f
  ```
- `StelarithCloudWatchdog`：每 5 分钟检查 8788 是否在监听，不在则拉起（`cloud-watchdog.cmd`）。
  ```bat
  schtasks /create /tn StelarithCloudWatchdog /tr "D:\Stelarith\Stelarith-cloud-ws\cloud-watchdog.cmd" /sc minute /mo 5 /ru SYSTEM /rl HIGHEST /f
  ```

**方式 B · 手动前台**（调试用）
```bat
cd /d D:\Stelarith\Stelarith-cloud-ws
"C:\Program Files\nodejs\node.exe" --env-file=.env src\index.js
```

### 2.4 验证

```bash
# 本机：能连上即说明在监听
curl -H "Authorization: Bearer <CLOUD_VIEWER_TOKEN>" http://127.0.0.1:8788/api/devices
# 期望：{"ok":true,"count":N,"devices":[...]}
```
启动日志应出现：`[cloud] 云端监听 http://127.0.0.1:8788 （被控端路径 /ws/agent，协议模式 v1-compat）`。

## 3. 公网暴露与 TLS（关键安全步骤）

云端本身只跑**明文 ws/http**。公网必须靠**反代终结 TLS**，对外提供 `wss://` 与 `https://`。

### 3.1 两种拓扑的取舍

| 拓扑 | `CLOUD_WS_HOST` | 说明 |
|---|---|---|
| **同机反代（推荐）** | `127.0.0.1` | 云端只绑回环，公网入口只有反代；云端不直接暴露，攻击面最小 |
| 直连公网 | `0.0.0.0` | 云端直接监听公网，**必须**已换生产令牌 + 主机防火墙仅放行反代/必要来源；不推荐 |

### 3.2 Nginx 反代示例（同机）

```nginx
# 被控端与管理端的 WebSocket 共用一台云端，故统一 upgrade 透传
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
    listen 443 ssl http2;
    server_name control.example.com;

    ssl_certificate     /etc/letsencrypt/live/control.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/control.example.com/privkey.pem;

    # 被控端 / 管理端 WebSocket（长连接：关缓冲、放大超时）
    location /ws/ {
        proxy_pass http://127.0.0.1:8788;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_buffering off;
    }

    # 管理面 HTTP（含 /api/ota/latest）
    location /api/ {
        proxy_pass http://127.0.0.1:8788;
        proxy_set_header Host $host;
    }

    # OTA 安装包分发（把安装包放此目录，供教室机下载）
    location /ota/ {
        alias /srv/stelarith-ota/;
        autoindex off;
    }
}
```

### 3.3 Caddy 反代示例（更省事，自动证书）

```
control.example.com {
    handle /ws/* {
        reverse_proxy 127.0.0.1:8788 {
            header_up Upgrade {http.request.header.Upgrade}
            header_up Connection {http.request.header.Connection}
        }
    }
    handle /api/* { reverse_proxy 127.0.0.1:8788 }
    handle /ota/* { root * /srv/stelarith-ota; file_server }
}
```

### 3.4 启用后的地址改写

TLS 就绪后：
- 被控端 `agent.env` → `STE_QT_WS_URL=wss://control.example.com/ws/agent`
- 管理端 `viewer.env` → `STE_VIEWER_URL=wss://control.example.com/ws/viewer`
- OTA 清单 `ota.json` 里的 `url` → `https://control.example.com/ota/...`

## 4. 被控端部署（教室机）

### 4.1 安装包

- NSIS 安装器：`Stelarith-control-qt\dist\stelarith-agent-setup.exe`
- MSI（企业批量/组策略）：`Stelarith-control-qt\msi\stelarith-agent-msi.msi`

> 二者装到同一目录 `C:\Program Files\Stelarith\`，注册表各自独立，可共存；但卸载一个不会卸另一个。**生产上择一**。

### 4.2 装机参数（安装向导会问）

| 参数 | 示例 | 说明 |
|---|---|---|
| 云端地址 | `wss://control.example.com/ws/agent` | |
| 设备令牌 | 与云端 `CLOUD_WS_TOKEN` 一致 | |
| 设备 uid | `CLASS101-PC01` 之类**唯一**代号 | 建议「班级-座位」命名，便于识别 |

安装器会把三项写进 `C:\Program Files\Stelarith\agent.env`，并调用 `install-autostart.ps1` 建立**登录触发器计划任务** `StelarithAgentQt`（交互会话、最高权限）。

### 4.3 为什么是「登录任务」而非 Windows 服务

真正的 Service 跑在 **Session 0**，拿不到交互桌面 —— 锁屏 / 输入注入 / 抓屏全会打在空白会话上。故必须以登录用户身份、在其自身会话运行。**这是有意设计，不要改成 Service。**

### 4.4 静默批量装机

```bat
stelarith-agent-setup.exe /S
rem /S 走 .onInit 默认值（ws://127.0.0.1:8788/ws/agent + uid=TEST1），装完需改 agent.env 再重启
```
批量场景建议：先 `/S` 静默装，再用脚本统一覆写 `C:\Program Files\Stelarith\agent.env` 后重启计划任务。

### 4.5 验证

- 托盘出现图标（Windows 10/11 默认折叠，需在托盘设置里"显示全部"）。
- 云端 `/api/devices` 能看到该 uid 在线，`version` 为 `0.5.0`。
- 教室机日志：`%LOCALAPPDATA%\xingjikong\agent-qt.log`。

## 5. 管理端部署（老师机）

1. 拷贝 `Stelarith-viewer-qt\deploy\` 全量到老师机（含 Qt 运行时 DLL）。
2. 编辑 `viewer.env`（与 `viewer-qt.exe` 同目录）：
   ```ini
   set "STE_VIEWER_URL=wss://control.example.com/ws/viewer"
   set "STE_VIEWER_TOKEN=<与云端 CLOUD_VIEWER_TOKEN 一致>"
   ```
3. 双击 `viewer-qt.exe`，登录后设备列表应出现教室机。
4. 打包：`Stelarith-viewer-qt\msi\stelarith-viewer-msi.msi`（可选）。
5. 日志：`viewer-run.log`（工作目录下，可用 `STE_VIEWER_LOG` 指定）。

> 浏览器端（手机集控页）不在此线：它由站点签发**短票据**登录云端，票据通道要求云端 `CLOUD_VIEWER_SECRET` 与站点一致。

## 6. 上线验收清单

- [ ] 云端启动日志无「内置开发令牌」告警；三项令牌均为生产强随机值。
- [ ] 云端在反代后用 `https://域名/api/devices` 带令牌可访问；不带令牌 **401**。
- [ ] 至少一台教室机 `agent` 用 `wss://` 连上，`/api/devices` 显示 `version=0.5.0`。
- [ ] 管理端能订阅该机、看到实时画面（RTC 走通，日志 `state:streaming`）。
- [ ] 下发一条无害指令（如 `ping`），管理端看到回执 `done`。
- [ ] 断网重连：拔网线/停云端 20 秒后恢复，被控端自动重连、画面恢复。
- [ ] OTA：`/api/ota/latest?product=agent` 返回清单；**先在一台灰度机**验证自更新（见 OTA 文档）。
- [ ] 看门狗：手动 kill 云端进程，5 分钟内自愈。

## 7. 需要你（用户）提供的环境资源

> 以下是「我来写文案、你供资源」中**你**需要准备的部分。给齐后即可按本手册施工。

1. **服务器**：云端主机的系统、公网 IP（或 Cloudflare 隧道）、可给的 SSH/RDP 方式。
2. **域名**：用于 `wss/https` 的域名，及你是否已有 DNS 解析权。
3. **TLS**：是否有现成证书（Let's Encrypt / 商业）；若无，反代能否自动签发（Caddy / certbot）。
4. **反代选型**：Nginx / Caddy / Cloudflare Tunnel / 其他网关（本手册给了 Nginx 与 Caddy 两套示例）。
5. **OTA 资源位**：安装包托管在哪 —— 站点（8090）静态目录 / 对象存储（OSS/COS/S3）/ 反代 `/ota/`。
6. **班级与设备命名规则**：`uid` 命名约定（如 `CLASS101-PC01`），以及设备清单（多少台、分布）。
7. **被控端令牌策略**：全校共用一把 `CLOUD_WS_TOKEN`，还是分校/分批多把（当前云端只支持单令牌）。
8. **是否已有站点线**：浏览器集控页所需的 `CLOUD_VIEWER_SECRET` 由站点侧配置，需一并协调。
