## 四、两项异常的处理与结论

### 4.1 `regression-recordings.cjs` 静态下载 401 —— **测试脚本过时**（非回归）

```
❌ 静态下载 mp4 — status=401 type=application/json bytes=159
```

- **测试脚本**第 84 行：`req('GET', '/recordings/<uid>/<fname>', null)` —— **不带令牌**。
- **云端实现**（`src/index.js:255-266`）注释写得很清楚：
  > ⚠️ 2026-10-08 补鉴权：实测枚举 URL（`rec-<ISO时间戳>.mp4` + 可猜 uid）可无令牌直接下载
  > 任意班级监控录像，且 `cache-control: public` 一年 ——「URL 不可知」不成立。
  > **现在回放下载与列表同鉴权（Bearer CLOUD_VIEWER_TOKEN 或票据），无令牌 401。**

⇒ **实现是有意的安全加固，脚本断言未同步**（10-08 之后没更新）。**产品行为正确**。

**佐证**（隔离实例手工验证，`VERIFY999`）：

| 动作 | 结果 |
|------|------|
| 上传（设备令牌） | `200` + `{"ok":true,"fname":"rec-...Z.mp4","bytes":3000}` |
| 无令牌静态下载 | **401** ✓（符合加固后的预期） |
| 带 `Bearer dev-viewer-token` 静态下载 | 404 —— 见 4.2（**另一个真问题**） |

### 4.2 发现：静态托管**未贯通** `CLOUD_RECORDINGS_DIR`（**既有 bug，未修**）

```js
// src/index.js:620-622
const RECORDINGS_ROOT = process.env.CLOUD_RECORDINGS_DIR
    ? resolve(process.env.CLOUD_RECORDINGS_DIR)
    : join(__dirname, '..', 'recordings');

// 上传 / 列表 —— 走 RECORDINGS_ROOT ✓（673/675/690/691/692 行）
// 静态托管 —— 硬编码 ✗
const file = join(__dirname, '..', 'recordings', rel);   // ← 第 271 行
```

**后果**：一旦设了 `CLOUD_RECORDINGS_DIR`（这正是给隔离测试用的开关），
**上传的录像能存、能出现在列表，但播放/下载一律 404**（写在一处、读在另一处）。

- 生产**未设该 env**（默认 `join(__dirname,'..','recordings')`）⇒ 读写一致 ⇒ 现网不受影响。
- 但这是 2026-10-09 加 env 覆盖时**漏改静态托管**留下的坑：**谁按文档用这个 env 做隔离，谁就踩**。
- 刚才 4.1 手工验证的 404 就是这个 bug 的直接表现（文件确实写进了隔离目录，静态托管却去工程目录找）。

**修法（一行）**：第 271 行改用 `join(RECORDINGS_ROOT, rel)`。
**未修** —— 属「顺带发现」，不在本轮点单范围（红线：不擅自扩大改动范围）；**列此等点单**。

## 五、隔离副作用与处置（我的失误，如实记账）

**首次启动隔离实例时漏设 `CLOUD_RECORDINGS_DIR`** ⇒ 录制根退回硬编码工程目录
⇒ `regression-recordings.cjs` 把测试 mp4 写进了
`Stelarith-cloud-ws/recordings/REC440/rec-2026-10-15T161750099Z.mp4`（1500 B）。

- 该目录在测试前**不存在**、且**未被 `.gitignore` 忽略**（会误入版本库）。
- **处置**：停实例 → 以**可逆方式**（`mv`，非 `rm`）移出到
  `<Temp>/ste-removed-recordings-20261016/recordings/` 留证 → 确认工程目录恢复原状。
- 随后重启实例**补上 env** 复跑，确认 upload 落在隔离目录、工程目录不再出现 `recordings/` ✓
- **最终状态**：三仓工作区无 `recordings/` 残留（已 `git status` 核验）。

> ⚠️ 教训固化：`src/index.js:619-621` 自己就写着「测试必须设 `CLOUD_RECORDINGS_DIR` 指到临时目录」——
> 这条注释上一行就是，**启动前该先读它**。
