- **位置**：`island.cpp:478-486`（`QRect(rect().right()-16-kOpenBtnW, rect().top()-8, kOpenBtnW, height()+16)`）／`island.cpp:523`（用 `ev->pos()` 判定）
- **问题**：鼠标/触摸事件的局部坐标必然落在 `rect()` 内（`0..w-1, 0..h-1`），`top()-8` 到 `top()`、`bottom()` 到 `bottom()+8` 这上下各 8px **不可能被命中的坐标**；实际可点高度仍是 `height()`（收起 56 / 空闲 36），并没有变成 72/52。归档与注释声称"实际可点高度 = 整行（36px 也够 40px 触控下限附近）"是把无效 padding 当成了有效区。
- **依据**：`QWidget::rect()` 语义 + `hitOpenButton()` 只接收 `ev->pos()`；`QMouseEvent::pos()` 对该 widget 恒在 rect 内。
- **建议**：把容差体现在**窗口尺寸**上（例如把岛的可用区/绘制区做高一点），或只在 x 方向放宽；若要真正的 44px 触控目标，就把 `Shape::Idle`/`Collapsed` 的高度调上去，别把命中矩形画到窗外。

### 中等-2 手势用**窗口局部坐标**做基准，而岛自身在动画中会位移 ⇒ 判据被窗口位移污染
- **位置**：`island.cpp:496`（`m_pressPos = ev->pos()`）／`island.cpp:504`（`dy = ev->pos().y() - m_pressPos.y()`）／`island.cpp:523`（release 用当时的 `rect()` 判命中）／`island.cpp:67-68`、`268-274`（几何动画 380ms、OutBack）
- **问题**：一旦下拉超过 24px 触发 `setExpanded(true)`，窗口 top 从 y=10 变到 y=24、高度 36→168 并在 380ms 内缓动。手指停在原地不动，局部 y 也会因为窗口下移而变小，下一帧算出的 `dy` 里混进了**窗口自身的位移**：上推/下拉的判定阈值在动画期间失真（表现为"轻轻回推就收起/继续下拉反而不触发"），形成自己追自己的反馈；release 时 `hitOpenButton` 也是在（可能仍在动画中的）`rect()` 上判。OutBack 还会过冲，问题更明显。
- **依据**：`ev->pos()` 是 widget 局部坐标；`showIsland`/`enterIdle`/`setExpanded` 都可能在按住期间启动几何动画。Qt 会给按下者保持隐式 grab，所以事件不会丢，但坐标基准会变。
- **建议**：手势基准改用 `ev->globalPosition()`（或按下时 `mapToGlobal(pos)` 存全局点）比较；判定按钮命中时用"按下那一刻"的几何，或在 `m_geoAnim` 运行期间（`state()==Running`）忽略手势/命中判定。

### 中等-3 `m_pressPos.isNull()` 当"没按下"的哨兵不可靠；release 不校验按键
- **位置**：`island.cpp:503`（`m_pressPos.isNull()` 早退）／`island.cpp:517`、`521`（用 `QPoint()` 复位）／`island.cpp:512-520`（`mouseReleaseEvent` 未判 `ev->button()`）
- **问题**：局部 `(0,0)` 是合法按下点（可交互时窗口左上角会被投递鼠标事件，`paintEvent` 只把绘制内容 `adjusted(1,1,-1,-1)`），此时 `isNull()` 为真，后续 `mouseMoveEvent` 全部 `ignore()`，手指下拉手势失效。另外 `mousePressEvent` 判了左键（`491`），`mouseReleaseEvent` 没判 —— 右键/中键抬起会被当成左键点击去 `setExpanded(true)`。
- **依据**：`QPoint()` 默认构造即 `(0,0)`，与"未按下"共用同一个值。
- **建议**：加独立 `bool m_pressed = false`；release 首行补 `if (ev->button() != Qt::LeftButton) return;`。

### 中等-4 `enterIdle()` 改状态不 `emit expandedChanged(false)`
- **位置**：`island.cpp:196-231`（直接 `m_expanded = false`）／对比 `island.cpp:246`、`253`、`265`（`setExpanded` 的三条 emit）
- **问题**：`dismiss()→enterIdle()` 这条最常用的收起路径不发 `expandedChanged(false)`，于是 `isExpanded()` 已是 false 而最后一次信号是 true —— 对外状态与信号不自洽。当前 `main.cpp` 没有接这个信号（已检索确认），属于埋雷而非现网故障。
- **建议**：所有改 `m_expanded` 的地方收口到一个 setter（内部负责 emit），或在 `enterIdle()` 里显式补 `emit expandedChanged(false)`。

### 中等-5 四个布尔没有单一真源，分支间不一致
- **位置**：`island.cpp:198-210`（`!m_idleEnabled` 分支不重置 `m_contentActive`）vs `island.cpp:215`（空闲分支才置 false）／`island.cpp:133-179`（`showIsland` 不动 `m_expanded`）／`island.cpp:181-185`（`setIdleEnabled(false)` 直接 `hide()` 但保留 `m_interactive=true`、不清 `m_idle`）
- **问题**：① `m_contentActive` 在两个 `enterIdle` 分支里处理不对称，之后 `setExpanded(false)` 的 `!m_contentActive` 判断（`251`）会读到过期值；② `showIsland` 不改 `m_expanded`，上一条还处于展开态时来新内容会**维持 Expanded 高度直接换文案**，用户看到"上一屏还开着、内容被换了"；③ `m_idle=true`+`m_interactive=true`（空闲胶囊）与 `island.h:106` 注释"默认穿透"矛盾；`m_idle/m_expanded/m_interactive` 可以组合出无法描述的状态（如隐藏但可交互），代码里没有任何断言或收口。
- **建议**：用一个 `applyState(State)` 或 `enterX()/exitX()` 收口，把"进入某态要设置/清空哪些位、起停哪些定时器、emit 什么"列成一张表；`showIsland` 至少显式决定 `m_expanded` 的归零策略（建议新内容一律回到 Collapsed 或保留展开但保持文案与几何一致）。

### 中等-6 `setInteractive(false)` 用**上一条**的 `m_durationMs` 起自动关
- **位置**：`island.cpp:320-321`（`m_autoClose->start(m_durationMs)`）／`main.cpp:1937-1938`（先 `setInteractive(interactive)` 再 `showIsland(..., ms)`）／`island.cpp:139`（`m_durationMs` 在 `showIsland` 里才更新）
- **问题**：`islandShow()` 先调 `setInteractive`，此时 `m_durationMs` 还是上一条的时长；虽然紧接着 `showIsland` 会 `stop()+start(新时长)`（`174-176`），当前是靠调用顺序侥幸正确，换个调用顺序（例如外部先 `setInteractive(false)`）就会以旧时长触发 `dismiss()`。
- **建议**：`setInteractive` 里也 `m_autoClose->stop()`，或把"时长/交互/openPath"作为一次调用一并下发（由 `showIsland` 统一驱动），消除顺序依赖。

### 中等-7 `NotifyWindow` 顶掉旧窗时 `fadeOutClose()+deleteLater()` —— 淡出实际被掐掉
- **位置**：`main.cpp:1974-1978`（`g_notify->fadeOutClose(); g_notify->deleteLater();`）／`main.cpp:2082-2095`（220ms 淡出动画 + `finished→close()`）
- **问题**：`deleteLater()` 在下一个事件循环就销毁旧窗（连同它作为子对象的 220ms 动画），所以"旧的**淡出**再走"仍然是一刀切，和注释里"直接 hide() 会硬切，教室大屏上很扎眼"（`1975`）想要解决的观感问题一样；新窗与此同时淡入，视觉上是旧窗"啪"消失、新窗渐显。
- **依据**：`deleteLater()` 语义（事件循环内删除）；动画父对象为窗口（`main.cpp:2088` 第三参 `this`），随窗销毁。
- **建议**：顶掉旧窗时只调 `fadeOutClose()` 并把已发起的 `deleteLater()` 去掉（`fadeOutClose` 的 `close()` + `WA_DeleteOnClose` 已在 `2092-2093` 负责回收）；或在 `showNotice` 里把新窗的 `show()` 延后到旧窗 `finished` 之后再做交叉淡入。

### 中等-8 旧的 `NotifyWindow::Island` 形态仍然存在，会和新灵动岛叠在同一位置
- **位置**：`main.cpp:1961`（`enum Kind { Popup, Island, Fullscreen }`）／`main.cpp:2252`（`kind=="island"` → `NotifyWindow::Island`）／`main.cpp:2112-2119`（该形态摆在顶部居中、60% 宽、h=64、y=24）
- **问题**：云端/站点下发 `notify{kind:"island"}` 时仍走旧窗实现，而 `IslandOverlay` 的活动胶囊也在顶部居中（`island.cpp:117-131`，y=24）。两个都是 `Qt::FramelessWindowHint|WindowStaysOnTopHint|Tool`，会**同屏叠放**——正是本轮宣称统一掉的"各弹各的、教室大屏上叠成一摞"。归档第四节写"`NotifyWindow::showNotice(..., Island, ...)` 4 处 + 2 处新增 全部改为 `islandShow(...)`"，但映射分支（`2252`）没删，远程仍可走到。
- **建议**：`kind=="island"` 直接改调 `islandShow(title, content, "", seconds*1000)`，并删除 `NotifyWindow::Island` 枚举与 `showWindow` 里的对应分支，让"顶部通道"只剩一条。

### 中等-9 课表上下课提醒仍走居中弹窗，未接灵动岛
- **位置**：`main.cpp:4769-4771`、`main.cpp:4776-4778`（`NotifyWindow::showNotice(NotifyWindow::Popup, "上课啦"/"下课啦", ..., 6, true, "remind")`）
- **问题**：本轮目标是"被控端一切通知都经过灵动岛"，`notify`(`4315`)、远控(`3477`)、考试(`4354/4364`)、语音(`4699`)、断线(`4662`) 都接了，唯独每节课必触发的上下课提醒还在教室大屏正中央弹窗 6 秒（`Popup` 还额外进托盘通知中心，`2273-2275`）——正是最需要"不打断上课"的场景。
- **建议**：上下课提醒改走 `islandShow(..., 6000)`（另可按 `remind` 决定是否要确认）；`NotifyWindow` 只保留"要确认/要输入文本/全屏遮罩"三类。

### 中等-10 Session 0 / 无托盘时灵动岛仍会被懒创建并 `show()`
- **位置**：`main.cpp:4624-4628`（注释"有托盘 = 有桌面会话，Session0 那种无界面环境不摆窗口"，`ensureIdle()` 在托盘块内）／`main.cpp:1933`（`islandShow()` 里 `IslandOverlay::instance()`）／`main.cpp:4662`（断线回调在无托盘时照样调 `islandShow`）
- **问题**：守卫只包住了开机常驻那一次 `ensureIdle()`；只要 WS 上来了任何提示（断线重连提示是最常见的），`islandShow()` 就会 `instance()` 懒创建一个顶层窗口并 `show()` —— "Session 0 不摆窗口"的设计意图失效。
- **建议**：把桌面可用性判断放进 `IslandOverlay::instance()`/`islandShow()`（判 `g_tray` 或 `QSystemTrayIcon::isSystemTrayAvailable()`），或让 `islandShow` 在无托盘时直接 return。

### 中等-11 深浅色只在构造读一次、`setLightMode()` 全仓零调用、无 `colorSchemeChanged` 连接
- **位置**：`island.cpp:61-63`（构造时读 `styleHints()->colorScheme()`）／`island.cpp:305-310`（`setLightMode`）／`island.h:59`／`main.cpp` 全文件无调用（已检索确认）／`main.cpp:2189`、`2193`（`NotifyWindow` 硬编码深色）
- **问题**：系统切浅色后岛不会跟着变；`NotifyWindow` 恒深色，与岛的系统浅色态并存时三套视觉不一致。归档第六节第 4 条自己把这条列为"本轮发现但没动"。
- **建议**：在 `main.cpp` 里 `connect(QGuiApplication::styleHints(), &QStyleHints::colorSchemeChanged, ...)` → 两侧都刷（岛 `setLightMode`，`NotifyWindow` 补一套浅色配色）。

### 中等-12 只认 `primaryScreen()`，无分辨率/主屏变化监听，多屏落到错误显示器
- **位置**：`island.cpp:110`、`119`、`144`（每次都取 `QGuiApplication::primaryScreen()`）／`island.h:98`（`positionForCurrent()` 声明了但**没有定义**）
- **问题**：教室投影切换分辨率/主副屏切换是常态；岛的位置一旦算出就不再重算，可能出现"岛留在旧坐标甚至屏外"。教室大屏常接成副屏，此时岛会出现在老师机主屏而非学生看到的那块屏。
- **建议**：监听 `QGuiApplication::primaryScreenChanged`/`screenAdded`/`QScreen::geometryChanged` 并在这些时机重算当前位置；屏幕选择做成可配项。顺带把 `positionForCurrent()` 真正实现（或从 `island.h:98` 删掉）。

### 中等-13 `Qt::UniqueConnection` 对 lambda 不生效，两处连接都会照常建立
- **位置**：`island.cpp:207-208`、`island.cpp:299-301`
- **问题**：Qt 对仿函数/非成员函数（含 lambda）无法做"同一信号-同一接收者-同一槽"的比较，运行时会打印 `unique connections require a pointer to member function of a QObject subclass` 并**照样建立连接**（见 [MuseScore issue #24716](https://github.com/musescore/MuseScore/issues/24716) 的告警原文）。所以这两处以为加了"防重复"，实际每调一次 `dismiss()`/`enterIdle()` 就多挂一条 `finished→hide`，与严重-3 叠加。
- **建议**：不用 `Qt::UniqueConnection` 配 lambda；改为成员函数槽（可比较）或自己保存 `QMetaObject::Connection` 做去重/断开。相关连接生命周期语义见 [QObject::connect 文档](https://doc.qt.io/qt-6.8/qobject.html)。

### 中等-14 资源与死代码：单例永不析构、淡出动画每次新建、两个私有函数只有声明
- **位置**：`island.cpp:40-45`、`102-105`（裸 `g_island`、无 parent、`~IslandOverlay` 永远跑不到，`g_island=nullptr` 是死代码）；`main.cpp:2088`（`fadeOutClose` 每次 `new QPropertyAnimation`，紧急通知被连点即累积多条同目标动画，虽随窗释放但会互相抢 opacity）；`island.h:91`（`applyTheme()`）、`island.h:98`（`positionForCurrent()`）**只有声明、全文件无定义**；`island.h:67-68` 注释仍写"鼠标按下就直接打开"与 release 实现不符；`island.cpp:400`/`465`/`477`/`483` 的 `hintW=34`、`kOpenBtnW=44`、硬编码 `16` 三处必须手工保持同步（当前恰好对齐，改动即错位）
- **问题**：单例泄漏属进程级可接受，但"看起来有能力（主题重算/重定位）其实没有"的声明、以及三处几何常量的隐式耦合会持续误导后续维护者。
- **建议**：删掉无定义的声明或补实现；`fadeOutClose` 复用一条动画成员并在 `m_closing` 时早退；把"右侧打开区"的几何算成一个常量表达式，绘制与命中共用。

### 中等-15 `openInShell()` 失败全静默，且文件被删后「▸ 打开」入口仍在
- **位置**：`island.cpp:341-349`（`fi.exists()` 为假直接 return；`QProcess::startDetached` 的返回值不看）／`main.cpp:3574`、`main.cpp:3584`（失败/取消时删除文件，但岛与 `m_openPath` 不会同步失效）
- **问题**：学生点「▸ 打开」后如果文件已被删除、explorer 被策略禁用、或 `startDetached` 失败，**界面上没有任何反馈、日志里也没有一行**——与项目"不许静默失败"的纪律相悖（`main.cpp:3-4`）。结合严重-1，这个状态在"接收被取消"后必然出现。
- **建议**：`openInShell()` 失败时 `qWarning()` 一行并把岛文案改成"文件已不存在/打开失败"；`file_done` 删除文件的分支同步 `clearOpenPath()` 并顶掉那条岛。

### 中等-16 几何动画用 `OutBack` 过冲，且没有"动画中"标志
- **位置**：`island.cpp:67-68`（380ms `QEasingCurve::OutBack`）／`island.cpp:268-274`（每次 `stop()+setStart/setEnd+start`）
- **问题**：`OutBack` 会越过目标值（几何过冲 ⇒ 顶层窗短暂超出 60% 屏宽上限、位置越过 y=24），与中等-2 的坐标基准问题互相放大；机房通知成串时 `animateGeometry` 被反复打断重来，岛看起来在抖；判定手势/命中时也没有"几何动画进行中"的保护。
- **建议**：为几何动画加 `m_animatingGeo` 标志（期间忽略手势与按钮命中），或几何用不过冲的曲线（`OutCubic`）、把果冻感只留给透明度。

## 最危险的 2 点

1. **`file_push` 的"收到文件"提示时机错了 —— 默认配置下必然发生的假成功**（严重-1，`main.cpp:3677-3690` / `3591-3598` / `island.cpp:345`）。它在**会话开始**就对外宣告"收到文件"并交出「▸ 打开」入口，而真正的校验完成点 `file_done` 反而静默；发送端取消或字节不符时文件已被 `QFile::remove`，岛上仍写着收到、点「打开」毫无反应。这既是项目红线"绝不报 done 其实没做"的违反，也是在教室机上把"半截/不存在的文件"推给学生去点——建议本轮就修（提示挪到 `file_done` 成功分支 + 失败/取消分支顶一条状态）。
2. **常驻空闲岛的"可交互 + 不自动关 + 点一下收不回"三件套，会把教室大屏顶部变成一块永久吃点击的遮挡**（严重-2，`island.cpp:221`/`95`/`175`/`235`/`537`）。默认配置（`STE_QT_ISLAND_IDLE` 缺省开）下开机即生效：从空闲点开后既不能靠再点一下收回，也不会超时回收，唯一出路是 ≥24px 的向上拖拽；期间那块 168px 高、最宽 640px 的岛不穿透，直接挡掉下层课件/白板的点击。文件提示（`interactive=true`）同理。
（次危险：严重-3 的 `finished→hide` 残留连接——它在 `STE_QT_ISLAND_IDLE=0` 下会让第一条之后的每次提示都只剩 220ms，且不报错、不崩溃，最容易在"改开关试探"时才炸。）
