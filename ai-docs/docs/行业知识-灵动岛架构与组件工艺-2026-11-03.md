# 星集控「灵动岛」：架构、组件工艺与行业对照

> 信源等级：✅ = 仓库源码一级信源（`Stelarith-control-qt` / `Stelarith-viewer-qt` / `Stelarith-shared-qml`）；🟡 = 合理推断；❓ = 本环境联网受限（HTTP 402）未查证。
> 本篇以星集控自研的「灵动岛（Island）」面板系统为样本，讲清一个**教室集控前端**在"通知 vs 看板""常驻 vs 临时""C++ 大脑 vs QML 皮肤"三对张力里的工程取舍。它也是本项目 §10.7 / §10.9（强类型数据契约 + 纯净 UI）最完整的落地样板。

---

## 0 · 电梯演讲

灵动岛是星集控被控端屏幕**顶端的一条常驻信息带**：平时只显示「概览」（当前通知 / 状态一句话），老师或集控云端下发指令时，它展开成对应的"面板"——今日课表、媒体进度、倒计时、日期周次、批注、音量、自动化。

它不是"又做了个弹窗"，而是一次**架构立场声明**：

```
┌──────────────────────────────────────────────────────────┐
│  顶部灵动岛（常驻一条，约 40px 高）                          │
│  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐            │
│  │ 概览 0 │  │ 今日 7 │  │ 媒体 1 │  │ ……  │            │
│  └────────┘  └────────┘  └────────┘  └────────┘            │
├──────────────────────────────────────────────────────────┤
│  主屏（被控画面 / 教学桌面）                                │
└──────────────────────────────────────────────────────────┘
        ▲ 展开成面板（点一下 / 云端下发 / 自动常驻）
        │
  通知（事件，6秒走）   vs   面板（看板，停看清、可常驻）
```

**一句话**：灵动岛 = 教室大屏的"状态仪表盘 + 轻交互入口"，对标 ClassIsland 的"组件"体系，但走的是 Qt/C++ 大脑 + QML 皮肤的纯净 UI 路线。

## 1 · 八块面板清单（✅ 来自 `island_layout.cpp`）

| id | 标签 | 标题 | 数据来源 | 默认开 | 说明 |
|----|------|------|----------|--------|------|
| 0 | 概 | 概览 | 通知/状态聚合 | ✅ | 兜底面，永远有；其他面都没开时它顶上 |
| 7 | 今 | 今日课表 | 课表域（ScheduleModel） | ✅ | 今天全部课程、当前节高亮、距下课倒计时 |
| 1 | 媒 | 媒体 | 媒体会话（MediaSession） | ✅ | 正在播放曲目/进度；没在播就不出现（requiresLive） |
| 4 | 笔 | 批注 | 桥（IslandBridge） | ✅ | 画笔/批注工具，默认收起 |
| 5 | 设 | 音量设置 | 桥 | ✅ | 系统音量 / 通知音量 / 通知黑名单 |
| 6 | 自 | 自动化 | 自动化引擎 | ✅ | 本机规则列表；无规则不出现（requiresLive） |
| 8 | 期 | 日期周次 | PanelDomain::buildDate | ❌ | 今天日期/星期/第几教学周（2026-11-03 新增，默认关） |
| 9 | 倒 | 倒计时 | PanelDomain::buildCountdown | ❌ | 距指定时刻；管理端可设目标（2026-11-03 新增，默认关） |

> ⚠️ **死 id 不复用纪律**：id 2（「史」）与 id 3（「态」）已由用户裁决移除。**绝不复用这两个号**——老机器磁盘上可能还留着它们，复用会让旧配置指向错的面。新面用 8/9，跳过了这两个废弃号。

布局顺序、开关、缩放（80%–140%）由 `IslandLayoutModel`（`QAbstractListModel`）持有，落 `QSettings` 键 `island/layout`。**磁盘只存用户可改的三项**（enabled / scale / order），文案永远取内置，被改坏就认默认、绝不弹错。

## 2 · 架构分层：C++ 大脑 + QML 皮肤（✅ §10.7 / §10.9 落地样板）

```
┌──────────────────────── 云端(8788) ────────────────────────┐
│  下发 island_panel / notify / island_panel_close 指令        │
└───────────────────────────┬────────────────────────────────┘
                            │ WebSocket（带令牌鉴权）
┌──────────────────────── 被控端 control-qt ─────────────────┐
│  C++ 大脑（算数、联网、持状态）                               │
│  ├─ execute_notice.cpp  解析指令词，白名单校验               │
│  ├─ PanelDomain        纯计算：buildDate / buildCountdown    │
│  ├─ IslandLayoutModel  面板清单（QAbstractListModel）        │
│  ├─ IslandPanelSource  Q_INVOKABLE dateInfo/countdownInfo   │
│  └─ IslandBridge       状态机（展开/收起/按住不收/触摸）     │
│         │  context property 注入                              │
│         ▼                                                    │
│  QML 皮肤（只画、只点，不连网不解析 JSON）                   │
│  ├─ IslandRoot.qml       调度：case 0/7/1/4/5/6/8/9 → comp  │
│  ├─ IslandDateFace.qml                                    │
│  ├─ IslandCountdownFace.qml   只读 panelSource.countdownInfo()│
│  └─ …… 共 8 个面组件                                       │
└───────────────────────────────────────────────────────────┘
```

**三条铁律在灵动岛的体现**：

1. **强类型数据契约（§10.7）**：面板数据一律从 `QAbstractListModel` / Q_INVOKABLE 出，QML 用 `panelSource.dateInfo()` 直接拿 `QVariantMap` 字段（`time`/`weekNum`/`targetMs`…）。**不是**把原始 JSON 字符串丢给 QML 去 `JSON.parse`（那正是 §10.9 要消灭的反模式）。
2. **纯净 UI（§10.9）**：QML 里**零** `XMLHttpRequest` / `WebSocket` / `fetch` / `JSON.parse`（业务）。所有脏活（联网、课表解析、NTP 偏移）在 C++。QML 只 `backend.xxx` / `panelSource.xxx` + 画。
3. **失败口径透明**：`build()` 失败时返回**带 error 的空对象**，QML 必须能区分"今天没课"（事实）与"课表没接上"（故障）。倒计时面据此写「未配置」而非画一个 `00:00`（00:00 会被误读成"正好到点"，是最坏的一种错）。

## 3 · 数据流：一条倒计时是怎么走到屏幕上的（✅）

以管理端下发 `island_panel{face:"countdown", to:"12:30", label:"午休"}` 为例：

```
管理端 viewer-qt ──WS──▶ 云端 ──WS──▶ 被控端 execute_notice.cpp
                                       │ action=="island_panel"
                                       ▼
                              PanelDomain::show("countdown", params, …)
                                       │ face=="countdown"
                                       ▼
                              PanelDomain::buildCountdown(params, &r)
                                       │ params 含 to/label/title ⇒ 用指定目标
                                       ▼
                              r.data = {targetMs, nowMs, skewMs, label, note, targetText}
                                       │
                          ┌────────────┴─────────────┐
             临时面板（durationSec）         常驻面板（灵动岛展开区）
                          │                          │
                  IslandPanelSource                  IslandPanelSource
                  .countdownInfo()                   .countdownInfo()
                          │  context property         │  context property
                          ▼                          ▼
                  IslandCountdownFace.qml     IslandCountdownFace.qml（常驻）
                          │  leftMs = targetMs − (nowMs + 打开后墙钟)
                          ▼
                  大数字 "01:02:33" 每秒走字，到点停 "时间到"
```

**关键设计点（✅ 来自 `IslandCountdownFace.qml` 注释）**：

- 剩余量 `remaining = targetMs − (nowMs + 本面打开后经过的墙钟)`。`nowMs` 是 C++ 的**判定时间**（系统钟 + NTP 差 + 人工偏移）。学校铃声整体偏移 3 分钟时，倒计时必须跟着偏移后的"上课时刻"走——**绝不改读系统钟**。
- 到点之后显示「时间到」并停在 `00:00`，**不自动关闭面板**（自动关会让人怀疑"是不是没到点就没了"）。

> 🟡 **当前缺口**：`IslandPanelSource::countdownInfo()` 现在硬编码空 `QJsonObject` 调 `buildCountdown`，即常驻倒计时面只算课表边界（距下课/距上课），**还读不到管理端下发的 `to` 目标**。管理端→被控端的 `island_panel` 通路本身已通（`execute_notice.cpp:166` 原样透传 `params`），缺口只在"常驻面把目标持久化/透传"这一环。这是下一个待点单的尾巴。

## 4 · 常驻 vs 临时：两种生命周期（✅）

```
                   下发 island_panel
                          │
            ┌─────────────┴──────────────┐
      durationSec > 0              durationSec == 0（常驻）
            │                             │
      临时面板，到点自动收          停在灵动岛展开区，直到
      （或下一条通知顶掉）          island_panel_close / 下一条顶掉
```

- 面板走岛**展开区**且可以常驻；不像通知那样 6 秒收走（课表看 5 秒根本读不完，`execute_notice.cpp:171` 把面板默认时长设为 60s，且允许 `durationSec:0` = 常驻）。
- **"按住不收"**：岛的展开态有"按住锁定"手势（搬家到 `island_touch.cpp`，三层闸：QML onPressed/onReleased/onCanceled + 原生事件 + 180s 兜底），防止误触收起正在看的课表。

## 5 · 五个工艺纪律（本项目可复用的经验）

| # | 纪律 | 反模式 | 出处 |
|---|------|--------|------|
| 1 | 面板数据强类型，绝不给 QML 原始 JSON | `JSON.parse` 业务串 | §10.7 / §10.9 |
| 2 | QML 只画只点，脏活全在 C++ | QML 里 `WebSocket`/`fetch` | §10.9 |
| 3 | 失败透明：区分"事实"与"故障" | 画 `00:00` 冒充"到点" | `IslandCountdownFace.qml` |
| 4 | 新面默认关，不惊扰现役机器 | 默认开=凭空改变所有旧机 | `island_layout.cpp:37` |
| 5 | 废弃 id 不复用 | 复用 2/3 让旧配置指向错面 | `island_layout.cpp:29` |

## 6 · 行业对照：灵动岛 vs ClassIsland 组件（✅/🟡）

| 维度 | 星集控灵动岛 | ClassIsland 组件 |
|------|--------------|------------------|
| 运行宿主 | 教室大屏被控端（Windows Qt） | 学生/教师机（WPF/.NET） |
| 目标用户 | 老师投屏时的状态带 + 轻交互 | 学生机桌面小组件 |
| 数据来源 | 云端集控下发 + 本机域计算 | 本机 + ClassIsland 集控服务器 |
| UI 技术 | QML（MD3/QtShadcn 令牌） | WPF XAML |
| 架构立场 | C++ 大脑 + QML 皮肤，纯净 UI | 逻辑在 ViewModel，XAML 绑定 |
| 下发通道 | WebSocket 带令牌，指令白名单 | HTTP 轮询 + 插件 |

> 两者在产品语义上高度同构（"组件"= 常驻看板），但星集控的灵动岛额外承担了**集控下发入口**（老师从管理端一键让全班大屏显示倒计时），这是 ClassIsland 组件偏"本机小组件"所没有的一层。
