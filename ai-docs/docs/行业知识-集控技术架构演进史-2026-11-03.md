## 0. 30 秒电梯演讲

> 终端集控（Endpoint Management）走过了四十年：从 1990 年代「机房管理员抱着软盘挨台装机、用 SNMP 看一眼打印机死没死」，到 2000 年代「Ghost 镜像 + PXE 网络克隆」的批量装机黄金期，再到 2010 年代智能手机逼出的 **MDM → EMM → UEM** 能力光谱升级，最后在 2020 年代被疫情远程办公/远程教学、零信任（ZTNA）与开源自托管浪潮推到现在。
> 一句话：**集控的本质，是「把 N 台设备当成一支舰队来管」的运维范式**，它从「管硬件」走到「管身份与数据」，从「强管控」走到「合规与体验平衡」。而 **Stelarith 星集控** 站在演进史的最末端——一个开源、可自托管、不绑硬件、面向全校教室屏幕的 Qt 三端集控平台，正好卡在「开源 + 自托管 + 全校集控 + 不绑硬件」这个长期空白的交集里。

## 1. 行业定义与边界：集控 ≠ 普通远控 ≠ 监控

「集控」这个词在中文语境里被用得很宽，但技术边界必须厘清。三个常被混为一谈的概念：

| 概念 | 本质 | 交互模型 | 典型代表 |
|---|---|---|---|
| **远程控制（Remote Control）** | 人 ↔ 人，实时接管一台机器的鼠标键盘 | 像素级实时投屏 + 操作注入 | TeamViewer / ToDesk / VNC |
| **监控（Monitoring）** | 单向采集状态，一般不主动处置 | 读指标、告警、看板 | Zabbix / Prometheus / 网管系统 |
| **终端集控 / 端点管理（Endpoint Mgmt）** | 管理员 ↔ 一群设备，一对 N 的持续运维 | 下发策略 + 订阅状态 + 离线指令队列 + 远程处置 | MDM / EMM / UEM / Stelarith |

关键差异：**远控是「临时握手」、监控是「只听不说」、集控是「长期指挥关系」**。集控平台一旦把设备纳管，就要处理 enrollment（入网注册）、策略下发、设备离线容错、OTA 升级、合规审计这一整套「生命周期」问题——这是远控软件和裸监控系统都回答不了的。

### 2.1 四个时代的脉络（🟡 合理推测为主，标 ✅ 处为公认事实）

- **1990s · SNMP + Active Directory 域控（✅ 已确认事实：SNMP 1988 标准化、AD 随 Windows 2000 普及为公认行业节点）**
  这一代的集控是「机房管理员视角」：用 SNMP 轮询交换机、打印机、服务器的存活与负载；用 AD 域控把账号、组策略、软件分发（GPO + SMS/AD 后期形态）集中到一台域控制器。它的思想是**「以设备/账号为中心、集中下发策略」**，这正是现代集控的雏形。局限：强绑定 Windows 生态，跨网段/跨组织几乎不可行，移动设备为零。

- **2000s · 镜像与克隆装机（🟡 合理推测）**
  随着 PC 在校园机房、网吧、办公网爆发，痛点变成「几百台同型号机器怎么快速装」。答案：Ghost 硬盘镜像 + PXE 网络启动 + 无人值守脚本。这一代把「批量同构部署」做到极致，但本质是**一次性交付**，没有「持续运维」能力——装完即失联，后续策略变更、故障回收仍靠人工。早期限域软件（如网吧管理、还原卡）也在此期成型。

- **2010s · 移动化催生 MDM → EMM → UEM（✅ 已确认事实：iOS 4/Android 2.x 起提供设备管控 API；Apple DEP、Google EMM API 为此期标志）**
  智能手机进校园、进企业，把「设备不再属于 IT 部门」这件事摆上台面。iOS/Android 的 MDM 协议让平台方第一次拥有「远程配置、锁屏、擦除、应用分发」的标准通道。随后 EMM 补上移动应用管理与安全容器，UEM 再把 Windows/macOS 桌面与 IoT 并入统一策略引擎。**这一代的核心转折：管控对象从「我买的电脑」变成「员工/学生自己的手机」，于是「合规」第一次压过「强管控」。**

- **2020s · 零信任 + 边缘 AI + 开源自托管（🟡 合理推测）**
  疫情把「远程办公/远程教学」从可选变成刚需，设备散落在千家万户的弱信任网络里，传统 VPN+边界防火墙失效，**零信任（以身份为中心、永不信任持续校验）与 SASE（安全访问服务边缘）**成为新范式。与此同时，数据主权、隐私合规（如未成年人数据）压力上升，商业云方案的「数据出境/黑盒审计」短板凸显，**开源自托管集控**作为对冲路线崛起。边缘 AI 则把一部分策略判断（异常行为识别、内容合规）从云端下沉到设备侧。

## 3. 范式转移：从「以设备为中心」到「以身份/数据为中心」

集控四十年的底层范式发生过两次位移：

```
 范式 1（1990s~2000s）          范式 2（2010s 移动化）        范式 3（2020s 至今）
 ┌──────────────┐             ┌──────────────────┐         ┌──────────────────┐
 │ 以设备为中心  │   ───►      │ 以身份为中心      │  ───►   │ 以数据/场景为中心│
 │ 设备=资产    │             │ 人=主体,设备=    │         │ 数据主权+体验   │
 │ 强管控优先   │             │ 载体,合规优先    │         │ 平衡,可审计     │
 └──────────────┘             └──────────────────┘         └──────────────────┘
   管「这台机器」                  管「这个人用过的所有端」        管「这份数据在哪、谁碰过」
```

同时，治理哲学从「能管则管」转向「合规 + 体验平衡」：过度管控会催生绕过（学生刷机、员工私装），所以现代集控强调**最小权限、可解释策略、用户侧可见性**。`🟡 合理推测`：这一转变与 GDPR（2018）、中国《个人信息保护法》（2021）等数据保护立法强相关，但本文未逐条核验法条原文（见末节待查证）。

- **L4 应用**：Stelarith 把课表/通知/广播/远控/媒体/批注统一收口到「灵动岛」面板（`✅ 已确认`：源码层面存在 `IslandTimetableFace` / `IslandMediaFace` / `IslandCountdownFace` / `IslandDateFace` / `IslandAnnotateFace` / `IslandPanelFace` 等多个面板）。

## 4. 开源 vs 商业：路线分歧与四象限矩阵

集控市场长期被「商业订阅 + 生态绑定」主导，但开源自托管是一条结构性对冲路线。两者的核心分歧不在功能多寡，而在**「谁掌握数据主权」与「是否被硬件/生态锁定」**。

```
        生态绑定强度（高 ▲）
              │
   商业闭源   │  [Jamf]        [Intune]
   强绑定     │  [Mosyle]      [VMware Ws1]
              │  [希沃/鸿合]    [科大讯飞]
              │   （硬件+云一体，数据在厂商侧）
              │
   ───────────┼──────────────────────────────► 部署自由度（高 ►）
              │
   开源自托管 │  ★ [Stelarith 星集控]
   弱绑定     │     （开源·可私有化·不绑硬件·数据在校内）
              │  [ClassIsland]（单班屏幕前端，互补）
              │  [MicroMDM / Headwind MDM 等]
              │
        生态绑定强度（低 ▼）
```

**矩阵一句话总结（🟡 推测）**：商业象限里，国外 Jamf/Intune 强在设备合规与生态完整，国内希沃/鸿合强在硬件捆绑（换非自家大屏即用不了）；开源象限里，通用 MDM 项目多在「设备管理」层面，而 **Stelarith 的独特卡位是「开源 + 自托管 + 全校集控 + 不绑硬件」四者交集，目前该交集几乎是空的**。`✅ 已确认`：Stelarith 仓库为开源形态（git 仓库、可本地构建、云端可私有化部署）。

商业路线的代价与开源自托管的代价对比：

| 维度 | 商业闭源（Jamf/Intune/希沃） | 开源自托管（含 Stelarith） |
|---|---|---|
| 数据主权 | 数据在厂商云，审计依赖厂商配合 | 数据在校内/自有机房，可审计、可脱敏 |
| 硬件绑定 | 强（希沃/鸿合绑自家大屏） | 弱（跑在任意 Windows 教室机） |
| 订阅成本 | 按设备/年订阅（`❓ 不确定`：具体单价未查证） | 零许可费，成本在运维人力 |
| 上手门槛 | 低（开箱即用） | 较高（需自建云端、懂部署） |
| 定制自由 | 低（受厂商路线图约束） | 高（源码在手，可改） |

### 5.2 灵动岛（Island）：信息枢纽面板（✅ 已确认）

`✅ 已确认`（源码 `Stelarith-shared-qml/island/` 与 `Stelarith-control-qt/src/island/`）：灵动岛是 Stelarith 被控端常驻的「信息枢纽面板」，承载多个「面（Face）」，把分散的业务语义收进一个可展开/收起的岛形 UI。已核实存在的面板包括：

- `IslandClock` / `IslandDateFace` —— 时钟与日期
- `IslandTimetableFace` —— 课表（对接 ClassIsland 课表格式归一化）
- `IslandCountdownFace` —— 倒计时（上课铃/考试计时）
- `IslandMediaFace` —— 媒体播放状态
- `IslandAnnotateFace` —— 批注/白板
- `IslandPanelFace` —— 聚合面板（Date + Timetable + Countdown）
- `IslandBannerFace` / `IslandMiniFace` / `IslandCardFace` / `IslandFullscreenFace` —— 不同形态的通知/展示面
- `IslandSettingsFace` / `IslandAutomationFace` —— 设置与自动化

设计上，岛壳用 C++（`island.cpp` 的 `IslandOverlay` + `QQuickWidget`），视觉层用 QML（`IslandRoot.qml`），桥接靠 `IslandBridge`（`Q_PROPERTY` 暴露状态 + 回调）。这一「C++ 大脑 + QML 皮肤」的分工，恰好是 §10.9 红线（QML 纯净 UI）的落地实践：`✅ 已确认`（AGENTS.md 与源码注释）QML 只画图、只接收点击，网络/JSON/Win32 全在 C++。

### 5.3 它在演进史里卡住的位置

把 Stelarith 放回第 2 节的时间轴，它落在 **2020s「开源自托管崛起」** 这一格，但更精确地说，它占据的是一个**长期空白的交集**：

```
            开源
              │
              │        ★ Stelarith
              │        (开源·自托管·全校集控·不绑硬件)
              │
  全校/全区 ──┼───────────────────────── 商业
  集控        │  [希沃/鸿合/锐捷]
              │  (绑硬件·闭源云)
              │
  单班轻量 ───┼─────────────────────────
              │  [ClassIsland](单屏前端)
  开源        │
```

`🟡 合理推测`：商业方案要么「绑硬件闭源」（希沃/鸿合），要么「通用 UEM 但缺教学业务语义」（Intune/Jamf）；纯开源项目要么停留在「单班屏幕前端」（ClassIsland），要么停留在「通用设备管理」（各类 MDM 开源实现）。**既开源自托管、又面向全校舰队运维、又内建课表/广播/巡课这类教育业务语义、又不绑硬件——这个交集，本文未检索到成熟竞品，Stelarith 是其中较完整的开源实现。**
