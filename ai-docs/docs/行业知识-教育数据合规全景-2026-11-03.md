# 教育数据合规全景：在「全校集控」场景落地数据安全法 / 个人信息保护法 / 未成年人保护法 / 双减

> **30 秒电梯演讲**：教育集控系统天然坐在"数据火药桶"上——它要采摄像头画面、麦克风音频、进程列表、设备指纹、使用时长，还可能云端集中存储。这些恰恰是《个人信息保护法》里的"敏感个人信息"、《未成年人保护法》里"涉未成年人更严"的高危区。合规不是法务的事后补丁，而是"采集前就设计好最小必要、单独同意、留存期限、用途告知、审计留痕"。本报告把法规拆成义务矩阵、把场景拆成风险热力图、把落地拆成可勾选清单，并对照星集控源码诚实标注"已做到 / 待建设"。

## 一、行业定义：教育数据的敏感度梯度

教育数据不是一坨"数据"，敏感度天差地别：

```
敏感度 高 ┌───────────────────────────────────────┐
        │ 生物/音视频：摄像头画面、麦克风录音      │ ← 需单独同意·留存期限·用途限定
        ├───────────────────────────────────────┤
        │ 行为/身份：进程列表、使用时长、设备指纹  │ ← 最小必要·可解释
        ├───────────────────────────────────────┤
   低   │ 教育行政：班级/课表/成绩(去标识化)        │ ← 分级保护
        └───────────────────────────────────────┘
```

- **教育行政数据**：课表、班级、去标识化成绩——敏感度相对低，但仍需分级。
- **教学行为数据**：进程列表、屏幕活跃度、使用时长——中等敏感，涉及"学生在做什么"。
- **生物/音视频数据**：摄像头实时画面、麦克风录音、自习模式噪音录制——**最高敏感**，属于《个保法》定义的"敏感个人信息"（生物识别、行踪轨迹、不满十四周岁未成年人信息）。

## 二、四法一规骨架（法规 × 核心义务 矩阵）

| 法规 | 核心义务 | 对集控系统的硬约束 |
|---|---|---|
| **《数据安全法》** | 数据分类分级、重要数据目录、风险监测 | 摄像头/音频数据应列为"重要数据"，集中存储需单独保护 |
| **《个人信息保护法》** | 告知-同意、最小必要、敏感个人信息单独同意、撤回权 | 采摄像头/麦克风必须**单独弹窗同意**，且能撤回；非必要不采 |
| **《未成年人保护法》"网络保护"专章** | 涉未成年人信息更严、监护人同意、防沉迷 | 学生端采集须有**监护人同意**流程，且不得用于与教学无关目的 |
| **《义务教育质量评价指南》/ 双减** | 减少不必要的采集与评比 | 不得用集控数据做学生排名、过度评比 |
| **教育部《未成年人学校保护规定》/ 数据出境** | 校内保护、数据境内存储倾向 | 学生数据尽量不出校、不出境 |

> ❓ 上述法条的**具体条款号与罚则金额**本轮因 `web_search` 额度不可用（HTTP 402）未联网核对，待查证后补入引用。

## 三、「全校集控」场景的合规冲突点（风险热力图）

```
风险等级（红=高 黄=中 绿=低）
─────────────────────────────────────────────────────
摄像头实时监看 / 自习噪音录制      ████████ 红  音视频敏感个人信息
屏幕+摄像头双画面广播             ██████   红  生物+行为叠加
云端集中存储学生行为数据          █████    黄  集中化+出境风险
设备指纹/进程列表/使用时长采集     ████     黄  最小必要争议
OTA/远程指令 鉴权与审计           ███      黄  缺审计留痕=失控
学生端 vs 教师端 身份混用         ██       绿  需区分策略
```

**五个冲突点展开**：

1. **摄像头实时监看（红）**：自习模式噪音录制、屏幕+摄像头双画面，本质是"在教室装监控"。需单独同意、明确留存期限、限定用途（仅教学管理，不作他用）。
2. **屏幕+摄像头双画面（红）**：生物信息（人脸）与行为信息（在做什么）叠加，敏感度相乘。
3. **云端集中存储（黄）**：上千台设备的音视频/行为数据集中到一处，一旦泄露是"一锅端"。倾向本地留存+境内存储。
4. **设备指纹/行为采集（黄）**：进程列表、使用时长——"最小必要"原则下，要能回答"采这个干什么、不采行不行"。
5. **OTA/远程指令（黄）**：远程锁屏、推送、采集若缺强鉴权与审计留痕，等于给了一个"无人监督的开关"。

## 四、合规落地可勾选清单

- [ ] 鉴权强度：云端令牌 + WS 双向鉴权，设备身份唯一（✅ 源码已有，见下）
- [ ] 传输加密：TLS 后端完整（✅ Stelarith 已修 TLS 退化事故，见 `src/main.cpp` TLS 自检）
- [ ] 存储加密：本地/云端落盘加密（❓ 待确认是否有落盘加密）
- [ ] 留存期限：音视频/行为数据有显式 TTL 与到期清除 UI（❓ 待建设）
- [ ] 用途告知：采集前弹窗说明"采什么、用于什么、存多久"（❓ 待建设）
- [ ] 单独同意：摄像头/麦克风需单独同意而非捆绑在用户协议（❓ 待建设）
- [ ] 撤回同意：用户可随时关掉某类采集（🟡 部分能力可在设置关，但无统一撤回入口）
- [ ] 审计日志：谁在何时下了什么指令、看了哪台设备（🟡 云端有指令回执，缺"查看"审计）
- [ ] 监护人告知：学生端涉未成年人须监护人知情（❓ 待建设）

## 五、Stelarith 现状对照（✅ 一级信源）

**已具备的机制**（据仓库源码）：

- **设备身份与云端令牌**：被控端经 OOBE 绑定设备身份，云端持令牌（`Stelarith-cloud/src/` 鉴权；`Stelarith-control-qt/src/oauthbind.cpp` / `src/main.cpp` 令牌自检）。
- **WS 双向鉴权与指令回执**：指令下发→设备执行→`sendActionReceipt` 回执→云端记录（`Stelarith-control-qt/src/main.cpp` 的 `sendActionReceipt`；云端 `registry.js` 的 `recordResult`）。
- **TLS 后端健壮性**：2026-10-13 修过 Qt TLS 后端退化成 `cert-only` 的生产事故，新增启动自检与打包三后端体检（`src/main.cpp`，提交 `dd421a4`）。
- **本地策略与设置域**：`settings_domain` 管设备设置与存储口径；灵巧岛本地留存历史（`src/island/`）。

**诚实指出的缺失项**（源码未见，标 ❓/🟡）：

- 未成年人**监护人同意流程**：源码无独立监护人同意入口。
- **数据留存期限 UI**：无面向用户的 TTL 设置与到期提示。
- **音视频用途告知弹窗**：采集前无专项告知。
- **"查看"行为审计**：有"指令"审计，缺"管理端看了哪台设备画面"的审计。
