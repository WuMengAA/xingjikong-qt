## 0. 30 秒电梯演讲

> **星集控（Stelarith）** 是一套**开源、可自托管、能私有化部署**的 K12 教室设备集控平台：一套 Qt 三端架构（教室机被控端 + 老师机管理端 + 云端中转）把「课表、通知、广播、远控、媒体、批注」收进一个叫「灵动岛」的常驻枢纽面板，让一个管理员像管一支舰队一样管全县/全校的屏幕。
> 一句话定位：**它是教育场景里的「开源 Jamf School + ClassIsland 课表 + 自托管控制台」合体，且把数据主权留在学校自己手里。**

## 1. 行业定义与边界：集控 ≠ 普通远控

「教室设备集控」不是远程桌面软件换个皮。它的本质是：**在「无人值守 / 半值守」的教室环境里，对一组异质设备做「状态可见、策略可下发、故障可远程处置」的持续运维**。

关键差异点（为什么不能用 TeamViewer / ToDesk 直接顶替）：

| 维度 | 普通远控（TeamViewer/ToDesk） | 教室设备集控（Stelarith/希沃/锐捷） |
|---|---|---|
| 使用主体 | 人 ↔ 人（A 帮 B 修电脑） | 管理员 ↔ 一群设备（一对 N） |
| 交互模型 | 实时抢占鼠标键盘 | 下发指令 + 订阅状态，多数无需实时接管 |
| 离线容忍 | 断线即失联 | 指令队列 + 重连补发（设备可能课间才联网） |
| 业务语义 | 无（只管像素） | 有（课表、上课铃、禁止时段、班级绑定） |
| 合规边界 | 个人授权即可 | 涉及未成年人数据、校园网络，需分级权限 |

**读法（🟡 合理推测 + ✅ 部分已确认）**：
- **L1 硬件**：国内教室主流是「交互大屏 + 内插 OPS 主机（一台 x86 小电脑）」，这是 Stelarith 被控端主要落地形态（`✅ 已确认`：Stelarith 被控端为 Windows 应用，适配 OPS/教室机）。
- **L2 系统**：Windows 占教室机大头；班牌/电子书包多为 Android；信创（统信 UOS / 银河麒麟 + 龙芯/兆芯）在政策驱动下渗透。`❓ 不确定`：信创适配 Stelarith 是否已有生产级支持。
- **L3 平台**：商业方案多为「硬件厂商私有云」；Stelarith 走「开源自托管云端中转」路线（`✅ 已确认`：云端中转端口 8788，可私有化部署）。
- **L4 应用**：Stelarith 把课表/通知/广播/远控/媒体/批注统一收口到「灵动岛」面板（`✅ 已确认`：源码层面存在 `IslandTimetableFace` / `IslandMediaFace` / `IslandCountdownFace` / `IslandDateFace` / `IslandAnnotateFace` 等面板）。

## 3. 政策时间线：集控的「隐性推手」

```
2018 ──── 教育信息化 2.0 行动计划
          「三全两高一大」：教学应用覆盖全体教师、学习应用覆盖全体适
          龄学生、数字校园建设覆盖全体学校；信息化应用水平和师生信
          息素养普遍提高；建成「互联网+教育」大平台。
              │
2019 ──── 《中国教育现代化 2035》发布，教育数字化上升为国家战略
              │
2022 ──── 「国家智慧教育公共服务平台」上线（国家中小学/职教/高教
          三平台 + 24365 就业），教育数字化战略行动启动
              │
2021 ──── 「双减」政策落地：校外培训压减 → 校内提质增效 →
          课堂/作业/课后服务数字化需求暴涨 → 集控类工具被纳入
          「校内增效」叙事（间接利好）
              │
2021 ──── 《数据安全法》《个人信息保护法》施行
2020 修订 ── 《未成年人保护法》「网络保护」专章（第 64–72 条）
              │
2023~ ──── 教育数字化战略行动深化：国家平台迭代、AI 大模型进课堂
          试点、数据出境/校园数据合规收紧
```

**对集控的影响（🟡 合理推测）**：

| 政策 | 对集控的直接/间接影响 |
|---|---|
| 教育信息化 2.0 / 智慧教育平台 | 制造「设备必须联网可管」的刚性需求，集控从「锦上添花」变「达标项」 |
| 双减 | 校内增效压力 → 课表、作业、课后服务数字化 → 课表归一化/通知必达这类能力吃香 |
| 数据安全法 / 个保法 / 未保法 | **集控平台采集设备状态、学生机操作日志、摄像头画面，必须做分级权限 + 最小化 + 留痕**；商业云方案面临数据出境/合规拷问，这正是「私有化自托管」路线的护城河 |

> `❓ 不确定`：上述政策条文的具体条款编号与「集控合规」的强制边界（如学生机屏幕录制是否需监护人同意），本文未逐条核验法律原文，建议合规落地前由法务复核。

**落点说明（✅ 已确认部分 + 🟡 推测部分）**：

| **Jamf School** | 商业（Apple 生态） | K-12 Apple 设备 MDM，含 Jamf Teacher/Student/Parent 三角色 | `✅ 已确认`（官网）：提供 automated enrollment、zero-touch、课堂锁屏。Stelarith 的对标「西方样本」，但绑 Apple、不碰 Windows 教室机 |
| **Microsoft Intune** | 商业 | UEM，覆盖 Win/Apple/Android，教育场景靠配置策略 | 通用 UEM，缺教学业务语义 |
| **Google Classroom** | 商业（免费） | 教学管理（作业/班级），非设备集控 | 业务层，不碰设备 |

| **希沃 / 鸿合 / 锐捷** | 商业（硬件绑定的方案商） | 大屏 + 集控后台一体 | 国内主流；**软硬耦合**是最大差异点——换非自家大屏即用不了 |
| **科大讯飞 / 奥威亚** | 商业 | 智慧课堂 / 录播 + 集控 | AI 与录播强，平台封闭 |
| **ClassIsland** | **开源**（`✅ 已确认` GitHub 描述：「功能强、可定制、跨平台，适用于班级多媒体屏幕的课表信息显示工具」） | 单班屏幕的课表/通知/计时显示 | **Stelarith 的课表归一化直接对接 ClassIsland 课表格式**（`✅ 已确认`：Stelarith 有 `cims-class-timetable-import` 技能，专门做 ClassIsland 档案切班下发）；二者是「互补而非竞争」——ClassIsland 是单屏前端，Stelarith 是舰队后端 |
| **Stelarith 星集控** | **开源 + 自托管** | 全校/全区 K12 教室集控 | **本笔记主角** |

**矩阵一句话总结（🟡 推测）**：开源象限里，ClassIsland 占「单班屏幕」、Stelarith 占「全校舰队」；商业象限里，国外 Jamf/Intune 强在设备合规、国内希沃/鸿合强在硬件捆绑。**Stelarith 的独特卡位是「开源 + 自托管 + 全校集控 + 不绑硬件」四者交集，目前该交集几乎是空的。**

### 5.1 三端 Qt 架构

```
        ┌─────────────────────────────────────────────┐
        │            云端中转 (Stelarith-cloud)         │
        │           监听 :8788                         │
        │  职责: 设备注册 · 指令路由 · OTA 渠道分发 ·   │
        │        多租户 · 课表/通知存储 · 报表          │
        └───────────────┬───────────────┬─────────────┘
               WebSocket│               │WebSocket
                        ▼               ▼
        ┌──────────────────────┐   ┌──────────────────────┐
        │ 被控端 (control-qt)  │   │ 管理端 (viewer-qt)    │
        │ 装在教室机/OPS       │   │ 装在老师机/管理员机   │
        │ 灵动岛常驻 · 接 VNC  │   │ 看全校设备地图 · 下发 │
        │ · 收指令 · 自升级    │   │ 指令 · 巡课 · 看回执  │
```

- **被控端**：Windows Qt 应用，常驻托盘 + 灵动岛面板，单实例守卫（Global 互斥体 + Local + QLockFile 三道闸，`✅ 已确认` AGENTS.md 8.1 实测）。
- **管理端**：Qt 应用，MainWindow 骨架（240 侧栏 + 64 顶栏 + 内容区），看全校设备地图、下发指令、看回执。
- **云端中转**：Node/JS 服务，端口 8788，被控端与管理端都通过 WebSocket 连它，天然解决跨 NAT / 跨网段发现（`✅ 已确认`：公网入口 `control.245959623.xyz` → cloudflared → 本机 8788）。

### 5.2 「灵动岛」（Dynamic Island）枢纽

`✅ 已确认`（源码 `Stelarith-shared-qml/island/`）：灵动岛是一块可开关/排序/缩放的常驻组件面板，由 `IslandRoot.qml` 驱动，面板面（face）由 C++ `PanelDomain::faces()` 注册。已确认存在的面板：

| 面板 face | 含义 | 证据 |
|---|---|---|
| `timetable` | 今日课程（对接 ClassIsland 课表） | `IslandTimetableFace.qml` |
| `date` | 日期 / 周次（「期」面板） | `IslandDateFace.qml`（注释称 buildDate 给 time/date/weekday） |
| `countdown` | 倒计时（「倒」面板） | `IslandCountdownFace.qml` |
| `media` | 媒体播放呈现（歌名/进度上岛） | `IslandRoot.qml` 媒体播放上岛逻辑 |
| `annotate`（笔） | 批注 / 白板（多页） | `IslandAnnotateFace.qml` + `execute_action.cpp` 的 `annotate_*` 指令簇 |
| `settings` | 设置 | `IslandSettingsFace.qml` |
| `custom` | 自定义 | `IslandPanelFace.qml` 支持自定义面 |
| `morph` | 形态态（progress/countdown/alert/marquee/audio 优先级裁决） | `IslandMorph.qml`（`countdown > alert > notice > marquee > progress > audio`） |

交互上：灵动岛一次只展开一件事（§七 纪律），且支持「按住不收起 / 钉住（pin）」等交互（`🟡 推测`：仓库注释与 AGENTS 记录提及 pinned 与「按住不收」交互，具体手势实现以源码为准）。渠道名（如「课程提醒」）由 C++ 注入、QML 画出 `IslandChannelChip`，保证学生看到的「上课啦」提示有明确渠道标识。

### 5.3 课表归一化 / 班级绑定 / OTA / VNC / 广播

- **课表归一化**：`✅ 已确认`：对接 ClassIsland 课表格式（`Profiles/Default.json` 信封），支持按班切分下发（`cims-class-timetable-import` 技能专门覆盖此链路，含「ClassPlan/TimeLayout/Subjects 必须是 Profile 信封否则客户端静默不显示」等铁律）。
- **班级绑定**：`✅ 已确认`：被控端以 `class_<校简称>_<届>_<班号>` 命名（如 `class_xlzx_2028_08`），全小写唯一，云端按此做多租户隔离。
- **OTA 自升级**：`✅ 已确认`：三渠道——历史 `stable/rc/gray`，2026-11-02 起演进为 `stable/beta/alpha`（`channel_persistence.cpp` 的 `channelCanonical` 做旧名自动翻译）。支持灰度（部分设备先行）、渠道持久化、升级回弹保护。
- **VNC 远控**：`✅ 已确认`：被控端经 `image://vnc/live` image provider 把屏幕推给管理端，走 C++ 而非 QML 直连（`§10.9 纯净 UI` 红线）。
- **广播 / 通知**：`✅ 已确认`：紧急通知三态（urgent/remind/emergency_confirm），云端下发 → 被控端回执 `action=notify result=done`，多渠道（钉钉/飞书等）经服务端转发。
- **多渠道下发**：`✅ 已确认`：管理端指令可经云端路由到钉钉/飞书等外部渠道触达（通知提供方清单在 `agent_ui.h` 注释中）。

### 5.4 工程架构「洁癖」（差异化软实力）

`✅ 已确认`（AGENTS.md §9/§10/§10.9）：

- **设计语言**：MD3（Material Design 3）+ QtShadcn 组件库，单一真源 `Stelarith-shared-qml/ui/Md3.qml`，零硬编码颜色、字号、圆角。
- **数据契约**：列表一律 `QAbstractListModel` 强类型（`roleNames()`），**禁止把 `QVariantMap`/`QJsonObject` 当模型喂 QML**（§10.7）。这一条把「改字段名要全库猜哪里读」的熵打下去。
- **QML 纯净 UI 封杀令**（§10.9）：**QML 只画图、只接点击；网络 / JSON 解析 / Win32 / DB / 日志全在 C++**。QML 里禁 `XMLHttpRequest`/`WebSocket`/`fetch`/`JSON.parse` 处理业务数据。全库唯一真·违例是 `ClassTimetablePane.qml` 两处 `JSON.parse`（解析 C++ 丢来的原始 JSON 串，属待消灭反模式）。
- **门禁九件**：提交前 `pre-commit` 跑 `qmllint`、文件规模红线、术语封杀、UI 合规等，不过即拒。

## 7. 如果你在做集控产品，这 10 个坑

1. **设备离线重连**——教室机课间才联网，指令必须「队列 + 重连补发 + 回执对账」，否则管理员以为发了其实没到。
2. **跨网段发现**——别指望广播发现，校园网早被 VLAN 切得稀碎；走云端中转（WebSocket 长连）才是最稳的「反向连接」。
3. **权限分级**——校长/管理员/老师/学生权限必须分层，学生端误触「远程锁屏全校」是事故级。
4. **未成年人数据合规**——屏幕录制/操作日志/摄像头画面属敏感个人信息，需最小化 + 留痕 + （推测）监护人告知；私有化部署是合规捷径。
5. **大屏分辨率适配**——86" 4K 大屏 vs 班牌 1280×320 vs 学生平板，一套 UI 要自适应，否则灵动岛在某些屏上「塌成一条」。
6. **批量 OTA 带宽**——全校同时拉安装包能把校园网打爆；必须灰度 + 错峰 +（理想）P2P 分发。
7. **时钟同步**——课表、倒计时、上课铃全依赖设备时钟；一台慢 3 分钟，全校「已上课」提示集体错位。
8. **课表多源合并**——不同年级/班级课表格式各异，归一化前先定「真源信封格式」（如 ClassIsland 的 Profile 信封），否则客户端静默不显示。
9. **通知必达**——紧急通知不能「发了就算到」；要回执 + 超时重试 + 多渠道兜底（端内 + 钉钉/飞书），否则班主任不知道学生机其实静音了。
10. **单实例守卫**——被控端必须「同一台机器只跑一个」，否则双开抢锁、重复上报、云端看到两台幽灵设备；三道闸（Global 互斥体 + Local + QLockFile）是血泪换来的。
