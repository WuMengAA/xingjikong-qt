# 现代终端管理技术白皮书：从 MDM/EMM/UEM 到教室集控（星集控视角）

> 信源等级：✅ = 星集控仓库一级信源（`src/action/*.cpp`、`src/island/*`、`PanelDomain`、`ota*`）；🟡 = 合理推断；❓ = 本环境联网受限（HTTP 402）未查证，绝不编造数字/引用。
> 本篇把"终端管理"这件事的技术底座拆开讲：分层架构、通信协议、远程画面、操作系统形态、以及"强类型数据契约"这条工程纪律。它是星集控 §10.7 / §10.9 在产线上的完整注解。

## 0 · 电梯演讲

终端管理（endpoint management）的本质，是**在一堆你管不到物理按钮的设备上，远程、批量、可靠地做四件事**：让它们报到、给它们下命令、往它们身上发东西、看它们现在在干嘛。

```
     集中管理平台（云端 / 控制台）
            │ 策略 / 指令 / 资产
            ▼
   ┌────────────────────────────────────────────┐
   │  设备代理（agent）── 跑在每台终端上的大脑     │
   │   · 注册 enroll · 心跳 · 执行指令 · 回执      │
   └────────────────────────────────────────────┘
            │ 本机动作
            ▼
   目标：锁屏 / 发应用 / 推课表 / 巡课截图 / 静音
```

MDM（移动设备管理）→ EMM（企业移动管理，多了应用/内容）→ UEM（统一终端管理，桌面+移动+IoT 一锅端），是一条**能力光谱**；教室集控是这条光谱里最"重交互"的一段——因为它管的不只是设备，还有**课堂场景**（这节课该显示什么、铃声偏移几分钟、谁在说话）。

## 1 · 技术分层：端到端的五段式架构（✅）

```
┌────────────────────────────────────────────────────────────────┐
│ L4  应用与数据层   课表 / 媒体 / 批注 / 倒计时 / 自动化规则        │
├────────────────────────────────────────────────────────────────┤
│ L3  平台层        云端中转(8788) · 多租户 · OTA 发版 · 指令白名单  │
├────────────────────────────────────────────────────────────────┤
│ L2  代理/系统层    被控端 agent(Qt/Windows) · VNC 巡课 · 状态机    │
├────────────────────────────────────────────────────────────────┤
│ L1  设备注册层     enroll · 设备身份(class_xxx) · 单实例守卫       │
├────────────────────────────────────────────────────────────────┤
│ L0  硬件层        教室大屏 / 学生机 / 老师机 / 交互平板           │
└────────────────────────────────────────────────────────────────┘
        ▲ 数据向上汇聚（心跳/回执）   ▼ 指令向下分发（WebSocket）
```

**星集控落点（✅）**：
- L1 设备身份用 `class_<校简称>_<届>_<班号>`（全小写、每台唯一）；单实例三道闸（端口 + QLockFile + 命名互斥量）防双开。
- L3 云端中转 `control.245959623.xyz:8788`，被控端带 `CLOUD_WS_TOKEN` 令牌鉴权；指令词表落在 `main.cpp` 白名单（`lock`/`notify`/`screenshot`/`set_volume`/`shutdown`/`island_panel`/`study_mode_start`…）。
- L2 指令分派进 6 个域文件：`src/action/{execute_action,execute_app,execute_device,execute_file,execute_media,execute_notice,execute_schedule}.cpp`——**按业务切，不堆一个上帝类**。
- L4 数据经 `QAbstractListModel` / `Q_INVOKABLE` 喂给 QML（见 §5）。

## 2 · 通信协议选型矩阵（✅ 星集控用 WebSocket；🟡 其余对比）

| 协议 | 连接模型 | 方向性 | 适用场景 | 星集控采用？ |
|------|----------|--------|----------|--------------|
| **WebSocket** | 长连、全双工 | 双向（心跳+下行指令+上行回执） | 实时指令/巡课回执 | ✅ 被控端↔云端 |
| MQTT | 长连、发布/订阅 | 多对多解耦 | 海量 IoT 遥测 | 🟡 未用（指令需强应答语义） |
| 长轮询 HTTP | 短连、拉取 | 单向拉 | 弱网/防火墙严格环境 | 🟡 可降级备用 |
| gRPC | 长连、强类型 | 双向 streaming | 内部服务间 | ❓ 云端内部未查证 |

**为什么是 WebSocket（✅ 来自 `ota_download`/`PanelDomain`/`execute_notice` 调用链）**：
- 指令要**带白名单 + 令牌**，下行同时要收**执行回执**（`event` 旁路 `kind=ota_health` 这类）——全双工最自然。
- 巡课截图走 C++ VNC 图像提供者 `image://vnc/live`，QML 只拿像素流画，**不另开一条连网**（§10.9 纯净 UI）。

```
                决策树：选哪种？
                     │
       需要强应答/实时双向？──否──▶ MQTT 或 长轮询
                     │是
       设备是浏览器/严格防火墙？──是──▶ 长轮询 HTTP 降级
                     │否
       已是 Qt/C++ 客户端？──────────▶ WebSocket + 令牌 + 白名单（星集控路径）
```

## 3 · 远程画面技术光谱（✅ VNC 巡课；🟡 其余）

```
  实时交互强 ←──────────────────────────────► 广播单向强
  ┌─────────┬──────────┬──────────┬──────────┬──────────┐
  │ WebRTC  │  RDP     │  VNC     │  RTSP    │  RTMP     │
  │ P2P信令 │ 远程桌面 │ 像素抓屏 │ 流媒体   │ 流媒体    │
  │ 双向音视│ 全功能   │ 轻量巡课│ 监控摄像 │ 直播广播  │
  └─────────┴──────────┴──────────┴──────────┴──────────┘
   星集控P2P   ❓未用     ✅巡课      ❓未用     🟡屏播待确认
```

- **VNC（✅ 星集控选用）**：C++ 端抓屏编码成帧，经 `image://vnc/live` 图像提供者把像素喂给 QML。QML 侧**零连网、零解析**，只画——完美贴合 §10.9。代价是带宽随分辨率走，适合"老师巡课看一眼在不在认真"而非"高清远程操作"。
- **WebRTC（🟡）**：已有 P2P 信令边车（Node socket.io :18110 + CIMS 透明代理），适合低延迟双向（远程协助）。公网排障踩过坑（CF 隧道 origin=localhost→IPv6 ::1 解析不到 IPv4，需 `netsh interface portproxy add v6tov4`）。
- **RTMP/RTSP（🟡）**：屏幕广播（一对多直播）更合适，星集控当前未接，属可选扩展。

## 5 · 工程纪律：强类型数据契约 vs 原始 JSON（✅ 来自 §10.7/§10.9 + 灵动岛落地）

这是本白皮书**最该被别的团队抄去**的一条。

```
  反模式（禁止）                正解（星集控）
  ┌──────────────┐            ┌────────────────────────────┐
  │ C++ 拼 JSON  │            │ C++ 算好 →               │
  │ 字符串       │──WS──▶     │ QAbstractListModel       │
  │              │            │   / Q_INVOKABLE          │
  │ QML JSON.    │            │        │ context property│
  │ parse() 解析 │            │        ▼                 │
  │              │            │ QML 只读 role/属性       │
  │ 字段名改=全库 │            │   编译期类型 + 自动刷新   │
  │ 猜哪在读     │            │   改字段名=编译报错定位   │
  └──────────────┘            └────────────────────────────┘
```

**三条硬理由（✅）**：
1. **可发现性**：强类型 Model 的 `roleNames()` 一搜就全，改一个字段名编译期报错定位；原始 `QVariantMap` 喂 QML，改字段名要在全库猜谁在读（星集控曾 108 处 `QVariantMap` 直喂，是"最疼的一条"）。
2. **纯净 UI（§10.9）**：QML 里 `JSON.parse` 处理业务数据是封杀项——它把"计算"泄漏进皮肤层。正确骨架是 `Q_PROPERTY` 只读绑定 + `Q_INVOKABLE` 只发指令。
3. **失败透明**：数据缺失时返回"带 error 的空对象"，QML 能区分"今天没课"（事实）与"课表没接上"（故障）。倒计时面据此写"未配置"而非假冒 `00:00`。

> 唯一真·QML 侧历史违例是 `ClassTimetablePane.qml` 两处 `JSON.parse`，解析 C++ 丢来的**原始 JSON 字符串**——这正是 §10.7 要消灭的反模式，修复归入"C++ 改传强类型 Model"待办（§10.8 步 5）。

## 6 · OTA：把"升级"做成前一天的普通事（✅）

```
   云端 ota.js ──cmpVersion──▶ 有更新？
        │ mandatory?          │
        ▼                     ▼
   强制立即      非强制：延迟 STE_QT_OTA_AUTO_DELAY_SEC(默认30s)
        │                     │
        ▼                     ▼
   被控端 ota_download ──▶ ota_update.applyUpdateInfo
        │ 启动安装器 + /S(NSIS) + /VERYSILENT(Inno) 双参数
        ▼
   重启自举 → 版本号 CMake + main.cpp 双副本强校验
```

- 云端 `ota.js` **只做版本比较，无最低版本门槛**（0.4.0-v1 除外，无 OTA 能力须重装）。
- 安装器兼容：同时给 `/S`（NSIS）与 `/VERYSILENT`（Inno）双参数，新旧安装器通吃。
- 版本号 `AGENT_VERSION`(CMakeLists) 与 `kAppVersion`(main.cpp) **双副本**，构建期不一致直接 FATAL——杜绝"包是新的、报的是旧的"。
